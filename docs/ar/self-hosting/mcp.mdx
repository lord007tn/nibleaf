يوفّر Nibleaf نقطة MCP مصادَقًا عليها عبر HTTP في `/api/mcp`، وهي معطّلة
افتراضيًا. تتصل العملاء إما بتسجيل الدخول عبر OAuth، الذي يربط الاتصال بمشروع واحد
وإعداد مسبق يختاره الشخص، وإما بمفتاح API شخصي. يرتبط كل مفتاح بمشروع واحد، ويعود
إلى العضو الذي أنشأه، ويحمل نطاقات صريحة، وله تاريخ انتهاء. يشتق الخادم المشروع
والمؤسسة من المفتاح أو الاتصال؛ ولا تقبل الأدوات أيًا منهما كسلطة يحددها المتصل.

تغطي أدوات القراءة المحتوى والتحليلات والبحث والاستخدام والإضافات والسمات
والتصدير وعمليات النشر والتكاملات. وتستطيع أدوات «مساعد كتابة الدعم» إنشاء مسودات
الصفحات وتعديلها ونشرها بعد معاينة وتأكيد صريحين. لا تتوفر عمليات الحذف، ولا
تغيير الإعدادات أو العضوية، ولا بيانات اعتماد المزوّد أو الدفع أو بدائيات قاعدة
البيانات أو الوصول العشوائي للملفات أو تنفيذ الشيفرة. لمسار عمل الدعم وفهرس
الأدوات الكامل، راجع [العمل على التوثيق مع مساعد ذكاء اصطناعي](/ar/product/ai-assistants).

## تفعيل نقطة النهاية

اضبط بيئة خدمة API:

```dotenv
MCP_ENABLED=true
MCP_ALLOWED_HOSTS=mcp.docs.example.com
MCP_RATE_LIMIT_PER_MIN=120
MCP_WRITE_RATE_LIMIT_PER_MIN=20
MCP_PUBLISH_RATE_LIMIT_PER_HOUR=6
```

تُسمح أسماء المضيفين في `API_URL` و`APP_URL` دائمًا. أضف إلى
`MCP_ALLOWED_HOSTS` أسماء المضيفين العامة الإضافية فقط؛ ولا تضف بروتوكولًا أو
مسارًا أو معلومات مستخدم أو فاصلة داخل المضيف الواحد أو قيمة بحرف بدل. أعد
إنشاء خدمة API بعد التغيير.

تتحقق نقطة النهاية من `Host` و`Origin` و`X-Forwarded-Host` و
`X-Forwarded-Proto` قبل المصادقة. اضبط الوكيل العكسي العام ليستبدل ترويسات
التمرير غير الموثوقة ويمرر مضيفًا وبروتوكولًا واحدين واضحين. أبقِ MCP معطّلًا إلى
أن يعيد مسار TLS والوكيل العام اسم المضيف المتوقع.

## المفاتيح الشخصية والتحقق الحي من الصلاحيات

ينشئ أي عضو في المشروع مفتاحه الخاص من **الإعدادات ← مساعدو الذكاء الاصطناعي
(MCP)**، فيختار إعدادًا مسبقًا (أو نطاقات منفردة من **خيارات متقدمة: اختر
الصلاحيات**) ومدة صلاحية من 7 أو 30 أو 90 أو 180 أو 365 يومًا، ثم يختار **إنشاء
مفتاح**. ويظهر السر مرة واحدة فقط:

| الإعداد المسبق | متاح لـ | النطاقات |
| --- | --- | --- |
| القراءة فقط (Read only) | الأعضاء فما فوق | `mcp:connect` و`projects:read` و`pages:read` و`languages:read` و`versions:read` و`analytics:read` و`search:read` و`deployments:read` |
| مساعد كتابة الدعم (Support writer) | الأعضاء فما فوق | نطاقات «القراءة فقط» إضافة إلى `analytics:search_terms` و`pages:write` و`deployments:publish` |
| إدارة كاملة (Full admin) | المسؤولون والمالكون | كل نطاقات MCP |

الإعدادات المسبقة تسهيل في لوحة التحكم فقط؛ أما الحد الأمني فهو مجموعة النطاقات
مع دور منشئ المفتاح. يعمل المفتاح باسم منشئه، ويعيد الخادم في كل طلب قراءة دور
المنشئ الحالي في مساحة العمل وحالة تعليق حسابه، فلا يستطيع المفتاح أبدًا أن
يتجاوز ما يستطيعه مالكه في لوحة التحكم في تلك اللحظة. وعند إزالة عضو أو تعليق
حسابه أو حذفه تتوقف مفاتيحه في الطلب التالي بالرمز `401 auth:invalid_api_key`. ولا
تفعل النطاقات إلا تضييق ما يسمح به دور المالك أصلًا.

يرى الأعضاء مفاتيحهم فقط ويلغونها. ويرى المسؤولون والمالكون كل مفاتيح المشروع
مع مالك كل منها، ويستطيعون إلغاء أي منها، لكن مالك المفتاح وحده يستطيع تدويره؛
ويعيد التدوير إصدار المفتاح باسم الشخص الذي دوّره. يعرض كل مفتاح إعداده المسبق
وآخر استخدام وآخر نشاط له، ويتحقق زر **اختبار الاتصال** من المفتاح والمضيف ومفتاح
تشغيل MCP في خطوة واحدة، ويعرض عند النجاح «تم الاتصال · N أداة متاحة». خزّن السر في مخزن أسرار
العميل، لا في التحكم بالمصدر أو سجل الطرفية أو رسائل الدعم أو السجلات أو لقطات
الشاشة أو إعداد MCP محفوظ في مستودع.

يحتاج كل مفتاح MCP إلى `mcp:connect`. لا يتحكم النطاق إلا في سطحه المسمى ولا
يوسّع ارتباط المفتاح بالمشروع. يعرض اكتشاف الإمكانات الأدوات والموارد والموجّهات
المسجلة للمفتاح نفسه. لا تفترض توفر إمكانية موثقة إذا لم تظهر في `tools/list`
أو `nibleaf://capabilities`.

لا تستطيع مفاتيح حرف البدل القديمة الاتصال عمدًا. يظهر المفتاح ذو تاريخ انتهاء
فارغ أو من دون `mcp:connect` أو بحالة ترحيل قديمة على أنه يحتاج إلى التدوير.
دوّره إلى مجموعة نطاقات صريحة ومنتهية بدل تعديل صف قاعدة البيانات.

## ضبط العميل

استخدم المصدر العام لواجهة API ومرّر المفتاح كرمز Bearer. غالبًا ما يقبل عميل
يدعم خوادم MCP البعيدة عبر HTTP إعدادًا بهذا الشكل:

```json
{
  "mcpServers": {
    "nibleaf": {
      "url": "https://api.docs.example.com/api/mcp",
      "headers": {
        "Authorization": "Bearer ${NIBLEAF_API_KEY}"
      }
    }
  }
}
```

تختلف أسماء إعدادات العملاء. استخدم خيار HTTP أو الخادم البعيد، لا أمرًا محليًا
ولا موصل ملفات. تولّد لوحة الإعداد في لوحة التحكم أوامر وروابط خاصة بكل من
Claude Code وClaude Desktop وCursor وVS Code؛ وتجد كل مقتطف في قسم «اربط المساعد»
ضمن [العمل على التوثيق مع مساعد ذكاء اصطناعي](/ar/product/ai-assistants). استدعِ أولًا `tools/list` ثم
`get_capabilities`. تحتوي الاستجابة الناجحة على محتوى بروتوكول MCP وغلاف منظم يضم
معرّف الطلب ومعرّف المشروع المرتبط والإمكانية المطلوبة.

أما العملاء التي تتصل عبر OAuth (‏ChatGPT، وموصلات claude.ai وClaude Desktop، وكذلك
Claude Code وCursor وVS Code إن فضّل مستخدموها ذلك) فلا تحتاج إلا إلى العنوان
`<APP_URL>/api/mcp`؛ راجع قسم «OAuth لعملاء MCP» أدناه. ترتبط رموز OAuth بذلك العنوان
بالضبط، لذا أعطِ تلك العملاء مصدر لوحة التحكم لا مضيفًا آخر مدرجًا في
`MCP_ALLOWED_HOSTS`.

## ضمانات الكتابة والنشر

- **نسخة العمل فقط.** تنشئ أدوات `pages:write` المسودات وتعدّلها، ولا يصبح شيء
  منشورًا قبل نجاح النشر.
- **نشر على مستوى المشروع ببوابة بشرية.** يتضمن النشر كل تغيير غير منشور في
  المشروع، بما فيه مسودات الجميع، لا تغييرات مالك المفتاح وحده. على العميل استدعاء
  `preview_publish`، ثم يراجع شخص القائمة، ثم يستدعي العميل `publish_changes` مع
  `confirm: true` ورمز المعاينة. وتسجّل رسالة عملية النشر اسم مفتاح MCP.
- **رمز معاينة مقيّد.** يرتبط الرمز بمالك المفتاح وبالمشروع وببصمة لكل ما سيُنشر، إضافة
  إلى آخر إصدار منشور وأحدث عملية نشر. تنتهي صلاحيته بعد 10 دقائق
  (`mcp:preview_expired`)، وهو صالح فعليًا لاستخدام واحد: فأي تعديل أو نشر أو تراجع
  إلى إصدار سابق بعد المعاينة يعيد `mcp:preview_stale`، ولا يُنشر شيء جزئيًا.
  ويتوقف النشر أيضًا بالرمز `mcp:publish_blocked` للأسباب نفسها التي توقفه في لوحة
  التحكم، مثل مشكلات إعادة التوجيه.
- **التزامن المتفائل.** تحمل التعديلات `expectedRevision`. فإذا حفظ شخص مراجعة
  أحدث، تفشل الكتابة بالرمز `mcp:revision_conflict`، وتتضمن بيانات الخطأ
  `currentRevision`، بدل أن تستبدلها.
- **عدم التكرار.** يستطيع العميل إرسال `clientRequestId`؛ فإذا أُعيد الطلب بالمعرّف
  والوسائط نفسها، تُعاد النتيجة الأولى بدل تطبيق الكتابة مرتين. ويعيد استخدام
  المعرّف نفسه مع وسائط مختلفة الرمز `mcp:idempotency_conflict`، وتعيد إعادة
  المحاولة أثناء تنفيذ الاستدعاء الأول الرمز `mcp:idempotency_in_progress` القابل
  لإعادة المحاولة. وتنتهي صلاحية سجلات الإعادة بعد 24 ساعة.
- **محتوى محدود الحجم وغير قابل للتنفيذ.** المحتوى بصيغة Markdown/MDX بحد أقصى
  128 KiB. ويمكن لكتلة YAML للبيانات الوصفية في مقدمة الملف أن تحدد `title`
  و`description` و`icon`، وتتقدّم الوسائط الصريحة عليها. وتستخدم البيانات الوصفية
  محلّل مزامنة Git، لذلك لا تُفك الأحرف المهرّبة، كما في مزامنة Git. ولا تُنفَّذ
  MDX أبدًا في موقع القرّاء: يُعرض المحتوى عبر `react-markdown` و`rehype-sanitize`،
  وتظهر تعبيرات MDX وأسطر `import`/`export` نصًا.
- **ربط الترجمات.** يرفض `translate_page` إنشاء ترجمة موجودة بالرمز
  `mcp:translation_exists` (ويحددها `data.pageId`؛ فعدّلها عبر `update_page`). وقد
  يضبط أيضًا مفتاح ترجمة مشتركًا على الصفحة المصدر، وعلى صفحات اللغات الأخرى
  المرتبطة بها مسبقًا عبر المسار، باستخدام عملية الكتابة نفسها الآمنة من تعارض
  المراجعات.
- **الإخفاء بدل الحذف.** لا توجد أداة حذف. بعد النشر التالي، تخرج الصفحة المخفية
  عبر `set_page_visibility` من التنقّل وبحث الموقع وخريطة الموقع و`llms.txt`،
  ويتوقف رابطها عن عرضها. وتخرج الصفحات الفرعية من التنقّل لكنها تبقى متاحة عبر
  روابطها الخاصة. وتُفشل الروابط من الصفحات الظاهرة إلى صفحة مخفية فحصَ الروابط
  المعطّلة عند النشر.
- **بيانات غير موثوقة.** يُعاد محتوى الصفحات وعبارات البحث وملاحظات القرّاء
  بوصفها بيانات، ويوجّه الخادم العملاء إلى عدم اتباع أي تعليمات ترد داخلها أبدًا.

## عبارات البحث وقيود التحليلات

في وضع ClickHouse، يقرأ `get_top_searches` و`get_failed_searches` نموذج البحث نفسه
الذي يستخدمه قسم **البحث** في لوحة التحكم:

- تُدمج ضغطات المفاتيح أثناء الكتابة في بحث واحد مستقر هو العبارة النهائية؛
- لا يظهر نص العبارة إلا إذا بحثت عنها زيارتان مختلفتان على الأقل. أما العبارات
  الأندر فتُحتسب لكنها تبقى مخفية؛
- العبارات الفاشلة هي التي لم تُعِد نتائج، أو أعادت نتائج لم ينقر عليها أحد.

لا توجد عبارات البحث الخام إلا إذا تحققت كل الشروط التالية:

1. أن تعمل النسخة بتحليلات ClickHouse (`ANALYTICS_MODE=clickhouse`)؛
2. أن يكون الموقع عامًا، وأن يفعّل المشروع **الإعدادات ← التحليلات ← تخزين عبارات
   البحث العامة**؛
3. أن يحمل بحث القارئ `consentState=granted`، أو `not_required` في موقع بلا لافتة
   موافقة. وموقع القرّاء المضمّن يرسله.

تحمل أحداث البحث الاستعلام دائمًا مجزّأً (salted hash)، ونصًا فقط عند تحقق هذه
الشروط. وعند غياب العبارات تعيد الأدوات المجاميع والنسب مع تلميح يوضح السبب. ولا
تخزّن التحليلات العلائقية نص البحث ولا عدد النتائج ولا النقرات، لذلك يبلّغ
`get_failed_searches` بأنه غير متاح فيها.

وفي وضع ClickHouse يعيد `get_referrers` أيضًا نشاط زواحف الذكاء الاصطناعي من التقرير
نفسه الذي يعرضه قسم **الظهور في الذكاء الاصطناعي** في لوحة التحكم: طلبات زواحف الذكاء
الاصطناعي، والصفحات التي جلبها المساعدون لشخص ما، والزواحف نفسها، والصفحات الأكثر
زحفًا. وتحتسب كل أدوات التحليلات البشر فقط؛ أما الزواحف فيُبلَّغ عنها منفصلة.

لا تُخزَّن تعليقات القرّاء. وبيانات البحث والزواحف وتقييمات الصفحات غير مقسّمة حسب
اللغة، لذلك تتجاهل هذه الأدوات عامل تصفية اللغة، ويذكر الرد ذلك.

## حد الإمكانات الحالي

مورد الإمكانات هو المرجع النهائي. يشمل سطح القراءة المستقر بيانات المشروع؛
وبيانات الصفحات ومحتواها المؤلف؛ واللغات والإصدارات؛ والتحليلات المجمعة؛ وإعدادات
البحث وتشخيص الفهرس الخالي من المحتوى؛ وملخصات الاستخدام الدقيقة والاستحقاقات
الإرشادية؛ وقراءة كتالوج الإضافات وحالتها وسجلها؛ وبيانات قالب السمة وكتالوجها
الآمنة ومعاينة الاستيراد من دون كتابة؛ وملخصات منقحة للتصدير والنشر؛ وبيانات
تغييرات النشر المعلّقة؛ وكتالوج التكاملات وحالات الاتصال وGit المطابقة للحقيقة.
وتتطلب عبارات البحث الخام النطاق المستقل `analytics:search_terms`.

يقتصر سطح الكتابة على `pages:write` (إنشاء مسودات الصفحات وتعديلها ونقلها
وترجمتها وإخفاؤها وإظهارها) و`deployments:publish` (المعاينة والنشر المؤكد). لا
يُصدَر أي نطاق لـ `usage:export` أو إعادة فهرسة البحث أو تغيير الإضافات أو السمات
أو تحقق التكاملات أو حذفها أو بيانات الاعتماد أو الدفع. ويبقى `exports:read` سطح
قراءة مستقلًا لملخصات مهام التصدير المنقحة.

تستخدم موارد المشروع عناوين مرتبطة مثل:

```text
nibleaf://projects/{boundProjectId}
nibleaf://projects/{boundProjectId}/pages
nibleaf://projects/{boundProjectId}/pages/{pageId}
nibleaf://projects/{boundProjectId}/pages/{pageId}/markdown
nibleaf://projects/{boundProjectId}/languages
nibleaf://projects/{boundProjectId}/versions
nibleaf://projects/{boundProjectId}/search/configuration
nibleaf://projects/{boundProjectId}/usage
nibleaf://projects/{boundProjectId}/entitlements
nibleaf://projects/{boundProjectId}/addons
nibleaf://projects/{boundProjectId}/theme-catalog
nibleaf://projects/{boundProjectId}/theme-template
nibleaf://projects/{boundProjectId}/integrations
nibleaf://projects/{boundProjectId}/deployments/latest
```

يعيد المورد `/markdown` صفحة واحدة بصيغة `text/markdown` مع البيانات الوصفية في
مقدمة الملف، بالصيغة نفسها المستخدمة في مزامنة Git.

يعيد معرّف مشروع مختلف أو صفحة خارج المشروع المرتبط نتيجة عدم العثور نفسها
التي يعيدها مورد غير موجود. تحذف إسقاطات القراءة حمولات المزوّد وعناوين معاينة
Bearer ومفاتيح التخزين والبصمات ولقطات النشر وحالة نظام ملفات السمة والأخطاء
الخام وبيانات الاعتماد. تعرض تشخيصات البحث بيانات المخطط والمراجعة والنموذج
المنطقية، لكنها لا تعرض المجموعات المادية أو المحتوى أو المتجهات أو البصمات أو
حمولات المزوّد الخام. تبقى كميات الاستخدام وحدوده سلاسل عشرية دقيقة أو `null`؛
ولا تتحول البيانات الجزئية أو غير المتاحة إلى صفر، كما يبقى سلوك الحظر المضبوط
إرشاديًا فقط. يتضمن نطاق `pages:read` المحتوى المؤلف داخل المشروع المرتبط
الواحد؛ فلا تمنحه إلا إذا احتاج العميل إلى نصوص المستندات.

## تشغيل التدقيق وتحديد المعدل

يضيف كل استدعاء أداة أو مورد حدث تدقيق مصغّرًا من ناحية الخصوصية إلى الجدول
`mcp_audit_event` قبل الإبلاغ عن النجاح. وتُدقَّق كل محاولة كتابة، سواء نجحت أو
انتهت بخطأ تحقق أو رفض صلاحية أو تعارض أو بلوغ حد المعدل أو إعادة تشغيل من سجل عدم
التكرار. يسجل الحدث المشروع، ومفتاح API أو اتصال OAuth ‏(`apiKeyId` أو `oauthGrantId`)، والمستخدم الفاعل (`actorUserId`) ومعرّف
الطلب والعملية والإمكانية ونوع الهدف ومعرّفه (`targetType` و`targetId`، كصفحة أو
عملية نشر) والنتيجة ورمز الخطأ الثابت والمدة ومعرّف الطلب من جهة العميل
(`clientRequestId`) والطابع الزمني. ولا يخزّن مدخلات الأدوات أو النتائج أو محتوى
الصفحات أو رموز Bearer أو حمولات المزوّد أو عناوين IP أو مفاتيح العميل الخام. إذا
تعذر حفظ التدقيق تفشل العملية بأمان مع خطأ تخزين منقح.

تنطبق ثلاثة حدود لكل مفتاح أو اتصال OAuth داخل كل عملية API:

| المتغيّر | القيمة الافتراضية | ما يُحتسب |
| --- | --- | --- |
| `MCP_RATE_LIMIT_PER_MIN` | `120` | كل طلبات MCP لكل مفتاح في الدقيقة. |
| `MCP_WRITE_RATE_LIMIT_PER_MIN` | `20` | كل استدعاء لأداة كتابة لكل مفتاح في الدقيقة. ولا يُحتسب `preview_publish`. |
| `MCP_PUBLISH_RATE_LIMIT_PER_HOUR` | `6` | محاولات `publish_changes` لكل مفتاح في الساعة التي تجتاز فحص رمز المعاينة. |

تعيد عملية الكتابة أو النشر المرفوضة `http:rate_limited` مع
`data.retryAfterSeconds`.

تُحفظ هذه العدادات في الذاكرة داخل كل عملية API (نسخة) على حدة، وليست حدودًا
شاملة للنشر بين النسخ المتعددة، وتُصفَّر عند إعادة تشغيل العملية. طبّق حدًا شاملًا عند بوابة الدخول الموثوقة أو الحافة
المشتركة، وراقب HTTP `429` و`Retry-After` وترويسات `X-RateLimit-*`. ولتقييد تضخّم
كتابات التدقيق، يسجّل النقل رفض `transport_rate_limit` واحدًا لكل مفتاح ونافذة
بدل إضافة صف لكل استجابة `429` متكررة. لا تصف عداد عملية واحدة بأنه الحصة الشاملة
للعميل.

## التدوير والإلغاء والتراجع

يلغي التدوير المفتاح القديم ذريًا وينشئ مفتاحًا جديدًا منتهيًا. حدّث العميل
بالسر الذي يظهر مرة واحدة، وتحقق من `tools/list`، ثم احذف السر القديم من مخزنه.
الإلغاء غير قابل للعكس ويتطلب مربع تأكيد في لوحة التحكم، ويسري في الطلب التالي.
ولا يُعدّ وجود نسخة احتياطية لقاعدة البيانات سببًا لإعادة تمكين مفتاح مسرّب.

طبّق ترحيلات MCP في فترة منخفضة النشاط قبل تفعيل نقطة النهاية، عبر خطوة الترحيل
المعتادة في الإصدار (`pnpm db:deploy`، أو خطوة الترحيل في طريقة النشر لديك). يضيف
الترحيل الأول أعمدة مصدر قابلة للقيمة الفارغة وفهرسين إلى جدول `api_key` الحالي
الذي يديره المشغّل، ثم ينشئ جدول التدقيق الفارغ في البداية. ويضيف ترحيل مسار
الكتابة `20261106090000_mcp_write_audit_idempotency` الأعمدة القابلة للقيمة الفارغة
`actorUserId` و`targetType` و`targetId` و`clientRequestId` وفهرسًا للمستخدم الفاعل
إلى `mcp_audit_event`، وينشئ ذاكرة الإعادة `mcp_idempotency_record` التي تخزّن بصمة
الوسائط وملخصًا موجزًا للنتيجة، ولا تخزّن المدخلات أو المحتوى أبدًا. قد تحجب أوامر PostgreSQL القياسية لإنشاء
الفهارس والتحقق من المفتاح الخارجي عمليات إنشاء مفاتيح API أو تدويرها أو إلغائها
لفترة قصيرة. افحص حجم الجدول والأقفال النشطة أولًا، وأوقف عمليات لوحة التحكم هذه
أثناء الترحيل، وأبقِ MCP معطّلًا حتى يكتمل. يستخدم الترحيل عمدًا مسار Prisma
القياسي في المستودع بدل إجراء فهرسة متزامن متعدد الخطوات قد يترك فهرسًا مطبقًا
جزئيًا أو غير صالح يحتاج إلى استرداد يدوي.

قبل التراجع عن التطبيق، عطّل MCP وأوقف عملاءه. لا تنفذ `rollback.sql` الخاص
بترحيل MCP بعد نجاح ترحيل Prisma. انشر تطبيقًا لا يقرأ بيانات تدقيق MCP أو
أعمدة مصدر مفاتيح API التي يملكها MCP، ثم انشر عبارات الرجوع المراجعة بوصفها
ترحيلًا تقدميًا لاحقًا وبترتيب الاعتماد العكسي. استخدم عبارات التراجع في
المستودع مباشرة فقط لعكس ترحيل فاشل طُبّق جزئيًا؛ وبعد عكس العبارات الجزئية
بأمان، علّم الترحيل الفاشل كمتراجع عنه وأعد تشغيل الترحيل التقدمي المصحح. انسخ
سجلات التدقيق احتياطيًا أولًا إذا كانت سياسة الاحتفاظ تتطلبها.

لأن MCP هو الترحيل التابع الأخير، عطّله واعكسه قبل مخطط التكاملات. اتبع
الترتيب العكسي كاملًا في
[دليل ترحيل الإصدار المجمع](/ar/self-hosting/combined-release-migration).

## OAuth لعملاء MCP

تستطيع موصلات ChatGPT، والموصلات المخصّصة في claude.ai وClaude Desktop، وClaude
Code وCursor وVS Code الاتصال بالعنوان وحده: يضيف الشخص `<APP_URL>/api/mcp` إلى
العميل، ويسجّل الدخول إلى Nibleaf في المتصفح، ويختار مشروعًا واحدًا وإعدادًا مسبقًا
للصلاحيات، ثم يوافق. لا يُنسخ أي مفتاح. وتبقى مفاتيح API الشخصية تعمل كما هي إلى
جانب OAuth.

خادم المصادقة في Nibleaf ‏(Better Auth 1.7.18) هو خادم تفويض OAuth 2.1، عبر الإضافة
الرسمية `@better-auth/mcp` مع `@better-auth/cimd` وإضافة `jwt`. ويعمل مع نقطة MCP
في الوقت نفسه، لذا فإن `MCP_ENABLED=true` على خدمة API هو المفتاح الوحيد.

### المتطلبات

- يكون `BETTER_AUTH_URL` هو المصدر العام للوحة التحكم (القيمة نفسها لـ `APP_URL` في
  ملفات Compose المرفقة). ويجب أن يستخدم HTTPS؛ ولا يُقبل HTTP العادي إلا لـ
  `localhost` وعناوين الحلقة المحلية أثناء التطوير. على أي مصدر HTTP آخر يبقى OAuth
  معطّلًا، وتسجّل واجهة API تحذيرًا، وتطلب صفحة الإعدادات من الأشخاص استخدام مفتاح
  شخصي.
- يجب أن تصل لوحة التحكم إلى واجهة API للمسار `/api/**` ولبادئات الاكتشاف الثلاث
  أدناه. تمرّرها لوحة التحكم المرفقة بالفعل؛ ويجب على أي وكيل عكسي أمامها أن يمرّرها
  دون تغيير.
- طبّق الترحيل `20261106120000_mcp_oauth` قبل تفعيل MCP. فهو ينشئ جداول OAuth حتى
  إن بقي MCP معطّلًا.

```dotenv
BETTER_AUTH_URL=https://docs.example.com
MCP_ENABLED=true
```

### الاكتشاف ونقاط النهاية

| العنوان | الغرض |
| --- | --- |
| `<APP_URL>/api/mcp` | مورد MCP المحمي. ترتبط رموز الوصول بهذا العنوان بالضبط كجمهور (audience). |
| `<APP_URL>/.well-known/oauth-protected-resource/api/mcp` | بيانات المورد المحمي وفق RFC 9728 (وتُخدَم أيضًا من دون اللاحقة `/api/mcp`). |
| `<APP_URL>/.well-known/oauth-authorization-server/api/auth` | بيانات خادم التفويض وفق RFC 8414 للمُصدِر `<APP_URL>/api/auth` (وتُخدَم أيضًا من المسار الجذر). |
| `<APP_URL>/api/auth/.well-known/openid-configuration` | بيانات OpenID (وتُخدَم أيضًا من `/.well-known/openid-configuration` وصيغتها مع `/api/auth`). |
| `<APP_URL>/api/auth/oauth2/register` | تسجيل العملاء الديناميكي (RFC 7591) للعملاء العامّين. |
| `<APP_URL>/api/auth/oauth2/authorize`، `/oauth2/token`، `/oauth2/revoke` | نقاط رمز التفويض مع PKCE ‏(S256) والرموز والإلغاء. |

تحمل كل استجابة `401` من `/api/mcp` تحديًا وفق RFC 6750 مع المؤشر
`resource_metadata` وفق RFC 9728، وبه يجد العميل مسار تسجيل الدخول. تحقّق من نسخة
ما بالأمرين:

```bash
curl -s https://docs.example.com/.well-known/oauth-protected-resource/api/mcp
curl -si -X POST https://docs.example.com/api/mcp | grep -i www-authenticate
```

يبدو التحدي هكذا؛ ويحصل الرمز الذي ينقصه `mcp:connect` على
`error="insufficient_scope"` مع `scope="mcp:connect"` والحالة `403`:

```text
WWW-Authenticate: Bearer realm="Nibleaf MCP", scope="mcp:connect projects:read ... offline_access", resource_metadata="https://docs.example.com/.well-known/oauth-protected-resource/api/mcp"
```

### تسجيل العملاء

تسجّل العملاء نفسها بنفسها. يستخدم ChatGPT وclaude.ai التسجيل الديناميكي للعملاء:
التسجيل المفتوح مفعّل للعملاء العامّين (`token_endpoint_auth_method: none`)، وPKCE
إلزامي، ولا يُعرض منح `client_credentials` لأن كل رمز يجب أن يعمل باسم شخص. أما
العملاء التي تنشر مستند Client ID Metadata فتستخدم عنوان HTTPS الخاص به معرّفًا
للعميل؛ فيجلب Nibleaf المستند ويتحقق منه (ملف MCP 2026-07-28) ويعرض نطاقه في صفحة
الموافقة على أنه موثَّق. أما العميل المسجَّل ديناميكيًا فيختار اسمه بنفسه، لذا تصفه
صفحة الموافقة بأنه غير موثَّق وتعرض المكان الذي سيعود إليه الشخص.

إدارة العملاء المعتمدة على الجلسة (`/api/auth/oauth2/create-client` و
`update-client` و`delete-client` و`get-client` و`get-clients` و
`client/rotate-secret`) ومسار JWT الخاص بالجلسة في Better Auth ‏(`/api/auth/token`)
معطّلة.

### ربط المشروع والإعداد المسبق

بعد تسجيل الدخول يسأل Nibleaf الشخص عن المشروع الذي يخصّه الاتصال والإعداد المسبق
الذي يحصل عليه (القراءة فقط، أو مساعد كتابة الدعم، أو مسؤول كامل). والقواعد هي
قواعد المفاتيح الشخصية نفسها: يجب أن يكون الشخص عضوًا في المشروع، ولا يُعرض «مسؤول
كامل» إلا على المسؤولين والمالكين. يُحفظ الاختيار كصف في `mcp_oauth_grant`؛ ومعرّفه
هو مرجع الموافقة في Better Auth، ويُنقل في كل رمز وصول كمطالبة `nibleaf_grant`
إلى جانب `nibleaf_project`. ثم تعرض صفحة الموافقة التطبيق والمشروع، وبلغة بسيطة
ما سيستطيع التطبيق فعله وما لن يستطيعه. ولا تستطيع جلسات الدعم (انتحال الهوية)
ربط التطبيقات.

في كل طلب MCP يتحقق الخادم من الرمز محليًا مقابل مفاتيح التوقيع الخاصة بالنسخة
(التوقيع، والمُصدِر `<APP_URL>/api/auth`، والجمهور `<APP_URL>/api/mcp`، وتاريخ
الانتهاء، والنوع `at+jwt`)، ثم يعيد قراءة المنح وعضوية الشخص وحالة الإيقاف.
والنطاقات الفعلية هي تقاطع الإعداد المسبق للمنح مع نطاقات الرمز ومع ما يسمح به دور
الشخص الحالي. يسري إلغاء الاتصال، أو إزالة الشخص أو إيقافه، أو تخفيض دوره، من
الطلب التالي.

ويمكن للعملاء أيضًا تقييد رموزهم بالمرسل عبر DPoP ‏(RFC 9449). يجب إرسال الرمز
المقيّد بـ DPoP بالصيغة `Authorization: DPoP <token>` مع إثبات في ترويسة `DPoP`
موقَّع بالمفتاح المقيَّد به، ويغطي طريقة الطلب والرمز والعنوان العام
`<APP_URL>/api/mcp`، ويُتحقق من هذا العنوان حتى عندما يصل الطلب إلى الواجهة البرمجية
عبر وكيل لوحة التحكم. ويعمل كل إثبات مرة واحدة: إذ يُحجز `jti` الخاص به في جدول
`verification` في Better Auth، فتفشل إعادة استخدامه على كل نسخ الواجهة البرمجية.
ويُرفض الرمز المقيّد بـ DPoP إذا أُرسل بصيغة `Bearer`. أما مفاتيح API الشخصية فتُرسل
دائمًا بصيغة `Bearer`.

رموز الوصول هي JWT صالحة لساعة واحدة. وتصدر رموز التحديث عندما يطلب العميل
`offline_access`، وتدوم 30 يومًا، وتُدوَّر بصرامة: يعمل رمز التحديث مرة واحدة. ويعيد
كل تحديث التحقق من أن الاتصال ما زال قائمًا.

### التطبيقات المتصلة والإلغاء

تعرض **الإعدادات ← مساعدو الذكاء الاصطناعي (MCP) ← التطبيقات المتصلة** الاتصالات
القائمة مع التطبيق والإعداد المسبق ومن ربطه وآخر استخدام وآخر نشاط. يرى الأعضاء
اتصالاتهم ويفصلونها، ويرى المسؤولون والمالكون اتصالات الجميع ويفصلونها. ويلغي
الفصل المنح ورموز التحديث الخاصة به وموافقته فورًا. وربط التطبيق نفسه بالمشروع نفسه
مرة أخرى يحلّ محل الاتصال السابق للشخص نفسه.

تسجّل صفوف التدقيق لاستدعاءات OAuth المنح في `mcp_audit_event.oauthGrantId` (ويبقى
عمود مفتاح API فارغًا)، فتُنسب كل استدعاء إلى الشخص والاتصال. وتُحتسب حدود الطلبات
والكتابة والنشر لكل اتصال تمامًا كما تُحتسب لكل مفتاح. ولأن العملاء المستضافة
تستدعي نقطتي الرموز والتسجيل من عناوين مشتركة، فلهاتين النقطتين حدٌّ خاص أكبر لكل
عنوان IP.

### الترقية والتراجع

1. انشر الإصدار وشغّل خطوة الترحيل المعتادة (`pnpm db:deploy`). ينشئ الترحيل
   `20261106120000_mcp_oauth` الجداول `jwks` و`oauth_client` و`oauth_resource` و
   `oauth_client_resource` و`oauth_refresh_token` و`oauth_access_token` و
   `oauth_consent` و`oauth_client_assertion` و`mcp_oauth_grant`، ويضيف العمود
   القابل للفراغ `oauthGrantId` إلى `mcp_audit_event` و`mcp_idempotency_record`،
   ويجعل `mcp_idempotency_record.apiKeyId` قابلًا للفراغ. ولا يمسّ الصفوف الموجودة.
2. اضبط `BETTER_AUTH_URL` على مصدر لوحة التحكم عبر HTTPS وأبقِ `MCP_ENABLED=true`
   على خدمة API، ثم أعد إنشاء الخدمة.
3. تحقق من أمري `curl` أعلاه، ثم اربط عميلًا واحدًا من البداية إلى النهاية.

يتحقق Better Auth من جداوله في كل طلب مصادقة ما دامت إضافات MCP محمّلة. وتفعيل
MCP على صورة تعمل قبل هذا الترحيل يعطّل كل تسجيلات الدخول، لا MCP وحده؛ لذا طبّق
الترحيل أولًا. وللتراجع، عطّل MCP، وانشر الصورة السابقة، ثم فقط بعد ذلك طبّق
`rollback.sql` الخاص بالترحيل كترحيل لاحق خضع للمراجعة. فهو يحذف صفوف إعادة التشغيل
الخاصة بـ OAuth، ويعيد إلزامية `apiKeyId`، ويحذف جداول OAuth، وهذا يُخرج كل عملاء
OAuth.

## استكشاف الأخطاء وإصلاحها بأمان

- `503 mcp:disabled`: فعّل MCP في خدمة API وأعد إنشاءها.
- `400 mcp:invalid_request`: صحح تمرير المضيف أو المصدر المشوّه أو الملتبس.
- `401 auth:invalid_api_key`: استبدل المفتاح المشوّه أو المنتهي أو الملغى أو الخالي من تاريخ الانتهاء، أو المفتاح الذي أُزيل مالكه أو عُلّق حسابه أو حُذف.
- `401 auth:invalid_token`: انتهت صلاحية رمز وصول OAuth، أو صدر لعنوان آخر، أو فُصل اتصاله، أو أُزيل صاحبه أو أُوقف. يجدّد العميل الرمز أو يسجّل الدخول من جديد.
- `403` مع `error="insufficient_scope"`: طلب العميل نطاقات أقل من اللازم؛ أعد ربطه ليطلب `mcp:connect`.
- `404` من `/.well-known/oauth-protected-resource/api/mcp`: إما أن MCP معطّل، أو أن `BETTER_AUTH_URL` ليس HTTPS (ولا عنوان حلقة محلية)؛ ويبقى OAuth معطّلًا في الحالتين.
- «انتهت صلاحية طلب الربط هذا» في المتصفح: مضى على الطلب الموقَّع أكثر من 10 دقائق؛ ابدأ الربط من جديد من العميل.
- `403 auth:insufficient_scope` أو `mcp:scope_required`: أنشئ المفتاح أو دوّره مع `mcp:connect` والنطاق الدقيق، ويجب أن يسمح به دور المالك الحالي أيضًا.
- `auth:insufficient_role`: لم يعد دور مالك المفتاح الحالي يسمح بهذا التغيير.
- `mcp:actor_required`: ليس للمفتاح مالك فعّال، فالكتابة مستحيلة؛ وعلى المالك إنشاء مفتاح جديد.
- `mcp:revision_conflict`: أعد قراءة الصفحة عبر `get_page`، وادمج التغيير، وأعد المحاولة بالمراجعة الجديدة؛ وتتضمن بيانات الخطأ `currentRevision`.
- `mcp:preview_stale`: تغيّر شيء بعد المعاينة؛ شغّل `preview_publish` من جديد وأعد المراجعة.
- `mcp:preview_expired`: مضى على الرمز أكثر من 10 دقائق؛ أعد المعاينة.
- `mcp:preview_invalid`: الرمز غير صالح لهذا الشخص والمشروع؛ أعد المعاينة.
- `mcp:confirmation_required`: يحتاج `publish_changes` إلى `confirm: true` بعد موافقة شخص على المعاينة.
- `mcp:nothing_to_publish`: لا توجد تغييرات غير منشورة.
- `mcp:publish_blocked`: أصلح المشكلة المانعة، مثل مشكلات إعادة التوجيه، في لوحة التحكم، ثم أعد المعاينة.
- `mcp:publish_in_progress` (`409`): توجد عملية نشر في الطابور أو قيد البناء، لذلك تنتظر عمليات كتابة الصفحات و`publish_changes`، ولم يُحفظ شيء. أعد المحاولة بعد أن يُظهر `get_deployment` أنها جاهزة أو فاشلة.
- `mcp:translation_exists`: يحدد `data.pageId` الترجمة الموجودة؛ عدّلها عبر `update_page`.
- `mcp:idempotency_conflict`: أُعيد استخدام `clientRequestId` نفسه مع وسائط مختلفة؛ استخدم معرّفًا جديدًا.
- `mcp:idempotency_in_progress`: ما زال الاستدعاء الأول بهذا `clientRequestId` قيد التنفيذ؛ أعد المحاولة.
- خطأ مورد `404`: تحقق من أن العنوان يستخدم مشروع المفتاح المرتبط وموردًا داخله.
- `429` أو `http:rate_limited`: التزم بـ`Retry-After` أو `data.retryAfterSeconds`، وافحص حدود بوابة الدخول وحدود الطلبات والكتابة والنشر في النسخة.
- `503 storage:error`: أعد خدمة حفظ التدقيق قبل المحاولة؛ فلا يُبلَّغ عن نجاح أي استدعاء دون حدث تدقيق.
