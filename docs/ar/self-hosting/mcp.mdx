يوفّر Nibleaf نقطة MCP مصادَقًا عليها عبر HTTP في `/api/mcp`، وهي معطّلة
افتراضيًا. يرتبط كل مفتاح بمشروع واحد، ويعود إلى العضو الذي أنشأه، ويحمل نطاقات
صريحة، وله تاريخ انتهاء. يشتق الخادم المشروع والمؤسسة من المفتاح؛ ولا تقبل
الأدوات أيًا منهما كسلطة يحددها المتصل.

تغطي أدوات القراءة المحتوى والتحليلات والبحث والاستخدام والإضافات والسمات
والتصدير وعمليات النشر والتكاملات. وتستطيع أدوات «كاتب الدعم» إنشاء مسودات
الصفحات وتعديلها ونشرها بعد معاينة وتأكيد صريحين. لا تتوفر عمليات الحذف، ولا
تغيير الإعدادات أو العضوية، ولا بيانات اعتماد المزوّد أو الدفع أو بدائيات قاعدة
البيانات أو الوصول العشوائي للملفات أو تنفيذ الشيفرة. لمسار عمل الدعم وفهرس
الأدوات الكامل، راجع [العمل على التوثيق مع مساعد ذكاء اصطناعي](/ar/product/ai-assistants).

## تفعيل نقطة النهاية

اضبط بيئة خدمة API:

```dotenv
MCP_ENABLED=true
MCP_ALLOWED_HOSTS=mcp.docs.example.com
MCP_RATE_LIMIT_PER_MIN=120
MCP_WRITE_RATE_LIMIT_PER_MIN=20
MCP_PUBLISH_RATE_LIMIT_PER_HOUR=6
```

تُسمح أسماء المضيفين في `API_URL` و`APP_URL` دائمًا. أضف إلى
`MCP_ALLOWED_HOSTS` أسماء المضيفين العامة الإضافية فقط؛ ولا تضف بروتوكولًا أو
مسارًا أو معلومات مستخدم أو فاصلة داخل المضيف الواحد أو قيمة بحرف بدل. أعد
إنشاء خدمة API بعد التغيير.

تتحقق نقطة النهاية من `Host` و`Origin` و`X-Forwarded-Host` و
`X-Forwarded-Proto` قبل المصادقة. اضبط الوكيل العكسي العام ليستبدل ترويسات
التمرير غير الموثوقة ويمرر مضيفًا وبروتوكولًا واحدين واضحين. أبقِ MCP معطّلًا إلى
أن يعيد مسار TLS والوكيل العام اسم المضيف المتوقع.

## المفاتيح الشخصية والتحقق الحي من الصلاحيات

ينشئ أي عضو في المشروع مفتاحه الخاص من **الإعدادات ← مساعدو الذكاء الاصطناعي
(MCP)**، فيختار إعدادًا مسبقًا ومدة صلاحية بين 7 أيام و365 يومًا، ويظهر السر مرة
واحدة فقط:

| الإعداد المسبق | متاح لـ | النطاقات |
| --- | --- | --- |
| قراءة فقط (Read only) | الأعضاء فما فوق | `mcp:connect` و`projects:read` و`pages:read` و`languages:read` و`versions:read` و`analytics:read` و`search:read` و`deployments:read` |
| كاتب الدعم (Support writer) | الأعضاء فما فوق | نطاقات «قراءة فقط» إضافة إلى `analytics:search_terms` و`pages:write` و`deployments:publish` |
| مسؤول كامل (Full admin) | المسؤولون والمالكون | كل نطاقات MCP |

الإعدادات المسبقة تسهيل في لوحة التحكم فقط؛ أما الحد الأمني فهو مجموعة النطاقات
مع دور منشئ المفتاح. يعمل المفتاح باسم منشئه، ويعيد الخادم في كل طلب قراءة دور
المنشئ الحالي في مساحة العمل وحالة تعليق حسابه، فلا يستطيع المفتاح أبدًا أن
يتجاوز ما يستطيعه مالكه في لوحة التحكم في تلك اللحظة. وعند إزالة عضو أو تعليق
حسابه تتوقف مفاتيحه في الطلب التالي. أما المفاتيح القديمة التي لا مالك مسجّلًا لها
فتبقى للقراءة فقط. ولا تفعل النطاقات إلا تضييق ما يسمح به دور المالك أصلًا.

يرى الأعضاء مفاتيحهم ويلغونها، ويرى المسؤولون والمالكون كل مفاتيح المشروع
ويلغونها. يعرض كل مفتاح آخر استخدام وآخر نشاط له، ويتحقق زر **اختبار الاتصال**
من المفتاح والمضيف ومفتاح تشغيل MCP في خطوة واحدة. خزّن السر في مخزن أسرار
العميل، لا في التحكم بالمصدر أو سجل الطرفية أو رسائل الدعم أو السجلات أو لقطات
الشاشة أو إعداد MCP محفوظ في مستودع.

يحتاج كل مفتاح MCP إلى `mcp:connect`. لا يتحكم النطاق إلا في سطحه المسمى ولا
يوسّع ارتباط المفتاح بالمشروع. يعرض اكتشاف الإمكانات الأدوات والموارد والموجّهات
المسجلة للمفتاح نفسه. لا تفترض توفر إمكانية موثقة إذا لم تظهر في `tools/list`
أو `nibleaf://capabilities`.

لا تستطيع مفاتيح حرف البدل القديمة الاتصال عمدًا. يظهر المفتاح ذو تاريخ انتهاء
فارغ أو من دون `mcp:connect` أو بحالة ترحيل قديمة على أنه يحتاج إلى التدوير.
دوّره إلى مجموعة نطاقات صريحة ومنتهية بدل تعديل صف قاعدة البيانات.

## ضبط العميل

استخدم المصدر العام لواجهة API ومرّر المفتاح كرمز Bearer. غالبًا ما يقبل عميل
يدعم خوادم MCP البعيدة عبر HTTP إعدادًا بهذا الشكل:

```json
{
  "mcpServers": {
    "nibleaf": {
      "url": "https://api.docs.example.com/api/mcp",
      "headers": {
        "Authorization": "Bearer ${NIBLEAF_MCP_API_KEY}"
      }
    }
  }
}
```

تختلف أسماء إعدادات العملاء. استخدم خيار HTTP أو الخادم البعيد، لا أمرًا محليًا
ولا موصل ملفات. تولّد لوحة الإعداد في لوحة التحكم أوامر وروابط خاصة بكل من
Claude Code وClaude Desktop وCursor وVS Code. استدعِ أولًا `tools/list` ثم
`get_capabilities`. تحتوي الاستجابة الناجحة على محتوى بروتوكول MCP وغلاف منظم يضم
معرّف الطلب ومعرّف المشروع المرتبط والإمكانية المطلوبة.

لا تستطيع العملاء التي لا تتصل إلا عبر OAuth، مثل موصلات ChatGPT وشاشات الموصلات
في claude.ai، استخدام مفاتيح API. راجع قسم «OAuth لعملاء MCP» أدناه.

## ضمانات الكتابة والنشر

- **نسخة العمل فقط.** تنشئ أدوات `pages:write` المسودات وتعدّلها، ولا يصبح شيء
  منشورًا قبل نجاح النشر.
- **نشر على مستوى المشروع ببوابة بشرية.** يتضمن النشر كل تغيير غير منشور في
  المشروع، لا تغييرات مالك المفتاح وحده. على العميل استدعاء `preview_publish`، ثم
  يراجع شخص القائمة، ثم يستدعي العميل `publish_changes` مع `confirm: true` ورمز
  المعاينة. وأي تغيير بعد المعاينة يُبطل الرمز.
- **التزامن المتفائل.** تحمل عمليات الكتابة `expectedRevision`. فإذا حفظ شخص
  مراجعة أحدث، تفشل الكتابة بتعارض في المراجعة بدل أن تستبدلها.
- **عدم التكرار.** يستطيع العميل إرسال `clientRequestId`، فلا يُطبَّق الطلب المعاد
  بالمعرّف نفسه مرتين.
- **لا أداة حذف.** إخفاء الصفحة هو البديل القابل للتراجع.
- **بيانات غير موثوقة.** يُعاد محتوى الصفحات وعبارات البحث وملاحظات القرّاء
  بوصفها بيانات، ويوجّه الخادم العملاء إلى عدم اتباع أي تعليمات ترد داخلها أبدًا.
- **عبارات البحث اختيارية.** لا يعيد `analytics:search_terms` العبارات إلا إذا
  فعّل المشروع **الإعدادات ← التحليلات ← تخزين عبارات البحث العامة**.

## حد الإمكانات الحالي

مورد الإمكانات هو المرجع النهائي. يشمل سطح القراءة المستقر بيانات المشروع؛
وبيانات الصفحات ومحتواها المؤلف؛ واللغات والإصدارات؛ والتحليلات المجمعة؛ وإعدادات
البحث وتشخيص الفهرس الخالي من المحتوى؛ وملخصات الاستخدام الدقيقة والاستحقاقات
الإرشادية؛ وقراءة كتالوج الإضافات وحالتها وسجلها؛ وبيانات قالب السمة وكتالوجها
الآمنة ومعاينة الاستيراد من دون كتابة؛ وملخصات منقحة للتصدير والنشر؛ وبيانات
تغييرات النشر المعلّقة؛ وكتالوج التكاملات وحالات الاتصال وGit المطابقة للحقيقة.
وتتطلب عبارات البحث الخام النطاق المستقل `analytics:search_terms`.

يقتصر سطح الكتابة على `pages:write` (إنشاء مسودات الصفحات وتعديلها ونقلها
وترجمتها وإخفاؤها وإظهارها) و`deployments:publish` (المعاينة والنشر المؤكد). لا
يُصدَر أي نطاق لـ `usage:export` أو إعادة فهرسة البحث أو تغيير الإضافات أو السمات
أو تحقق التكاملات أو حذفها أو بيانات الاعتماد أو الدفع. ويبقى `exports:read` سطح
قراءة مستقلًا لملخصات مهام التصدير المنقحة.

تستخدم موارد المشروع عناوين مرتبطة مثل:

```text
nibleaf://projects/{boundProjectId}
nibleaf://projects/{boundProjectId}/pages
nibleaf://projects/{boundProjectId}/pages/{pageId}
nibleaf://projects/{boundProjectId}/pages/{pageId}/markdown
nibleaf://projects/{boundProjectId}/languages
nibleaf://projects/{boundProjectId}/versions
nibleaf://projects/{boundProjectId}/search/configuration
nibleaf://projects/{boundProjectId}/usage
nibleaf://projects/{boundProjectId}/entitlements
nibleaf://projects/{boundProjectId}/addons
nibleaf://projects/{boundProjectId}/theme-catalog
nibleaf://projects/{boundProjectId}/theme-template
nibleaf://projects/{boundProjectId}/integrations
nibleaf://projects/{boundProjectId}/deployments/latest
```

يعيد المورد `/markdown` صفحة واحدة بصيغة `text/markdown` مع البيانات الوصفية في
مقدمة الملف، بالصيغة نفسها المستخدمة في مزامنة Git.

يعيد معرّف مشروع مختلف أو صفحة خارج المشروع المرتبط نتيجة عدم العثور نفسها
التي يعيدها مورد غير موجود. تحذف إسقاطات القراءة حمولات المزوّد وعناوين معاينة
Bearer ومفاتيح التخزين والبصمات ولقطات النشر وحالة نظام ملفات السمة والأخطاء
الخام وبيانات الاعتماد. تعرض تشخيصات البحث بيانات المخطط والمراجعة والنموذج
المنطقية، لكنها لا تعرض المجموعات المادية أو المحتوى أو المتجهات أو البصمات أو
حمولات المزوّد الخام. تبقى كميات الاستخدام وحدوده سلاسل عشرية دقيقة أو `null`؛
ولا تتحول البيانات الجزئية أو غير المتاحة إلى صفر، كما يبقى سلوك الحظر المضبوط
إرشاديًا فقط. يتضمن نطاق `pages:read` المحتوى المؤلف داخل المشروع المرتبط
الواحد؛ فلا تمنحه إلا إذا احتاج العميل إلى نصوص المستندات.

## تشغيل التدقيق وتحديد المعدل

يجب أن يضيف كل استدعاء أداة أو مورد، ناجحًا كان أو فاشلًا، حدث تدقيق مصغّرًا من
ناحية الخصوصية قبل الإبلاغ عن النجاح. يسجل الحدث المشروع ومفتاح API والمستخدم
الفاعل ومعرّف الطلب والعملية والإمكانية ومعرّف الهدف (كصفحة أو عملية نشر)
والنتيجة ورمز الخطأ الثابت والمدة ومعرّف الطلب من جهة العميل والطابع الزمني. ولا
يخزّن الوسائط أو النتائج أو المحتوى أو رموز Bearer أو حمولات المزوّد أو عناوين IP
أو مفاتيح العميل الخام. إذا تعذر حفظ التدقيق تفشل العملية بأمان مع خطأ تخزين
منقح.

تحمي ثلاثة حدود كل عملية API:

| المتغيّر | القيمة الافتراضية | ما يُحتسب |
| --- | --- | --- |
| `MCP_RATE_LIMIT_PER_MIN` | `120` | كل طلبات MCP لكل مفتاح في الدقيقة. |
| `MCP_WRITE_RATE_LIMIT_PER_MIN` | `20` | استدعاءات أدوات الكتابة لكل مفتاح في الدقيقة. |
| `MCP_PUBLISH_RATE_LIMIT_PER_HOUR` | `6` | استدعاءات النشر لكل مفتاح في الساعة. |

تُحفظ هذه العدادات داخل كل عملية API (نسخة) على حدة، وليست حدودًا شاملة للنشر
بين النسخ المتعددة. طبّق حدًا شاملًا عند بوابة الدخول الموثوقة أو الحافة
المشتركة، وراقب HTTP `429` و`Retry-After` وترويسات `X-RateLimit-*`. ولتقييد تضخّم
كتابات التدقيق، يسجّل النقل رفض `transport_rate_limit` واحدًا لكل مفتاح ونافذة
بدل إضافة صف لكل استجابة `429` متكررة. لا تصف عداد عملية واحدة بأنه الحصة الشاملة
للعميل.

## التدوير والإلغاء والتراجع

يلغي التدوير المفتاح القديم ذريًا وينشئ مفتاحًا جديدًا منتهيًا. حدّث العميل
بالسر الذي يظهر مرة واحدة، وتحقق من `tools/list`، ثم احذف السر القديم من مخزنه.
الإلغاء غير قابل للعكس ويتطلب مربع تأكيد في لوحة التحكم، ويسري في الطلب التالي.
ولا يُعدّ وجود نسخة احتياطية لقاعدة البيانات سببًا لإعادة تمكين مفتاح مسرّب.

طبّق ترحيل MCP في فترة منخفضة النشاط قبل تفعيل نقطة النهاية. يضيف الترحيل
أعمدة مصدر قابلة للقيمة الفارغة وفهرسين إلى جدول `api_key` الحالي الذي يديره
المشغّل، ثم ينشئ جدول التدقيق الفارغ في البداية. وطبّق في النافذة نفسها أي ترحيلات
MCP لاحقة تذكرها ملاحظات الإصدار. قد تحجب أوامر PostgreSQL القياسية لإنشاء
الفهارس والتحقق من المفتاح الخارجي عمليات إنشاء مفاتيح API أو تدويرها أو إلغائها
لفترة قصيرة. افحص حجم الجدول والأقفال النشطة أولًا، وأوقف عمليات لوحة التحكم هذه
أثناء الترحيل، وأبقِ MCP معطّلًا حتى يكتمل. يستخدم الترحيل عمدًا مسار Prisma
القياسي في المستودع بدل إجراء فهرسة متزامن متعدد الخطوات قد يترك فهرسًا مطبقًا
جزئيًا أو غير صالح يحتاج إلى استرداد يدوي.

قبل التراجع عن التطبيق، عطّل MCP وأوقف عملاءه. لا تنفذ `rollback.sql` الخاص
بترحيل MCP بعد نجاح ترحيل Prisma. انشر تطبيقًا لا يقرأ بيانات تدقيق MCP أو
أعمدة مصدر مفاتيح API التي يملكها MCP، ثم انشر عبارات الرجوع المراجعة بوصفها
ترحيلًا تقدميًا لاحقًا وبترتيب الاعتماد العكسي. استخدم عبارات التراجع في
المستودع مباشرة فقط لعكس ترحيل فاشل طُبّق جزئيًا؛ وبعد عكس العبارات الجزئية
بأمان، علّم الترحيل الفاشل كمتراجع عنه وأعد تشغيل الترحيل التقدمي المصحح. انسخ
سجلات التدقيق احتياطيًا أولًا إذا كانت سياسة الاحتفاظ تتطلبها.

لأن MCP هو الترحيل التابع الأخير، عطّله واعكسه قبل مخطط التكاملات. اتبع
الترتيب العكسي كاملًا في
[دليل ترحيل الإصدار المجمع](/ar/self-hosting/combined-release-migration).

## OAuth لعملاء MCP

لا تتصل بعض العملاء بخوادم MCP البعيدة إلا عبر OAuth، ومنها شاشات الموصلات في
claude.ai وClaude Desktop، وموصلات ChatGPT. لا تستطيع هذه العملاء إرسال مفتاح API
من Nibleaf، ولذلك لا يمكنها الاتصال بهذا الإصدار.

### نتيجة التقييم

تتوقع مواصفة تفويض MCP للخوادم البعيدة ما يلي:

- بيانات وصفية للمورد المحمي (RFC 9728) ينشرها مضيف MCP؛
- بيانات وصفية لخادم التفويض (RFC 8414)؛
- تسجيلًا ديناميكيًا للعملاء (RFC 7591)، لأن العملاء غير معروفين مسبقًا؛
- تدفق رمز التفويض مع PKCE؛
- مؤشرات الموارد (RFC 8707)، ليكون جمهور كل رمز هو نقطة MCP نفسها.

يعتمد Nibleaf في المصادقة على better-auth 1.7.14. ولم يعد هذا الإصدار يتضمن
الإضافتين `mcp` و`oidc-provider`؛ وصادراته المتعلقة بـ OAuth هي `jwt` و
`generic-oauth` و`oauth-proxy` و`device-authorization`، ولا يعمل أي منها خادمَ
تفويض لعملاء خارجيين. لذلك يحتاج دعم OAuth إلى الحزمة المستقلة
`@better-auth/oauth-provider`. ويتطلب إصدارها الحالي better-auth أحدث من 1.7.14،
فتأتي الترقية أولًا.

تضيف الحزمة جداول مصادقة خاصة بها. ومنذ الإصدار 1.7.3 يتحقق better-auth من
جداوله مقابل مخطط Prisma في كل طلب مصادقة، وأي عدم تطابق يعطّل تسجيل الدخول كله،
لا MCP وحده. ولا تكشف الاختبارات التي تستخدم المحوّل الموجود في الذاكرة هذا
الخلل. ويلزم أيضًا شاشة موافقة يربط فيها المستخدم التفويض بمشروع واحد وإعداد
مسبق واحد، كما يفعل المفتاح اليوم.

### قرار هذا الإصدار

نُبقي على مفاتيح API الشخصية المرتبطة بالمشروع. فهي توفر بالفعل نسبة كل عملية
إلى شخص بعينه، والتحقق الحي من الدور، وتاريخ الانتهاء، والإلغاء، وتعمل في Claude
Code وفي Claude Desktop عبر `mcp-remote` وفي Cursor وVS Code. ويؤجَّل OAuth حتى
يمكن إطلاقه من دون تعريض تسجيل الدخول للخطر.

### الخطة

1. **الحزمة والترحيل.** رقِّ better-auth، وأضف `@better-auth/oauth-provider`،
   وأطلق جداولها في ترحيل Prisma مراجَع. واشترط لاعتماده اختبارات مصادقة على
   قاعدة PostgreSQL حقيقية تغطي تسجيل الدخول بالبريد وGoogle والدعوات قبل الترحيل
   وبعده. وراجع كل نقطة نهاية تضيفها الإضافة، وعطّل أي نقطة تتجاوز قواعد العضوية
   والمشاريع الخاصة بـ Nibleaf.
2. **الاكتشاف.** قدّم `/.well-known/oauth-protected-resource` على مضيف MCP مشيرًا
   إلى البيانات الوصفية لخادم التفويض، وأعِد من `/api/mcp` تحدي `WWW-Authenticate`
   يحيل إليه.
3. **الموافقة.** ابنِ شاشة موافقة تُصدر تفويضًا مكافئًا للمفتاح ومرتبطًا بمشروع
   واحد وإعداد مسبق واحد وتاريخ انتهاء. ويمر التفويض بفحوص الدور الحي والتعليق
   والنطاقات والتدقيق وتحديد المعدل نفسها التي يمر بها مفتاح API.
4. **جمهور الرمز.** لا تقبل إلا الرموز التي يكون جمهورها نقطة MCP (RFC 8707)،
   وأبقِ العملاء المسجلين ديناميكيًا على PKCE.
5. **الإلغاء.** اعرض تفويضات OAuth بجوار مفاتيح API في **الإعدادات ← مساعدو
   الذكاء الاصطناعي (MCP)**، بقواعد الإلغاء نفسها للمالك والمسؤول.

عند إطلاق هذه الخطوات، يفتح OAuth الطريق أمام شاشات الموصلات في claude.ai
وClaude Desktop وأمام موصلات ChatGPT، وتبقى مفاتيح API مدعومة.

## استكشاف الأخطاء وإصلاحها بأمان

- `503 mcp:disabled`: فعّل MCP في خدمة API وأعد إنشاءها.
- `400 mcp:invalid_request`: صحح تمرير المضيف أو المصدر المشوّه أو الملتبس.
- `401 auth:invalid_api_key`: استبدل المفتاح المشوّه أو المنتهي أو الملغى أو الخالي من تاريخ الانتهاء، أو المفتاح الذي أُزيل مالكه أو عُلّق حسابه.
- `403 auth:insufficient_scope`: أنشئ المفتاح أو دوّره مع `mcp:connect` والنطاق الدقيق، ويجب أن يسمح به دور المالك الحالي أيضًا.
- تعارض في المراجعة عند الكتابة: أعد قراءة الصفحة وطبّق التغيير على المراجعة الأحدث.
- معاينة قديمة عند النشر: استدعِ `preview_publish` من جديد، وراجع، ثم أكّد بالرمز الجديد.
- خطأ مورد `404`: تحقق من أن العنوان يستخدم مشروع المفتاح المرتبط وموردًا داخله.
- `429 http:rate_limited`: التزم بـ`Retry-After`، وافحص حدود بوابة الدخول وحدود الطلبات والكتابة والنشر في النسخة.
- `503 storage:error`: أعد خدمة حفظ التدقيق قبل المحاولة؛ فلا يُبلَّغ عن نجاح أي استدعاء دون حدث تدقيق.

اربط الأعطال بمعرّف الطلب الآمن. لا تلصق ترويسة Authorization أو وسائط MCP أو
نتائجه الخام أو محتوى المستند أو استجابة المزوّد في السجلات أو تذكرة دعم.
