تظل الحسابات والمشاريع وعمليات النشر في Postgres، بينما يخزن ClickHouse بيانات التحليلات.
**ظهور «التحليلات غير متاحة» لا يعني تعطل موقع التوثيق.** القيمة المجهولة ليست صفراً، ولا يتصل القارئ مباشرة بـ ClickHouse.

## قبل البدء

تصف هذه الصفحة تحليلات المصدر الحالي، بما فيها جداول التقارير والمحادثات
المضافة في نوفمبر. لا يتضمن ملف Compose الإنتاجي المثبّت للإصدار v0.2.0
**خدمة ClickHouse أو تعيينات بيئة التحليلات أو ملف التعريف `analytics-tools`**.
ضبط `ANALYTICS_MODE` في `.env` وحده لا يؤثر فيه. جهّز ClickHouse وصورة متوافقة
مراجعة ومرّر إعدادات التحليلات إلى API والعامل. يتضمن التشغيل السريع من المصدر
وCoolify الخدمة وملف تعريف الترحيل. احتفظ بملف الإصدار المثبّت واستخدم ملف تجاوز
مستقلاً للتعيينات المخصّصة.

## اختيار الوضع

| الوضع | متى تستخدمه؟ |
| --- | --- |
| `disabled` | الإبقاء على التحليلات العلائقية، دون إدخال بيانات إلى ClickHouse أو ترقية مخططه عند البدء. |
| `dual_write` | الكتابة إلى المخزنين أثناء التحقق والملء التاريخي. تستخدم اللوحات القديمة Postgres، ولا تتاح لوحة التحليلات الجديدة. |
| `shadow_read` | مقارنة القراءات القديمة مع ClickHouse. تقرأ لوحة التحليلات الجديدة من ClickHouse. |
| `clickhouse` | بعد مطابقة النتائج، اعتماد ClickHouse وإيقاف الكتابة العلائقية للتحليلات. |

انسخ المخزنين قبل التدرج. من مستودع مصدر مثبت الاعتماديات، صدّر
`POSTGRES_URL` و`ANALYTICS_HASH_SALT` ومتغيّرات اتصال ClickHouse للقواعد
المقصودة. لا تحمّل السكربتات ملف `.env` الجذري بنفسها. أدخل معرّف المشروع
من `/app/projects/<projectId>` في رابط لوحة التحكم:

```bash
read -r -p 'Project ID from the site dashboard URL: ' PROJECT_ID
test -n "$PROJECT_ID"
pnpm analytics:backfill -- --project="$PROJECT_ID"
pnpm analytics:reconcile -- --project="$PROJECT_ID"
```

ينسخ الملء الأحداث العلائقية المتبقية ولا يعيد إنشاء الموافقة التاريخية أو نص
البحث الخام. تطابق المقارنة معرّفات الأحداث مع ClickHouse، ولا تثبت كل أبعاد
التقارير أو أحداث ما بعد الانتقال. راقب فترة كاملة واحتفظ بالتاريخ العلائقي
خلال التراجع. العودة إلى `dual_write` لا تعيد أحداث Postgres المفقودة أثناء
وضع ClickHouse وحده.

## ترقيات المخطط والحالة

عند تفعيل التحليلات، يشغّل العامل ترقيات المخطط في الخلفية إذا كانت
`CLICKHOUSE_MIGRATE_ON_BOOT=true`، وهي القيمة الافتراضية. ينشئ قاعدة البيانات عند غيابها،
ويطبق الترقيات المعلقة ومدد الاحتفاظ الحالية. تبدأ إعادة المحاولة بعد ثانية وتصل إلى 60 ثانية كحد أقصى.
لا تؤخر هذه العملية بدء الخدمات الأساسية. يجب أن يستخدم جميع العمال وأداة الترقية قاعدة Postgres نفسها؛
فقفل استشاري مرتبط بمعاملة PostgreSQL يمنع تزامن ترقيات قاعدة ClickHouse بالاسم نفسه.
عند انشغال القفل، ينتظر العامل للمحاولة التالية دون تنفيذ أوامر المخطط.
مدة المعاملة القصوى ساعة؛ افحص العمليات العالقة قبل بلوغها ولا تبدأ ترقية يدوية متزامنة.

إذا استخدمت هوية مخصصة للترقية، عطّل الترقية عند البدء وشغّل:

```bash
# Source quickstart only; use the Coolify deployment job for its Compose file.
docker compose --profile analytics-tools run --rm analytics-migrate
# Or from a source checkout with POSTGRES_URL and ClickHouse writer credentials:
pnpm --filter @nibleaf/clickhouse migrate
```

تنتظر الأداة القفل حتى عشر دقائق وتعيد المحاولة كل خمس ثوان، ثم تفشل إذا ظل
مشغولاً. افحص العملية المالكة قبل إعادة التشغيل.
تحتوي استجابة `/health` للخادم والعامل على حقل مستقل:

```json
{"analytics":{"configured":true,"latencyMs":4,"status":"ok"}}
```

تعني `disabled` أن التحليلات معطلة، و`migrating` أن العملية الحالية ترقي المخطط،
و`schema_outdated` أن ترقية واحدة على الأقل لم تسجل بعد، بما في ذلك قاعدة غير مهيأة.
تعني `unavailable` فشل الاتصال أو بيانات الاعتماد أو فحص المخطط، و`ok` تسجيل كل الترقيات الموجودة في الشفرة.
يفحص الخادم القاعدة مستقلاً، وقد يعرض `schema_outdated` أثناء عمل العامل.
تحتفظ كل عملية بنتيجة فحص المخطط عشر ثوان، بما في ذلك حالات الفشل. تظهر حالة الترقية المحلية فوراً ويمسح اكتمالها الذاكرة المؤقتة. مهلة الفحص 750 ملّي ثانية، لتبقى الاستجابة ضمن مهلة فحص الحاوية عند الانقطاع. تعتمد جاهزية الخدمات الأساسية ورمز HTTP على خدماتها الأساسية فقط.

## بيانات الاعتماد والخصوصية

ولّد `ANALYTICS_HASH_SALT` مستقلاً بالأمر `openssl rand -hex 32`. احتفظ بالقيم والمفاتيح الحالية؛
فتغيير الملح يفصل هويات الزيارات التاريخية. عند غياب الملح مع تفعيل تحليلات ClickHouse،
**تُسقط الأحداث** ولا تستخدم قيمة بديلة؛ ويظل موقع التوثيق سليماً.
أعد السر الحالي قبل تفعيل الإدخال. توليد ملح جديد مخصص للتثبيت الجديد، لا لاستبدال قيمة إنتاج مفقودة.

لا تنشأ معرّفات الجلسة والمستخدم المجهول ولا تقبل إلا مع الموافقة `granted` أو `not_required`.
لذلك تحسب الزيارات التي يمكن تمييزها فقط. مع `denied` أو `unknown` تظل مشاهدات الصفحات
وأعداد البحث تحسب كتجميعات خالية من المحتوى، دون تجزئات للجلسة أو المستخدم المجهول؛
ويتجاهل الخادم المعرّفات حتى إن أرسلها العميل. تستخدم الجلسات المؤهلة تجزئة مملحة ومعرّفاً خاصاً بعلامة التبويب.
يتطلب النص الحساس أيضاً `granted` أو `not_required`.

يتطلب حفظ عبارات البحث موقعاً عاماً وتفعيل `analytics.storePublicSearchTerms=true` في المشروع.
لا تحفظ المواقع الخاصة العبارات الخام. توحّد العبارات بصيغة NFKC، وتحول الحروف إلى الصغيرة،
وتزيل المسافات الزائدة. تحجب عناوين البريد والروابط وتسلسلات الأرقام من ست خانات فأكثر قبل التجزئة والحفظ.
لا يظهر النص إلا إذا بحثت عنه **زيارتان مختلفتان على الأقل**؛ وتدخل بقية العبارات في إجماليات العبارات المخفية.
للنص الحساس مدة احتفاظ قصيرة مستقلة. لا تتضمن أحداث التحليلات نصوص المستندات أو المطالبات أو الإجابات.

ينشئ Compose هوية كاتب أولية، ولا ينشئ قارئاً منفصلاً. أنشئ الأدوار وأسندها إلى مستخدمين مستقلين.
تغطي الصلاحيات على مستوى القاعدة الجداول الجديدة وقراءة سجلات الحذف دون نسيانها:

```sql
CREATE ROLE IF NOT EXISTS nibleaf_analytics_reader;
GRANT SELECT ON nibleaf_analytics.* TO nibleaf_analytics_reader;

CREATE ROLE IF NOT EXISTS nibleaf_analytics_writer;
GRANT INSERT ON nibleaf_analytics.* TO nibleaf_analytics_writer;
GRANT SELECT ON nibleaf_analytics.analytics_deletion_tombstones TO nibleaf_analytics_writer;
GRANT SELECT ON nibleaf_analytics.usage_deletion_tombstones TO nibleaf_analytics_writer;

CREATE ROLE IF NOT EXISTS nibleaf_analytics_erasure;
GRANT ALTER DELETE ON nibleaf_analytics.* TO nibleaf_analytics_erasure;
```

يشمل القارئ `analytics_deletion_tombstones` وإصدارات المخطط وجدول العبارات الحساسة اللازم للعبارات المؤهلة.
صلاحيات SQL تشمل القاعدة، بينما تفرض استعلامات Nibleaf نطاق المستأجر والمشروع.
اضبط `CLICKHOUSE_READER_USERNAME` و`CLICKHOUSE_READER_PASSWORD` بما يطابق المستخدم.
يحتاج الكاتب أثناء التشغيل إلى INSERT وSELECT على سجلات الحذف؛ وتحتاج أداة المحو أيضاً إلى
SELECT للتحقق من الحذف ودور المحو أعلاه، الذي يغطي **كل جدول للمشروع**.
أسند دوري القارئ والمحو إلى هوية العامل إذا نفذ قراءة التجميعات وحذف المشاريع.
لا تمنح قارئ لوحة التحليلات صلاحية المحو، واحفظ كلمات المرور في أسرار النشر.

تحتاج الترقية بصورة منفصلة إلى CREATE وALTER وقراءة وكتابة إصدارات المخطط، بما فيها إنشاء القاعدة عند غيابها.
مع الترقية عند البدء، امنح هوية الكاتب الخاصة بالعامل هذه الحقوق.
إذا منعت تعديل المخطط أثناء التشغيل، اضبط `CLICKHOUSE_MIGRATE_ON_BOOT=false` وشغّل الأداة
بهوية ترقية مخصصة. دور INSERT وحده لا يكفي لترقية المخطط.

يحذف حذف المشروع بياناته الخام والحساسة والمجمعة مع حاجز يمنع إعادة إدخالها.
تحقق من انتهاء عمليات التعديل في ClickHouse قبل إغلاق طلب المحو.
قد تعيد نسخة قديمة بيانات سبق محوها؛ أعد تطبيق عمليات الحذف قبل ربط البيانات المستعادة بالتطبيق.

## الاحتفاظ ومساحة القرص

| المتغير | الأيام الافتراضية | النطاق |
| --- | --- | --- |
| `CLICKHOUSE_RAW_RETENTION_DAYS` | 180 | 7–730 |
| `CLICKHOUSE_CRAWLER_RETENTION_DAYS` | 90 | 7–730 |
| `CLICKHOUSE_ROLLUP_RETENTION_DAYS` | 730 | 30–3650 |
| `CLICKHOUSE_SENSITIVE_RETENTION_DAYS` | 30 | 1–90 |
| `AI_CONVERSATION_RETENTION_DAYS` | 90 | 1–365 |

تعيد كل ترقية تطبيق TTL مع `materialize_ttl_after_modify=0`؛ تسري التغييرات عند الدمج اللاحق دون
إعادة كتابة فورية. الحذف غير متزامن، وتقصير المدة يزيل السجل الأقدم نهائياً.
يحدد Compose ذاكرة الحاوية بـ 1.5 GiB، وميزانية الخادم بـ 1 GiB، وذاكرة العلامات بـ 128 MiB،
مع تدوير سجلات التحذير وتعطيل الكتابات الجديدة إلى جداول سجلات النظام الكثيفة.
تظل الجداول القديمة تشغل مساحة وتتطلب مراجعة المشغّل. هذه حدود بداية وليست ضمان سعة.
راقب المساحة الحرة وعمر المهام الفاشلة والأجزاء والدمج والتعديلات. لا تحذف ملفات مجلد بيانات ClickHouse يدوياً.
راجع [النسخ الاحتياطي](/ar/self-hosting/backups-upgrades) و[استكشاف الأخطاء](/ar/self-hosting/troubleshooting).
لا يرى التقاط طلبات الزواحف عند خادم الأصل الطلبات التي تجيب عنها بالكامل ذاكرة CDN أو الحافة أمام Nibleaf.
لذلك تصف أعداد الزواحف الطلبات التي تصل إلى Nibleaf، لا جميع طلبات الحافة.
قارن سجلات CDN منفصلة عند تقييم التغطية، ولا تعتبر غياب طلبات الأصل دليلاً على غياب الزواحف.

يُبلغ خادم التطبيق الـ API عن زيارات الزواحف للصفحات المنشورة وملفات Markdown و`llms.txt` وخرائط الموقع وملفات robots باستخدام `INTERNAL_API_SECRET`.
اضبط القيمة العشوائية نفسها (`openssl rand -hex 32`) على خدمتي التطبيق وواجهة API.
بدونها تُحتسب فقط الزواحف التي تطلب الـ API مباشرة، ويسجّل التطبيق تحذيراً مرة واحدة عند بدء التشغيل.
## نص المحادثات والاستخدام

يخزّن المصدر الحالي جولات الذكاء الاصطناعي والتقييمات والاستخدام اليومي حسب
النموذج. يحتاج حفظ النص إلى إعداد الموقع وموافقة الزائر الملائمة ومفتاح
`AI_CONVERSATION_ENCRYPTION_KEY` نفسه، أو بديله المشتق من مفتاح التكاملات،
على API والعامل. الطابور مشفّر، لكن أعمدة النص المنقّح في ClickHouse مقروءة
لمن يملك صلاحية القراءة. قيّد الوصول وطبّق سياسة تشفير التخزين لديك. يمكن
تسجيل حقائق الجولات الخالية من المحتوى دون حفظ النص. راجع
[خصوصية المحادثة وميزانياتها](/ar/self-hosting/search-ai) للشروط الدقيقة.

صحة المخطط ليست اختبار استقبال أحداث. تحقق من زيارة وهمية بموافقة وبحث وطلب
زاحف وجولة ذكاء اصطناعي في اللوحة. تظهر الأرقام المجهولة كغير متاحة أو جزئية،
ولا تثبت انعدام الزيارات. تُصنّف هوية الزاحف من وكيل المستخدم دون التحقق من
نطاقات IP الخاصة بالمزوّد. لا تثبت اللقطات المجمّعة سعة المواقع الكبيرة؛ قِس
نطاقات تقاريرك واختبر الاستعادة على إصدار ClickHouse نفسه الذي تنشره.
