إذا كان فريقك يحتفظ بالتوثيق في GitHub، فيمكنك ربط مستودع ليتمكن الأعضاء من
التحرير في Nibleaf أو في Git. يرسل Nibleaf تعديلات المتصفح إلى GitHub في طلب سحب
في حالة مسودة للمراجعة، ويعيد تغييرات المستودع إلى Nibleaf، ويتوقف ليسألك عندما
يتغير الملف نفسه في الجانبين.

لنسخ ملفات Markdown من مستودع عام مرة واحدة دون تحرير ثنائي الاتجاه، استخدم
**استيراد مستودع عام بدلاً من ذلك** في الشاشة نفسها، أو راجع
[انقل توثيقك إلى Nibleaf](/ar/product/migration).

## قبل أن تبدأ

- يجب أن تكون مالك الموقع أو مشرفًا، فإعدادات Git لا تظهر للمحررين.
- تحتاج إلى مستودع GitHub وإلى صلاحية إنشاء رمز وصول له.
- في نسخة مستضافة ذاتيًا، يجب أن يضبط المشغّل أولًا أسرار التشفير وعامل المعالجة
  الخاصة بـ Git؛ راجع [تهيئة عملية نشر لبيئة الإنتاج](/ar/self-hosting/configuration).
- تدرّب على مستودع تجريبي قبل ربط مستودعك الرئيسي.

## أنشئ رمز وصول في GitHub

رمز الوصول كلمة مرور تتيح لـ Nibleaf العمل على مستودع واحد. في GitHub، أنشئ
**رمز وصول شخصيًا دقيق الصلاحيات** (fine-grained personal access token) مقصورًا على
المستودع الذي تريد ربطه، وبهذه الصلاحيات فقط:

- **Metadata:** قراءة
- **Contents:** قراءة وكتابة
- **Pull requests:** قراءة وكتابة

لا يحتاج Nibleaf إلى أي صلاحية أخرى. يشفّر الرمز، ولا يعرضه مرة أخرى، ولا يكتبه في
السجلات أبدًا.

## اربط المستودع

1. افتح **الإعدادات ← Git**، وتحت **سير عمل Git ثنائي الاتجاه** اختر **الاتصال
   بـ GitHub**.
2. **التفويض:** الصق الرمز في **رمز دقيق الصلاحيات**، واختر **تفويض GitHub**.
3. **المستودع:** اختر المستودع ثم:
   - **الفرع الأساسي** الذي تأتي منه وثائقك، وهو عادةً `main`؛
   - **فرع Nibleaf المخصص**، وهو فرع منفصل مثل `nibleaf/docs` يكتب فيه Nibleaf
     تغييراته؛
   - **مسار المستندات**، أي المجلد الذي يضم وثائقك (`content` افتراضيًا).
4. **المراجعة:** تحقّق من الحساب والمصدر والوجهة، ثم اختر **الاتصال بـ GitHub**.

لا ينسخ الربط أي شيء بعد، فالاستيراد وإرسال التغييرات خطوتان منفصلتان.

## اجلب تغييرات المستودع إلى Nibleaf

افتح **الاستيراد والمزامنة** واختر **مزامنة أحدث التغييرات**. يقرأ Nibleaf الفرع
الأساسي، ويقارنه بآخر نسخة اتفق عليها الجانبان، ثم يحدّث صفحاتك. وتبقى التغييرات
المستوردة مسودات حتى تنشر.

للمزامنة تلقائيًا بعد كل دفع إلى المستودع، أضف webhook في GitHub. افتح **إعدادات
الاتصال** في Nibleaf لنسخ عنوان الاستقبال والسر. ثم افتح في GitHub إعدادات
المستودع **Settings ← Webhooks ← Add webhook**، والصق القيمتين، واضبط نوع المحتوى
على `application/json`، واشترك في حدثَي **Pushes** و**Pull requests**.

## أرسل تعديلات Nibleaf إلى GitHub

1. افتح **إنشاء طلب سحب أو تحديثه**.
2. راجع الملفات المتغيّرة، واملأ **رسالة الالتزام** و**اسم المؤلف** و**بريد
   المؤلف** و**عنوان طلب السحب**.
3. اختر زر الالتزام، مثل **إنشاء الالتزام وتحديث مسودة طلب السحب**.

يلتزم Nibleaf بالتغييرات في الفرع المخصّص، وينشئ طلب سحب واحدًا في حالة مسودة أو
يحدّثه، ولا يفرض الدفع أبدًا. وإذا تغيّر الفرع في GitHub خلال ذلك، يتوقف Nibleaf
لتزامن أولًا.

يحصل كل طلب سحب على معاينة خاصة به، وهي نسخة خاصة غير مُدرجة من الوثائق لا
تفهرسها محركات البحث. يمكنك متابعتها في **طلبات السحب والمعاينات**، وعند إغلاق طلب
السحب تتوقف معاينته.

## سوِّ التعارضات

عندما يتغيّر ملف في Nibleaf وفي Git معًا، يضع Nibleaf عليه علامة **تعارض** ولا يغيّر
شيئًا حتى تقرر. في **تسوية التعارضات** ترى ثلاث نسخ لكل ملف: **الأساس** الذي بدأ
منه الجانبان، ونسخة Nibleaf، ونسخة Git. اختر لكل ملف **استخدام Nibleaf** أو
**استخدام Git** أو **استخدام المخصص** لكتابة نسختك الخاصة، أو **حذف الملف**.

عندما يحصل كل ملف على قرار، يتابع Nibleaf العمل. وإذا تغيّر الملف في جانب واحد فقط،
يحتفظ Nibleaf بذلك التغيير تلقائيًا.

## كيف تُرتَّب الملفات في المستودع

يستخدم Nibleaf هذا الترتيب داخل مسار المستندات:

```text
content/
  guides/authentication.mdx        default language
  ar/guides/authentication.mdx     other languages, by language code
  versions/v1/guides/...           other documentation versions
```

تصبح المجلدات مجموعات في التنقّل، ويمثّل ملف `index.mdx` الصفحة الرئيسية للمجلد.
وتبقى أسماء الملفات العربية مقروءة. يُنشئ Nibleaf ملف `docs.json` ومجلد `.nibleaf/`
بنفسه ويعيد كتابتهما في كل مزامنة، فلا تعدّلهما يدويًا.

## استكشاف الأخطاء وإصلاحها

- **تعرض اللوحة فشل التفويض:** انتهت صلاحية الرمز أو تنقصه صلاحية. أنشئ رمزًا جديدًا
  بالصلاحيات المذكورة أعلاه واربط مجددًا.
- **تغيّر الفرع البعيد:** اختر **مزامنة أحدث التغييرات**، وسوِّ أي تعارضات، ثم أرسل
  تغييراتك مرة أخرى.
- **تبدو المزامنة أو طلب السحب عالقين:** راجع **الحالة والنشاط**. وفي نسخة مستضافة
  ذاتيًا، اطلب من المشغّل التأكد من عمل عامل معالجة Git؛ راجع
  [استكشاف الأخطاء وإصلاحها](/ar/self-hosting/troubleshooting).
- **ضاع سر الـ webhook:** دوّره في **إعدادات الاتصال**، وحدّثه في GitHub فورًا، وأعد
  إرسال الأحداث الفائتة من GitHub.

لإيقاف المزامنة، افتح **إعدادات الاتصال** واختر **قطع الاتصال**. يحذف ذلك الرمز
المحفوظ وسجل المزامنة، لكنه يُبقي صفحاتك ومستودعك كما هما.
