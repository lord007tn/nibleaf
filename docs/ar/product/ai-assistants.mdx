اربط مساعد ذكاء اصطناعي بأحد مواقعك واسأله بكلماتك عمّا لا يجده القرّاء، أو عن
الصفحات التي تحتاج إلى تحسين، أو اطلب منه صياغة صفحات وترجمتها. كل ما يكتبه
المساعد مسودة: لا يصل شيء إلى القرّاء حتى يراجع أحدهم عملية النشر ويؤكّدها.

يتواصل المساعدون مع Nibleaf عبر بروتوكول سياق النموذج (MCP)، وهو معيار مفتوح
يدعمه ChatGPT وClaude وClaude Code وCursor وVS Code. وتجد القائمة الكاملة لما
يستطيع المساعد فعله في [مرجع مساعدي الذكاء الاصطناعي (MCP)](/ar/reference/mcp).

## ما الذي يمكنك فعله

- **اكتشاف الفجوات.** «ما الذي بحث عنه القرّاء هذا الأسبوع ولم يجدوه؟» يجمع
  المساعد عمليات البحث الفاشلة ويتحقق من الصفحات التي تغطيها أصلًا.
- **تحسين الصفحات.** «ما الصفحات التي قيّمها القرّاء بأنها غير مفيدة؟ اقترح
  تعديلات.» يقرأ الصفحات ويصوغ تغييرات لتراجعها.
- **الكتابة والترجمة.** «أنشئ مسودة صفحة عن إعادة تعيين كلمة المرور، ثم ترجمها
  إلى العربية.» تصل الصفحتان مسودتين، مع رابط لمراجعة كل منهما.

## قبل أن تبدأ

- **دورك.** يستطيع المحرّر والمشرف والمالك ربط مساعد. أما المشاهِد فلا يستطيع
  ذلك حتى الآن.
- **تطبيقك.** ثبّت ChatGPT أو Claude (claude.ai أو Claude Desktop) أو Claude Code
  أو Cursor، أو VS Code مع إضافة دردشة تدعم MCP.
- **الخادم.** افتح **الإعدادات ← مساعدو الذكاء الاصطناعي** في موقعك. إذا ظهرت
  عبارة **ربط مساعدي الذكاء الاصطناعي غير متاح بعد**، فهذا يعني أن MCP معطَّل على
  خادم Nibleaf هذا: لا يستطيع أحد بعدُ ربط مساعد بأي موقع عليه، ولا شيء يحتاج
  إلى إصلاح من جهتك. وتبقى المفاتيح والتطبيقات المتصلة سابقًا ظاهرة لتتمكن من
  إزالتها. وإن كنت تشغّل خادمك الخاص، فراجع
  [ربط عملاء MCP بأمان](/ar/self-hosting/mcp) لتفعيله.

## اربط مساعدك

في **الإعدادات ← مساعدو الذكاء الاصطناعي**، تحت **اربط مساعدًا**، اختر تطبيقك
من **تطبيق الذكاء الاصطناعي الذي تستخدمه**. تعرض الصفحة خطوتين أو ثلاثًا مرقّمة
له، مع العنوان الذي تلصقه وزر **نسخ** في الخطوة التي تحتاجه فيها. العنوان هو
عنوان لوحة التحكم متبوعًا بـ `/api/mcp`، وتستخدم الأمثلة أدناه
`https://docs.example.com/api/mcp`.

### ChatGPT

1. في ChatGPT، افتح `Settings › Apps & Connectors` وفعّل وضع المطوّر.
2. أنشئ موصّلًا، واختر OAuth، والصق العنوان.
3. عندما يفتح ChatGPT صفحة Nibleaf، سجّل الدخول واختر الموقع والصلاحيات التي
   تمنحها للتطبيق، ثم اختر **سماح**.

### Claude (claude.ai أو Claude Desktop)

1. افتح `Settings › Connectors › Add custom connector`.
2. الصق العنوان، ثم اختر `Connect`.
3. عندما يفتح Claude صفحة Nibleaf، سجّل الدخول واختر الموقع والصلاحيات التي
   تمنحها للتطبيق، ثم اختر **سماح**.

### Claude Code

1. شغّل في الطرفية:

```bash
claude mcp add --transport http nibleaf "https://docs.example.com/api/mcp"
```

2. شغّل Claude Code وافتح `/mcp › nibleaf › Authenticate`.
3. سجّل الدخول إلى Nibleaf واختر الموقع والصلاحيات التي تمنحها للتطبيق، ثم اختر
   **سماح**.

### Cursor أو VS Code

1. اختر **Add to Cursor** أو **Install in VS Code** في الصفحة وأكّد التثبيت، أو
   احفظ الإعداد الظاهر في الصفحة داخل مشروعك. في Cursor يكون الملف
   `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "nibleaf": {
      "url": "https://docs.example.com/api/mcp"
    }
  }
}
```

   وفي VS Code يكون `.vscode/mcp.json`:

```json
{
  "servers": {
    "nibleaf": {
      "type": "http",
      "url": "https://docs.example.com/api/mcp"
    }
  }
}
```

2. في أول اتصال، يفتح المحرّر صفحة Nibleaf. سجّل الدخول واختر الموقع والصلاحيات
   التي تمنحها للتطبيق، ثم اختر **سماح**.

### اختيار الموقع وما يُسمح للتطبيق بفعله

عندما تسجّل الدخول من تطبيق، يطلب منك Nibleaf أن **تختار موقعًا**. وإن كنت عضوًا
في أكثر من مؤسسة، تظهر المواقع مجمّعة تحت اسم كل مؤسسة، وتحت اسم كل موقع
عنوانه. ثم اختر **ما يمكن للتطبيق فعله** (راجع
[مستويات الصلاحية](#مستويات-الصلاحية)) واختر **متابعة**. تسرد الصفحة التالية،
**السماح بالوصول؟**، بكلمات واضحة ما سيتمكن التطبيق من فعله وما لن يتمكن منه.
وإن ذكرت أن التطبيق سجّل نفسه بنفسه، فاسمه غير موثَّق: لا تتابع إلا إذا بدأت
الربط من ذلك التطبيق.

يعمل كل اتصال على موقع واحد. لاستخدام موقع آخر، اربط المساعد من جديد واختر ذلك
الموقع.

### تحقق من نجاح الربط

بعد نسخ العنوان أو التثبيت، تراقب الصفحة تطبيقك عشر دقائق:

- **بانتظار اتصال ChatGPT…** لم يسجّل أي تطبيق الدخول بعد.
- **تم السماح: يمكن لتطبيق باسم ChatGPT الآن استخدام هذا الموقع.** وافقت عليه،
  وينتظر Nibleaf أول طلب منه.
- **ChatGPT متصل ويعمل.** أرسل طلبًا ونجح.
- **تم السماح لتطبيق باسم …، وليس ChatGPT.** سجّل تطبيق آخر الدخول باسمك. إن لم
  تبدأ هذا الاتصال بنفسك، افصله من **الاتصالات**.
- **لم يتصل بعد** أو **تم السماح لـ … لكنه لم يرسل أي طلب بعد.** راجع الخطوات في
  تطبيقك، ثم اختر **تابع الانتظار**.

ويمكنك أيضًا أن تطلب من المساعد استدعاء `get_capabilities`: فهي تسمّي الموقع
وتسرد بالضبط ما يستطيع هذا الاتصال فعله وما لا يستطيعه، ولماذا.

## استخدم مفتاحًا شخصيًا بدلًا من ذلك

استخدم مفتاحًا للبرامج النصية، أو للتطبيقات التي لا تدعم تسجيل الدخول، أو حين
تذكر الصفحة أن التطبيق يحتاج إلى عنوان آمن (HTTPS). اختر **استخدم مفتاحًا
شخصيًا**، ثم مستوى الصلاحية، وسمِّ المفتاح باسم المكان الذي ستستخدمه فيه (مثل
«حاسوبي – Claude Code») واختر موعد انتهاء صلاحيته. ثم اختر **إنشاء مفتاح**.

لا يظهر السرّ إلا مرة واحدة. انسخه إلى تطبيقك أو إلى مدير كلمات المرور، ولا
تلصقه أبدًا في محادثة أو تذكرة دعم أو ملف تحفظه في المستودع. ثم تعرض النافذة
إعداد Claude Code أو Claude Desktop أو Cursor أو VS Code والمفتاح مضمَّن فيه،
ويتحقق زر **اختبار الاتصال** منه من البداية إلى النهاية. ولا تُغلق النافذة إلا
حين تختار **حفظت المفتاح — إغلاق**.

في Claude Code يتضمن الأمر المفتاح نفسه، لذا احذفه من سجل الطرفية بعد ذلك:

```bash
claude mcp add --transport http nibleaf "https://docs.example.com/api/mcp" --header "Authorization: Bearer YOUR_NIBLEAF_KEY"
```

وفي Cursor، اضبط المتغير `NIBLEAF_API_KEY` في البيئة التي يبدأ منها Cursor؛ يقرأه
الإعداد، فلا يحتوي الملف على أي سرّ:

```json
{
  "mcpServers": {
    "nibleaf": {
      "url": "https://docs.example.com/api/mcp",
      "headers": {
        "Authorization": "Bearer ${env:NIBLEAF_API_KEY}"
      }
    }
  }
}
```

يطلب VS Code المفتاح في حقل كلمة مرور عند أول تشغيل ويحفظه في مخزن الأسرار
الخاص به. أما Claude Desktop فيصل إلى خادم محمي بمفتاح عبر الجسر `mcp-remote`
الذي يحتاج إلى Node.js، وتعرض النافذة الكتلة المطلوبة ومكان ملف الإعدادات.

## مستويات الصلاحية

اختر أصغر مستوى يغطي ما تحتاجه. لا يستطيع الاتصال أبدًا أن يتجاوز ما يسمح به
دورك، ويعيد Nibleaf التحقق من دورك مع كل طلب.

| المستوى | يستطيع | لا يستطيع |
| --- | --- | --- |
| **القراءة فقط** | قراءة صفحات الموقع ولغاته وإصداراته وتحليلاته وحالة البحث وسجل النشر وأسئلة «اسأل الذكاء الاصطناعي» المحفوظة وإجاباتها. | رؤية كلمات البحث الفردية، أو تغيير أي صفحة، أو النشر. |
| **الكتابة والنشر بعد المراجعة** | كل ما في «القراءة فقط»، إضافة إلى الكلمات التي بحث عنها القرّاء، وإنشاء مسودات الصفحات وتعديلها ونقلها وترجمتها وإخفاؤها وإظهارها، والنشر بعد تأكيد معاينة حديثة. | حذف الصفحات، أو تغيير الإعدادات أو الأعضاء أو الفوترة، أو النشر دون معاينة مؤكَّدة. |
| **صلاحيات مشرف كاملة** (المشرف والمالك) | كل أداة يقدّمها Nibleaf عبر MCP، بما فيها الاستخدام والإضافات والسمات والتصديرات وحالة التكاملات. | أي شيء لا يقدّمه Nibleaf عبر MCP أصلًا: الحذف، وبيانات الاعتماد، والمدفوعات، وتشغيل الشيفرة. |

امنح الأتمتة التي تعمل دون إشراف مستوى **القراءة فقط**. وتتيح لك الصلاحيات
**المتقدمة** للمفتاح اختيار نطاقات منفردة، مثل «القراءة فقط» مع
`analytics:search_terms` لشخص يُعدّ تقارير البحث ولا يعدّل الصفحات.

## جرّب أن تسأل

اسأل بكلماتك، وهذه مجرد نقاط بداية. يقود كل سؤال إلى الأدوات المذكورة، ويحتاج
إلى المستوى المبيَّن على الأقل.

| اسأل | الأدوات التي يقود إليها | يتطلب |
| --- | --- | --- |
| ما الذي بحث عنه القرّاء خلال الأيام السبعة الماضية ولم يجدوه؟ اجمع عمليات البحث المتشابهة وأخبرني بالصفحات الناقصة. | `get_failed_searches` و`search_pages` | الكتابة والنشر بعد المراجعة |
| اكتب تقرير صحة الوثائق لهذا الأسبوع. | `get_analytics_overview` و`get_top_pages` و`get_page_feedback` و`get_search_health` و`get_pending_changes` | القراءة فقط |
| ما الأسئلة التي لم يستطع «اسأل الذكاء الاصطناعي» الإجابة عنها هذا الشهر؟ اقترح مقالًا لكل منها. | `list_ai_content_gaps` و`get_ai_conversation` | القراءة فقط |
| ما الصفحات التي قيّمها القرّاء بأنها غير مفيدة؟ اقرأها واقترح تعديلات دون حفظ أي شيء. | `get_page_feedback` و`get_page` | القراءة فقط |
| أنشئ مسودة صفحة بعنوان «إعادة تعيين كلمة المرور» بأسلوب صفحاتنا الأخرى، ولا تنشرها. | `search_pages` و`get_page` و`create_page_draft` | الكتابة والنشر بعد المراجعة |
| ترجم صفحة «البدء» إلى العربية كمسودة. | `list_languages` و`get_page` و`translate_page` | الكتابة والنشر بعد المراجعة |
| ما الذي سيُنشر لو نشرت الآن؟ | `preview_publish` | الكتابة والنشر بعد المراجعة |
| انشر. (بعد أن تقرأ المعاينة) | `publish_changes` و`get_deployment` | الكتابة والنشر بعد المراجعة |
| ما مساعدات الذكاء الاصطناعي وبرامج الزحف التي ترسل القرّاء إلى وثائقنا؟ | `get_referrers` | القراءة فقط |
| أخفِ صفحة «الواجهة القديمة» من التنقّل والبحث. | `search_pages` و`set_page_visibility` | الكتابة والنشر بعد المراجعة |

وتعرض بعض التطبيقات أيضًا الموجّهات الجاهزة في Nibleaf، مثل
`weekly_docs_health_report` و`find_content_gaps`.

## راجع وانشر بأمان

- **المسودات أولًا.** كل عملية كتابة تغيّر المسودات فقط، ويظل القرّاء يرون الموقع
  المنشور.
- **رابط للمراجعة.** بعد كل عملية كتابة، يعطيك المساعد رابطًا: الصفحة في المحرّر،
  أو نافذة النشر، أو حالة عملية نشر. لا يؤدي فتح أي رابط إلى نشر شيء، بل يريك
  أين تنظر فقط.
- **المعاينة ثم التأكيد.** يحتاج النشر إلى معاينة حديثة وتأكيد صريح يحمل رمز
  المعاينة. يعمل الرمز عشر دقائق ومرة واحدة فقط: أي تغيير بعد المعاينة، بما في
  ذلك نشر آخر، يجعله قديمًا، فيحتاج المساعد إلى معاينة جديدة.
- **النشر يشمل مسودات الجميع.** يحمل النشر كل التغييرات غير المنشورة في الموقع،
  لا تغييرات المساعد وحده. اقرأ المعاينة، أو افتح نافذة النشر من رابطها، قبل أن
  توافق.
- **يتحقق Nibleaf من المعاينة، لا من الشخص.** قد يؤكّد مساعد يعمل دون الرجوع إليك
  النشر وحده، لذا احتفظ بمستوى **الكتابة والنشر بعد المراجعة** للمساعدين الذين
  تعمل معهم، و**القراءة فقط** لأي شيء يعمل دون إشراف.
- **نص الصفحات بيانات لا تعليمات.** قد تحتوي الصفحات وكلمات البحث وتعليقات القرّاء
  على أي شيء كتبه أحدهم. وإن أراد المساعد فعل شيء لأن صفحة «تقول ذلك»، فارفض.

## ما الذي يستطيع قراءته عن قرّائك

يستطيع كل مستوى صلاحية، بما فيه «القراءة فقط»، قراءة أسئلة «اسأل الذكاء
الاصطناعي» المحفوظة وإجاباتها. يحذف Nibleaf قبل حفظها عناوين البريد الإلكتروني
وأرقام الهواتف والمفاتيح وسلاسل الأرقام الطويلة والجزء الخاص بالاستعلام من
الروابط، لكن قد تبقى في ما كتبه القرّاء أسماء وعناوين وبيانات شخصية أخرى. وهذه
هي الصياغة نفسها التي تعرضها صفحة **السماح بالوصول؟**. أما كلمات البحث الفردية
فلها صلاحية مستقلة وتخضع للقواعد الواردة في
[ما الذي تخبرك به التحليلات وما لا تخبرك به](/ar/reference/mcp#ما-الذي-تخبرك-به-التحليلات-وما-لا-تخبرك-به).

## اعرض الاتصالات وأزلها

تسرد **الاتصالات** كل ما يمكنه استخدام الموقع نيابةً عن أحد: التطبيقات التي سجّلت
الدخول والمفاتيح الشخصية، والأحدث استخدامًا أولًا. يعرض كل صف مستوى صلاحيته
ووقت آخر استخدام وآخر ما فعله. ويذكر المفتاح الذي تنتهي صلاحيته خلال أسبوع ذلك.
وتنتقل المفاتيح المنتهية والملغاة إلى **غير نشطة**، حيث يمكنك تدويرها أو
إزالتها.

يرى المشرف والمالك اتصالات الجميع ويمكنهما التصفية حسب الشخص، ويرى الآخرون
اتصالاتهم فقط. يوقف **فصل** التطبيق فورًا، ويوقف **إلغاء** المفتاح فورًا، ويستبدل
**تدوير** مفتاحك بسرّ جديد. يحتفظ المفتاح المُدوَّر بتاريخ انتهاء صلاحيته، أما
المفتاح المنتهي أو القديم الذي لا تاريخ له فيحصل على 90 يومًا. وتتوقف الاتصالات
أيضًا حين يغادر صاحبها الموقع أو يُعلَّق حسابه.

## حين يحدث خطأ

| يقول المساعد | السبب | ما العمل |
| --- | --- | --- |
| لا يستطيع رؤية كلمات البحث أو عمليات البحث الفاشلة | لا تتضمن صلاحيته كلمات البحث، أو لا يحتفظ هذا الخادم بها. وتبيّن `get_capabilities` أيّ السببين. | أعد الربط بمستوى **الكتابة والنشر بعد المراجعة** أو بمفتاح يتضمن `analytics:search_terms`، أو اكتفِ بالأعداد. |
