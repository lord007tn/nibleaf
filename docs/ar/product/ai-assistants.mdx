يستطيع مساعد الذكاء الاصطناعي المتصل بـ Nibleaf أن يجيب عن سؤال مثل «ما الذي
يبحث عنه القرّاء ولا يجدونه؟»، وأن يقرأ الصفحات المعنية، ويصوغ إصلاحًا، ويجهّزه
للنشر، وكل ذلك داخل مشروع واحد. يعتمد المساعد على بروتوكول Model Context
Protocol (MCP) وعلى مفتاح شخصي تنشئه بنفسك. لا يستطيع المساعد أبدًا أن يتجاوز ما
تستطيع أنت فعله في لوحة التحكم، ولا يصل شيء مما يكتبه إلى القرّاء قبل أن يراجع
شخص التغييرات ويؤكد النشر.

## قبل أن تبدأ

- يجب أن يكون MCP مفعّلًا في نسخة Nibleaf التي تستخدمها. في الاستضافة الذاتية
  يفعّله المشغّل؛ راجع [ربط عملاء MCP بأمان](/ar/self-hosting/mcp). وإذا كان
  معطّلًا فسيُبلغك زر **اختبار الاتصال** وكل عميل بأن MCP معطّل.
- يجب أن تكون عضوًا في مساحة العمل التي يتبعها المشروع؛ إذ يستطيع أي عضو إنشاء
  مفتاح لنفسه.
- ثبّت المساعد الذي ستستخدمه: Claude Code أو Claude Desktop أو Cursor أو VS Code
  مع إضافة محادثة تدعم MCP.

## اختر ما يُسمح للمساعد بفعله

يبدأ كل مفتاح من إعداد مسبق. اختر أصغر إعداد يغطي المهمة.

| الإعداد المسبق | من يمكنه اختياره | يستطيع المساعد | لا يستطيع المساعد |
| --- | --- | --- | --- |
| **قراءة فقط** (Read only) | أي عضو | قراءة بيانات المشروع والصفحات ومحتواها واللغات والإصدارات والتحليلات المجمّعة وإعدادات البحث وسلامته وعمليات النشر. | رؤية عبارات البحث الفردية، أو تغيير أي صفحة، أو النشر. |
| **كاتب الدعم** (Support writer) | أي عضو | كل ما في «قراءة فقط»، إضافة إلى قراءة عبارات البحث الأكثر تكرارًا والفاشلة، وإنشاء مسودات الصفحات وتعديلها، ونقل الصفحات وترجمتها وإخفائها وإظهارها، والنشر بعد تأكيدك. | حذف الصفحات، أو تغيير الإعدادات أو الأعضاء أو الفوترة أو السمات أو الإضافات أو التكاملات، أو النشر من دون معاينة حديثة وتأكيد منك. |
| **مسؤول كامل** (Full admin) | المسؤولون والمالكون | كل عمليات القراءة والكتابة التي يوفرها خادم MCP، ومنها قراءة الاستخدام والاستحقاقات والإضافات والسمات والتصدير وحالة التكاملات. | أي شيء لا يوفره الخادم أصلًا: حذف المحتوى، أو بيانات الاعتماد، أو المدفوعات، أو تشغيل الشيفرة. |

تنطبق قاعدتان فوق كل إعداد مسبق:

- **المفتاح يعمل باسمك.** يعيد Nibleaf في كل طلب التحقق من دورك الحالي وحالة
  حسابك. فإذا أزالك مسؤول من مساحة العمل أو علّق حسابك، تتوقف مفاتيحك عند طلبها
  التالي. أما المفاتيح القديمة التي لا مالك مسجّلًا لها فلا تستطيع إلا القراءة.
- **عبارات البحث بيانات اختيارية.** لا توجد عبارات البحث الأكثر تكرارًا أو
  الفاشلة إلا إذا فعّل أحدهم **الإعدادات ← التحليلات ← تخزين عبارات البحث
  العامة** للمشروع. ومن دون ذلك لا تعيد أدوات عبارات البحث أي عبارات.

## أنشئ مفتاحك الشخصي

1. افتح المشروع، ثم **الإعدادات ← مساعدو الذكاء الاصطناعي (MCP)**.
2. اختر **إنشاء مفتاح**، وأعطه اسمًا يدل على مكان استخدامه (مثل «الحاسوب المحمول
   – Claude Code»)، واختر إعدادًا مسبقًا، ومدة صلاحية بين 7 أيام و365 يومًا.
3. انسخ السر؛ فهو لا يظهر إلا مرة واحدة. ألصقه مباشرة في المساعد أو في مدير
   كلمات المرور، ولا تضعه أبدًا في محادثة أو تذكرة أو لقطة شاشة أو ملف تحفظه في
   مستودع.

اختر **اختبار الاتصال** لتتأكد من أن المفتاح وعنوان الخادم وتفعيل MCP في النسخة
تعمل جميعًا قبل ضبط أي عميل. تعرض قائمة المفاتيح آخر استخدام لكل مفتاح وآخر
نشاط له. يرى الأعضاء مفاتيحهم فقط، أما المسؤولون فيرون مفاتيح الجميع ويمكنهم
إلغاؤها.

## اربط المساعد

تعرض لوحة الإعداد المجاورة لمفتاحك الجديد أمرًا أو رابطًا أو إعدادًا جاهزًا لكل
عميل، وعنوان الخادم مملوء مسبقًا. تستخدم الأمثلة التالية العنوان
`https://api.docs.example.com/api/mcp` ومفتاحًا محفوظًا في متغيّر البيئة
`NIBLEAF_MCP_API_KEY`؛ فاستبدل بهما القيم الظاهرة في لوحة الإعداد لديك.

### Claude Code

1. انسخ الأمر من لوحة الإعداد.
2. شغّله في الطرفية:

```bash
claude mcp add --transport http nibleaf https://api.docs.example.com/api/mcp \
  --header "Authorization: Bearer $NIBLEAF_MCP_API_KEY"
```

3. شغّل Claude Code ونفّذ `/mcp`؛ يجب أن يظهر `nibleaf` متصلًا.

أبقِ النطاق المحلي الافتراضي، ولا تضف `--scope project`، لأن ذلك يكتب المفتاح في
ملف `.mcp.json` الذي يُحفظ عادة في المستودع.

### Claude Desktop

يصل Claude Desktop إلى خادم بعيد يتطلب مفتاحًا عبر الجسر `mcp-remote`، وهو يحتاج
إلى Node.js.

1. افتح **Settings ← Developer ← Edit Config**.
2. ألصق الكتلة الظاهرة في لوحة الإعداد، واستبدل بالعنصر النائب مفتاحك:

```json
{
  "mcpServers": {
    "nibleaf": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://api.docs.example.com/api/mcp",
        "--header",
        "Authorization:${NIBLEAF_AUTH_HEADER}"
      ],
      "env": {
        "NIBLEAF_AUTH_HEADER": "Bearer YOUR_NIBLEAF_KEY"
      }
    }
  }
}
```

3. أغلق Claude Desktop تمامًا وأعد فتحه، ثم تحقق من ظهور أدوات Nibleaf في قائمة
   الأدوات.

تُمرَّر قيمة الترويسة عبر `env` ومن دون مسافة بعد النقطتين، حتى يستلمها الجسر
سليمة على كل أنظمة التشغيل.

### Cursor

1. اختر **Add to Cursor** في لوحة الإعداد، فيفتح Cursor ويعرض الخادم الذي سيثبّته.
2. أكّد التثبيت. وإذا احتوى الإدخال المثبّت على عنصر نائب بدل مفتاحك، فافتح
   `~/.cursor/mcp.json` واقرأ المفتاح من متغيّر بيئة:

```json
{
  "mcpServers": {
    "nibleaf": {
      "url": "https://api.docs.example.com/api/mcp",
      "headers": {
        "Authorization": "Bearer ${env:NIBLEAF_MCP_API_KEY}"
      }
    }
  }
}
```

3. تحقق من أن الخادم `nibleaf` يظهر بحالة خضراء ويعرض أدواته.

### VS Code

1. اختر **Install in VS Code** في لوحة الإعداد وأكّد التثبيت.
2. عندما يشغّل VS Code الخادم، يطلب المفتاح في حقل كلمة مرور ويحفظه في مخزن
   الأسرار لديه. يبدو الإعداد المثبّت هكذا:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "nibleaf-key",
      "description": "Nibleaf MCP API key",
      "password": true
    }
  ],
  "servers": {
    "nibleaf": {
      "type": "http",
      "url": "https://api.docs.example.com/api/mcp",
      "headers": {
        "Authorization": "Bearer ${input:nibleaf-key}"
      }
    }
  }
}
```

3. افتح عرض المحادثة في وضع الوكيل (agent mode) وتحقق من ظهور أدوات Nibleaf.

### ChatGPT

تسجّل موصلات ChatGPT الدخول إلى خوادم MCP البعيدة حاليًا عبر OAuth ولا تقبل
مفتاح API ملصقًا، لذلك لا يمكن ربط ChatGPT بـ Nibleaf بعد. وينطبق الأمر نفسه على
شاشات الموصلات في claude.ai. يعتمد دعمهما على تسجيل الدخول عبر OAuth لـ MCP، وهو
مخطط له؛ راجع قسم «OAuth لعملاء MCP» في [ربط عملاء MCP بأمان](/ar/self-hosting/mcp).

### تحقق من الاتصال من داخل المساعد

اطلب من المساعد «استدعِ `get_capabilities`». يذكر الرد المشروع المرتبط بالمفتاح
ويعرض الأدوات التي يستطيع مفتاحك استخدامها بالضبط. إذا غابت أداة تتوقعها، فإن
إعدادك المسبق أو دورك الحالي لا يشملها.

## مثال: سدّ فجوة في المحتوى من البداية إلى النهاية

يستخدم هذا المثال مفتاحًا بإعداد **كاتب الدعم**.

1. **اعرف ما يفتقده القرّاء.** اطلب: «باستخدام `get_failed_searches` لآخر 7
   أيام، ما عمليات البحث التي لم تجد نتائج؟ اجمع العبارات المتشابهة معًا». ويمكنك
   أيضًا البدء من الموجّه `find_content_gaps`.
2. **ابحث قبل أن تكتب.** اطلب من المساعد تشغيل `search_pages` لكل مجموعة، حتى
   يوسّع صفحة موجودة بدل إنشاء صفحة مكررة.
3. **صِغ الإصلاح.** اطلب منه تحديث أقرب صفحة عبر `update_page`، أو إنشاء صفحة
   جديدة عبر `create_page_draft`. يُحفظ التغيير مسودةً في نسخة العمل، ويظل
   القرّاء يرون الموقع المنشور.
4. **راجع المسودة.** افتح الصفحة في محرّر Nibleaf واقرأها كما يقرؤها القارئ،
   وعدّلها بنفسك إن لزم. وإذا عدّلتها بعد أن قرأها المساعد، تفشل كتابته التالية
   بتعارض في المراجعة بدل أن تستبدل عملك؛ فاطلب منه قراءة الصفحة من جديد أولًا.
5. **عاين النشر.** اطلب `preview_publish`. تعرض المعاينة كل تغيير غير منشور في
   المشروع، بما فيه مسودات الآخرين، لأن النشر يشمل المشروع كله. وإذا احتوت
   القائمة على ما ليس جاهزًا، فتوقف ونسّق مع صاحبه.
6. **انشر بعد تأكيدك.** عندما تطمئن، اطلب من المساعد النشر. فيستدعي
   `publish_changes` مع `confirm: true` والرمز الناتج عن المعاينة. وإذا تغيّر أي
   شيء بعد المعاينة، يفقد الرمز صلاحيته وتعيد المعاينة.
7. **تحقق من الموقع المنشور.** اطلب منه متابعة `get_deployment` حتى تصبح عملية
   النشر جاهزة، ثم افتح الصفحة من دون تسجيل الدخول وابحث عن إحدى العبارات التي
   فشل البحث عنها. اتبع [النشر والتحقق](/ar/product/publishing) لإجراء فحص القارئ
   كاملًا.

يسجّل Nibleaf كل استدعاء في سجل التدقيق مع المفتاح والشخص الذي عمل باسمه، من دون
تخزين محتوى الصفحة.

## ما الذي يحمي توثيقك

- **المسودة أولًا.** لا تغيّر عمليات الكتابة إلا نسخة العمل، ولا يصبح شيء منشورًا
  قبل نجاح النشر.
- **معاينة ثم مراجعة ثم تأكيد.** يحتاج النشر إلى معاينة، وقرار بشري، وتأكيد صريح
  يحمل رمز المعاينة.
- **لا استبدال صامت.** تذكر كل عملية كتابة المراجعة التي بُنيت عليها.
- **لا تكرار عند إعادة المحاولة.** يستطيع المساعد إرفاق معرّف طلب من جهة العميل،
  فلا يُطبَّق الطلب المعاد مرتين.
- **لا حذف.** لا توجد أداة حذف، وإخفاء الصفحة قابل للتراجع.
- **المحتوى غير الموثوق يبقى بيانات.** قد يحتوي نص الصفحات وعبارات البحث
  وملاحظات القرّاء على أي شيء كتبه زائر أو مؤلف. يوجّه Nibleaf المساعد إلى عدم
  اتباع أي تعليمات ترد داخلها أبدًا. فإذا اقترح المساعد إجراءً لأن صفحة أو عبارة
  بحث «تطلب ذلك»، فارفضه.
- **حدود وسجل تدقيق.** يخضع عدد الطلبات وعمليات الكتابة والنشر لتحديد معدل
  الطلبات، ويُسجَّل كل استدعاء من دون تخزين محتواك.

## استكشاف الأخطاء وإصلاحها

| ما يظهر لك | السبب | ما العمل |
| --- | --- | --- |
| «MCP is disabled for this Nibleaf instance» (`mcp:disabled`) | MCP معطّل في النسخة. | اطلب من المشغّل تفعيله. |
| «The API key is invalid, expired, or revoked» (`auth:invalid_api_key`) | انتهت صلاحية المفتاح، أو أُلغي، أو لُصق ناقصًا، أو أُزيل مالكه أو عُلّق حسابه. | أنشئ مفتاحًا جديدًا وحدّث العميل. |
| `auth:insufficient_scope`، أو غياب أداة | الإعداد المسبق أو دورك الحالي لا يسمح بها. | أنشئ مفتاحًا بإعداد مسبق أوسع، أو اسأل مسؤولًا عن دورك. |
| تعارض في المراجعة عند الكتابة | غيّر أحدهم الصفحة بعد أن قرأها المساعد. | اطلب من المساعد قراءة الصفحة من جديد وإعادة تطبيق تغييره فوقها. |
| رفض النشر لأن المعاينة قديمة | تغيّر شيء بعد `preview_publish`. | أعد المعاينة، وراجع القائمة الجديدة، ثم أكّد. |
| طلبات كثيرة جدًا (`http:rate_limited`) | بلغتَ حد الطلبات أو الكتابة أو النشر. | انتظر المدة الواردة في `Retry-After`، وأبطئ المساعد أو اجمع العمل في دفعات. |

عندما تطلب المساعدة، شارك معرّف الطلب الوارد في رسالة الخطأ، ولا تشارك أبدًا
المفتاح أو ترويسة `Authorization` أو محتوى الصفحات.

## فهرس الأدوات والموجّهات

لا يرى المساعد إلا العناصر التي يسمح بها مفتاحه. يبيّن عمود **الإعداد المسبق**
أصغر إعداد يتضمن كل عنصر.

| الاسم | النوع | النطاق | الإعداد المسبق | الغرض |
| --- | --- | --- | --- | --- |
| `get_capabilities` | أداة | `mcp:connect` | قراءة فقط | عرض المشروع المرتبط والأدوات والموارد والموجّهات المتاحة لهذا المفتاح. |
| `get_project` | أداة | `projects:read` | قراءة فقط | قراءة بيانات المشروع. |
| `list_pages` | أداة | `pages:read` | قراءة فقط | سرد الصفحات وموقعها في شجرة الصفحات. |
| `get_page` | أداة | `pages:read` | قراءة فقط | قراءة صفحة واحدة مع محتواها ومراجعتها الحالية. |
| `search_pages` | أداة | `pages:read` | قراءة فقط | العثور على الصفحات الموجودة بالعنوان أو المحتوى قبل الكتابة. |
| `list_languages` | أداة | `languages:read` | قراءة فقط | سرد لغات المشروع. |
| `list_versions` | أداة | `versions:read` | قراءة فقط | سرد إصدارات التوثيق. |
| `get_analytics_overview` | أداة | `analytics:read` | قراءة فقط | الزيارات والتفاعل وأعداد عمليات البحث مجمّعةً، من دون العبارات. |
| `get_top_pages` | أداة | `analytics:read` | قراءة فقط | الصفحات الأكثر مشاهدة خلال مدة محددة. |
| `get_page_feedback` | أداة | `analytics:read` | قراءة فقط | تقييمات القرّاء المفيدة وغير المفيدة لكل صفحة. |
| `get_referrers` | أداة | `analytics:read` | قراءة فقط | مصادر وصول القرّاء مصنّفةً، ومنها مساعدو الذكاء الاصطناعي. |
| `get_search_configuration` | أداة | `search:read` | قراءة فقط | إعدادات البحث في المشروع. |
| `get_search_index_diagnostics` | أداة | `search:read` | قراءة فقط | حالة الفهرس ومراجعته من دون محتوى. |
| `get_search_health` | أداة | `search:read` | قراءة فقط | هل البحث سليم ومحدَّث. |
| `list_deployments` | أداة | `deployments:read` | قراءة فقط | عمليات النشر الأخيرة. |
| `get_deployment` | أداة | `deployments:read` | قراءة فقط | حالة عملية نشر واحدة، للتحقق من نجاح النشر. |
| `get_pending_changes` | أداة | `deployments:read` | قراءة فقط | التغييرات غير المنشورة التي تنتظر في نسخة العمل. |
| `get_top_searches` | أداة | `analytics:search_terms` | كاتب الدعم | عبارات البحث الأكثر تكرارًا لدى القرّاء. |
| `get_failed_searches` | أداة | `analytics:search_terms` | كاتب الدعم | عمليات البحث التي لم تُرجع نتائج. |
| `create_page_draft` | أداة | `pages:write` | كاتب الدعم | إنشاء صفحة جديدة بوصفها مسودة. |
