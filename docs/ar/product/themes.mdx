يتضمن Nibleaf ثلاث سمات أصلية ببنى صفحات مختلفة. تستخدم **Harbor** بنية المراجع
التقليدية: تنقلًا ثابتًا للمكتبة وعمود قراءة وفهرسًا للصفحة على الجانب الآخر.
وتنقل **Manuscript** المكتبة إلى رف أفقي للفصول فوق عمود قراءة مركّز. أما
**Signal** فتقدم مساحة عمل تقنية كثيفة بشريط مكتبة ضيق ولوحة مقال واسعة وفهرس
أوامر أعلى الصفحة. الأسماء والرموز والتخطيطات والأصول أصلية ومملوكة لـ
Nibleaf. ألهمت منتجات التوثيق العامة أنماط المنتج العامة، مثل معرض الإعدادات
المسبقة والتخصيص الدلالي والمعاينة قبل النشر، لكن Nibleaf لا ينسخ شيفرتها أو
أصولها أو أسماءها أو مظهرها التجاري المملوك.

تحتفظ المشاريع المنشأة قبل مخطط السمة v1 بألوانها وتخطيطها الحاليين إلى أن
يختار المالك سمة أو يخصصها أو يستوردها. يمنع وضع التوافق هذا تغييرًا مرئيًا غير
مطلوب في موقع منشور قائم.

## بنية المصيّر

يحل التطبيق بيانات السمة المحفوظة مرة واحدة ثم يمررها إلى مزود سمات التوثيق.
يختار المزود قالب React مسجلًا بحسب قيمة `layout.shell` البنيوية، بينما يظل
الإعداد المسبق مالكًا للبيانات الوصفية والرموز الدلالية. يركب كل قالب بصورة
مستقلة القارئ المنشور ومعاينة المشروع ومعاينة الإعدادات وتخطيط المقال وفهرس
الصفحة. لذلك يغير تبديل الهيكل بنية المعلومات المصيّرة فعلًا، وليس ترتيب CSS أو
الألوان فقط. ويستخدم عامل النشر قيمة الهيكل ذات الإصدار نفسها في التصديرات
الثابتة، فتشترك المصيرات في عقد تخطيط مستقر من دون مشاركة شيفرة خاصة بالمتصفح.

تظل البنى المتجاوبة مختلفة. تطوي Harbor مكتبتها الثابتة وفهرس الصفحة إلى تنقل
مضغوط يحيط بمقال مرجعي. وتحافظ Manuscript على الترويسة ورف الفصول الأفقي القابل
للتمرير وسطح القراءة الشبيه بالورق قبل التحول إلى عمود طويل واحد. أما Signal
فتبقي شريط أوامر مضغوطًا وشريط مكتبة ولوحة واسعة للشيفرة وفهرس أوامر، ثم تحول
شريط المكتبة إلى تنقل أفقي قابل للتمرير في الهاتف. وتحافظ خصائص CSS المنطقية
على هذه العلاقات في اتجاهي LTR وRTL.

## حدود الإلهام والملكية

راجعت عملية التصميم أدلة تخطيطات التوثيق وكتالوجات المكونات الحالية في
[Fumadocs](https://www.fumadocs.dev/docs/ui/layouts/docs) و
[Mintlify](https://mintlify.com/docs/themes) و
[ReadMe](https://docs.readme.com/main/docs/built-in-components)، بما فيها
[إرشادات ReadMe لاكتشاف الذكاء الاصطناعي](https://docs.readme.com/main/docs/ai-discoverability). أثّرت هذه المصادر في
توقعات عامة، مثل الإعدادات المسبقة والإعدادات الدلالية والتنقل القابل للطي وفهارس
الصفحات وخيارات التخطيط ومسار
العمل الذي يبدأ بالمعاينة. تستخدم Harbor وManuscript وSignal أسماء وقيم رموز
ومعالجات مكونات وشيفرة وأصولًا أصلية يملكها Nibleaf. أسماء المنتجات في هذه
الفقرة ملك لأصحابها ولا تعني وجود ارتباط بهم.

## تخصيص المسودة بأمان

افتح **محرر الموقع ← السمات**. اختر سمة بداية، ثم عدّل المظهر وهيكل الصفحة والكثافة وعرض
المحتوى ونصف القطر والرأس والشريط الجانبي والتنقل والشيفرة والتنبيهات والبطاقات
والتبويبات والجداول والألوان الدلالية للوضعين الفاتح والداكن. تستطيع المعاينة
التبديل مستقلًا بين العربية والإنجليزية وبين الوضعين الفاتح والداكن.

يتحقق المحرر من تباين النص واللون البارز قبل الحفظ. يعيد **التراجع** التعديل
السابق، ويستعيد **إلغاء التغييرات** آخر إعدادات مشروع محفوظة، ويعيد **إعادة
الضبط** الإعداد المسبق المختار. تؤثر هذه الإجراءات في المسودة وحدها. تظل عملية
النشر الحالية ذات الحالة `READY` ظاهرة للعامة حتى نشر المشروع من جديد. عاين
اتجاهي اللغة ووضعَي الألوان قبل النشر.

تستهلك مكونات السمة متغيرات دلالية ثابتة، مثل `--theme-canvas` و
`--theme-foreground` و`--theme-surface` و`--theme-accent` و`--theme-focus`
و`--theme-code`. يستخدم البحث الواجهة نفسها، ويمكن لأسطح الذكاء الاصطناعي
المستقبلية اعتمادها عبر `data-theme-surface="ai"` من دون الارتباط بالبنية
الداخلية لمصيّر الصفحة.

يعيد كتالوج السمات الموثق معرّفات ثابتة للسمات والمكونات وقدرات بنيوية ومفاتيح
رسائل Paraglide. تُعرض أسماء الإعدادات المسبقة وأوصافها ومبرراتها في لوحة التحكم
عبر Paraglide، لا عبر بيانات وصفية إنجليزية ثابتة. وتبقى بيانات السمة المخصصة
المصدّرة هوية للمستودع وليست عقدًا لنص واجهة مترجم. تحصل المحولات على هذا
الكتالوج المطهّر عبر إجراء مشترك، ولا تحصل على مسارات الملفات أو ملفات البيان
أو اللقطات أو ملفات المستودع الثنائية أو محتوى صفحات العميل.

## الإعدادات الافتراضية للبحث واكتشاف الذكاء الاصطناعي

تستخدم كل سمة قواعد النشر نفسها مع بنية عرض خاصة بها. تصدر الصفحات المنشورة
الرابط الأساسي وتعليمة robots وبيانات Open Graph وTwitter وعلاقات اللغات مع
`x-default` وبيانات JSON-LD من نوع `TechArticle` ومسار التنقل. وتحتوي الأرشيفات
الثابتة كذلك على `robots.txt` و`sitemap.xml` و`llms.txt` و`llms-full.txt` في
الجذر، إلى جانب نسخ لكل لغة وإصدار مفعّلين. تُستبعد الصفحات المخفية والخاصة
والممنوعة من الفهرسة وصفحات اللغات المعطلة والصفحات ذات الرابط الأساسي الخارجي
من ملفات الاكتشاف. تبقى روابط الأرشيف نسبية إلى الجذر لأن اللقطة القابلة للنقل
لا تعرف مضيف النشر النهائي الموثوق، ويحلها مضيف الخدمة من دون اختلاق نطاق.

## تصدير قالب وفحصه

اختر **تصدير** لتنزيل ملف JSON قانوني بترميز UTF-8. تُرتب المخرجات ترتيبًا
حتميًا كي تظل المراجعات ومقارنات دورة التصدير والاستيراد مفيدة. لا يحتوي الملف
إلا الإعدادات التي تملكها السمة: بياناتها الوصفية ورموزها، إلى جانب مراجع
العلامة والخطوط المدعومة. ولا يتضمن المحتوى أو بيانات الاعتماد أو الأعضاء أو
التحليلات أو شيفرة قابلة للتنفيذ.

```json
{
  "kind": "nibleaf-theme",
  "version": 1,
  "metadata": {
    "name": "Product docs theme",
    "description": "Shared theme for product documentation",
    "author": "Documentation team"
  },
  "config": {
    "theme": {
      "preset": "harbor"
    },
    "styling": {
      "theme": "system"
    }
  }
}
```

لا يقبل مخطط v1 إلا حقولًا معروفة ومحدودة. الحد الأقصى للقالب 128 KiB، و12
مستوى من التداخل، و600 قيمة يجري المرور عليها. يجب أن تكون مراجع الأصول روابط
HTTPS أو مسارات تبدأ من الجذر من دون انتقال بين الأدلة أو بيانات اعتماد أو
مضيفات نسبية للبروتوكول. تفشل الحقول المجهولة وCSS أو JavaScript القابلان
للتنفيذ ومفاتيح تلويث النماذج الأولية وإصدارات المخطط المستقبلية برسائل قابلة
للتنفيذ. يرحّل المستورد صيغة v0 القديمة الموثقة إلى v1 قبل التحقق.

## معاينة الاستيراد وتطبيقه

ألصق JSON أو اختر ملفًا، وحدد **دمج** أو **استبدال**، ثم عاين التغييرات الدقيقة.
يحدّث الدمج الحقول الواردة في القالب ويحتفظ بإعدادات السمة الأخرى. ويعيد
الاستبدال ضبط الإعدادات التي تملكها السمة أولًا. لا يغيّر أي وضع تحسين محركات
البحث أو التنقل أو المحتوى أو التحليلات أو الوصول أو إعدادات المشروع الأخرى.

طلب الاستيراد الأول معاينة جافة. لا تطبق التغييرات إلا بعد مراجعة القائمة
وتحذيرات إمكانية الوصول. يحدّث التطبيق مسودة المشروع، ولا ينشرها سرًا. انشر
صراحة، وتحقق من عملية النشر الناتجة، واحتفظ بالقالب السابق المصدّر كنقطة رجوع.

تحمي عملية مقارنة وتبديل تفاؤلية تغييرات المسودة المتزامنة. يعيد تطبيق السمة
حساب كل الأقسام التي تملكها السمة من أحدث إعداد للمشروع داخل معاملة واحدة، مع
الحفاظ على إعدادات المهام الأخرى. ويعيد التزاحم المتكرر خطأ تعارض بدل الكتابة
فوق تغييرات محرر إعدادات آخر.

## التراجع عن سمة

صدّر القالب الحالي قبل تغيير مهم للسمة. للتراجع، استورد ذلك الملف باستخدام
**استبدال**، وراجع الفرق، وطبقه على المسودة، ثم انشر عملية نشر جديدة. تظل عمليات
النشر السابقة غير القابلة للتغيير ونواتج التصدير المنشأة سابقًا من دون تغيير.
وإذا فشل التحقق من الاستيراد، فلا تُكتب أي إعدادات للمشروع.

للحصول على أرشيف كامل للمحتوى والموقع، استخدم [التصديرات المنشورة](/ar/product/exports).
قوالب السمات ملفات صغيرة لتبادل التصميم، وليست نسخًا احتياطية للمشروع.

## تشغيل مستودع Git وتعديله

يصدّر عقد المستودع v2 مشروع توثيق مألوفًا: تطبيق TanStack Start مع Vite
وTailwind CSS v4 يعتمد اصطلاحات المحتوى المعروفة من fumadocs وMintlify. يشغّله
الأمر `corepack pnpm install && corepack pnpm dev`، ويولّد `corepack pnpm build`
موقعًا ثابتًا مسبق التصيير لكل الصفحات القابلة للوصول (`.output/public`) يمكن
نشره على أي استضافة ثابتة. لا يتطلب المستودع اعتمادية `workspace:` ولا أسرارًا
ولا طلبات شبكة أثناء البناء.

- `docs.json` ملف بيان متوافق مع Mintlify (`name` و`colors`
  و`navigation.languages[].pages` و`navigation.versions[]` عندما يملك المشروع
  أكثر من إصدار) مع كتلة `x-nibleaf` تضم رموز السمة المحلولة واللغات مع
  اتجاهها والإصدارات ومسار المحتوى. يعيد Nibleaf توليده في كل مزامنة؛ لا تعدّله
  يدويًا.
- يحتوي `content/` صفحات MDX بالبيانات الوصفية نفسها التي تكتبها مزامنة Git
  (`title` و`description` و`icon` و`hidden` اختياريًا). تقع اللغة الافتراضية في
  جذر المحتوى، واللغات الأخرى في `content/<code>/`، والإصدارات غير الافتراضية
  في `content/versions/<slug>/`. المجلدات مجموعات تنقّل؛ وأي ملف لم يُدرج بعد في
  `docs.json` يُلحق بمجموعته كي يستمر الموقع في العمل إلى أن يلحق به Nibleaf.
- يضم `src/components/layout/` هياكل Harbor وManuscript وSignal مبنية بأدوات
  Tailwind ورموز `docs.json` (الوضعان الفاتح والداكن، وخصائص CSS المنطقية
  لاتجاه RTL). يربط `src/styles.css` الرموز بالأدوات، ويصيّر
  `src/components/mdx/` مكونات التأليف عبر قائمة السماح نفسها المستخدمة في
  المنصة، وتحفظ `messages/{en,ar}.json` نصوص الواجهة ثنائية اللغة. كل ما يقع
  تحت `src/` و`messages/` و`public/` وملفات الأدوات مملوك للعميل ولا يُستبدل بعد
  الدفع الأول.
- يحتفظ `.nibleaf/` ببيانات المصالحة فقط: `manifest.json` (إصدار المخطط 2
  والمشروع والقالب وتجزئتا `docs.json` وخريطة المحتوى) و`content-map.json`. لا
  توجد لقطة محتوى كاملة.

تفشل مستودعات المخطط v1 (`nibleaf.theme.json` مع `.nibleaf/snapshot.json`)
برسالة صريحة. احذف تلك الملفات المولّدة وادفع مجددًا من Nibleaf لإعادة توليد
تخطيط v2؛ ولا تُمسّ الملفات التي يملكها العميل.
