يسحب برنامج التثبيت الموجّه صورة v0.2.1 المثبّتة لمعمارية `linux/amd64`، دون
ترجمة Nibleaf على الخادم. جرّب التثبيت الأول على مضيف يمكن الاستغناء عنه.
لا يتضمن ملف Compose الإنتاجي Qdrant أو ClickHouse؛ يعمل البحث المنشور العادي
دونهما. تبقى الميزات الاختيارية، مثل مفاتيح ذكاء مساحة العمل ومحادثة Ask AI
وتسجيل دخول MCP عبر OAuth، معطّلة حتى تضبطها وفق أدلتها.

ينشئ هذا الدليل تثبيتاً جديداً. احتفظ بأسرار وبيانات أي تثبيت قائم واتبع
[النسخ والترقية](/ar/self-hosting/backups-upgrades)، أو
[الترقية من v0.1.2 إلى v0.2.1](/ar/self-hosting/upgrade-v0-2)، بدلاً منه.

## المتطلبات الأساسية

جهّز خادم Linux بمعمارية `amd64` (`x86_64`) مع Docker Engine وDocker Compose v2
و`curl` و`sed` وOpenSSL. تحتاج جلسة SSH تفاعلية وصلاحية استخدام Docker.
يدعم الإصدار المنشور `linux/amd64` فقط.

جهّز اسماً للوحة التحكم وآخر للتخزين يمكن للمتصفح الوصول إليه ووكيل TLS عكسياً.
لتسجيل الدخول برمز البريد، اضبط Postmark أو SMTP؛ البديل هو Google عند ضبط
بيانات اعتماده معاً. وفّر مساحة ووجهة خارج المضيف لنسخ القاعدة والتخزين.

```bash
uname -m
docker --version
docker compose version
curl --version
openssl version
```

توقّع `x86_64` من `uname -m`. توقف إذا كانت معمارية خادم Docker غير مدعومة أو
كانت أداة مطلوبة مفقودة.

## التثبيت الموجّه

ينزّل الأمر التالي برنامج التثبيت بإصدار محدد ويتحقق من بصمة SHA-256 الواردة
في `release/self-host.json` قبل تنفيذه. عند اختلاف البصمة يتوقف الغلاف؛ لا تتجاوز الفحص:

```bash
set -eu; d=$(mktemp -d); trap 'rm -rf "$d"' EXIT; curl -fsSLo "$d/nibleaf-install.sh" https://github.com/lord007tn/nibleaf/releases/download/v0.2.1/nibleaf-install.sh; actual=$(openssl dgst -sha256 "$d/nibleaf-install.sh"); actual=${actual##* }; [ "$actual" = "b653c9e51106ff0d6778ad65163ebbed08c57c5dbc7c2ac869a31e9c32778032" ] || { echo "Nibleaf installer checksum mismatch" >&2; exit 1; }; sh "$d/nibleaf-install.sh"
```

يسأل البرنامج عن العناوين العامة والبريد، وينشئ أسراراً جديدة، ويكتب `.env`
بصلاحيات 600، ويتحقق من ملف Compose ثم يبدأ الخدمات. أبقِ وسم الصورة v0.2.1
للتثبيت المثبّت. يرفض وجود تثبيت أو وحدات Compose سابقة؛ لا تحذفها لتجاوز
الفحص، بل استخدم دليل الترقية.

المجلد الافتراضي هو `$PWD/nibleaf`. بعد اكتمال التثبيت، ادخل إليه، أو إلى
المجلد الذي اخترته إن غيّرته:

```bash
cd nibleaf
```

يتضمن `docker-compose.yml` و`.env`، فيجدهما `docker compose` تلقائياً.
انتقل إلى التحقق أدناه.

## التثبيت اليدوي البديل

اختر هذا المسار لتحرير البيئة بنفسك. تحتاج Git لهذا المسار. استخدم وسم الإصدار
حتى لا يزوّدك فرع `main` المتغيّر بقالب مختلف:

```bash
git clone --branch v0.2.1 --depth 1 https://github.com/lord007tn/nibleaf.git
cd nibleaf
cp .env.production.example .env
chmod 600 .env
export COMPOSE_FILE=docker-compose.prod.yml
```

حرّر `.env` قبل التشغيل. اضبط `APP_URL` و`BETTER_AUTH_SECRET` و
`POSTGRES_PASSWORD` و`STORAGE_PUBLIC_ENDPOINT` و`STORAGE_ACCESS_KEY_ID` و
`STORAGE_SECRET_ACCESS_KEY`. اضبط `STORAGE_PUBLIC_URL` على رابط الحاوية أو
الأصول العام، وجهّز البريد، واضبط `INTERNAL_API_SECRET` مستقلاً لتمرير عنوان
العميل الموثوق. استبدل جميع النطاقات التوضيحية. يشرح
[دليل الإعداد](/ar/self-hosting/configuration) الفرق بين عناوين التخزين الداخلية
والعامة والإعدادات الاختيارية.

أنشئ أسراراً مستقلة على الخادم ولا تعِد استخدام أمثلة القيم:

```bash
openssl rand -hex 32
openssl rand -base64 24
```

اسحب الإصدار وابدأه. يضمن `COMPOSE_FILE` أعلاه استخدام ملف الإنتاج. تطبق خدمة
`migrate` ذات التشغيل الواحد ترحيلات Postgres قبل بدء API والعامل:

```bash
docker compose pull
docker compose up -d
```

## التحقق من التثبيت

نفّذ من مجلد النشر وفي الغلاف نفسه:

```bash
docker compose ps
docker compose logs migrate
docker compose logs --tail=100 server worker app
```

توقّع اكتمال `migrate` بنجاح وتحول الخدمات المستمرة إلى حالة سليمة. يظل العامل
غير سليم عند اشتراط البريد دون إعداد مزوّد. لا تثبت فحوص API والعامل وحدها
وصول الرسائل.

افتح `/sign-up` على `APP_URL` الذي ضبطته. أنشئ المالك الأول واستقبل رمز دخول
حقيقياً، أو استخدم Google المجهّز. ارفع صورة وانشر صفحتين، وافتحهما بعد تسجيل
الخروج وابحث عن الثانية وتحقق من رابط الصورة. وجّه اسم مضيف التخزين إلى منفذ
maxio رقم 9000؛ لا يُنشر افتراضياً إلا منفذ التطبيق 4310.

عند الفشل احتفظ بـ`.env` والوحدات، واقرأ الخطأ الأول واستخدم
[استكشاف الأخطاء](/ar/self-hosting/troubleshooting). لا تعِد تشغيل المثبّت لإصلاح
نشر قائم. قبل دعوة الكتّاب، أكمل [قائمة الإنتاج](/ar/self-hosting/production)
و[اختبار استعادة معزول](/ar/self-hosting/backups-upgrades).
