يسحب مسار الإنتاج الموصى به صورة `linux/amd64` مثبتة الإصدار من GHCR. ولا يجمع
المستودع الأحادي على الخادم. أكمل هذا الدليل التعليمي على مضيف مؤقت قبل نقل
المحتوى الحقيقي.

ينشر برنامج التثبيت الإصدار المثبت في بيان الاستضافة الذاتية المنشور. استخدم هذا
الدليل للناتج المثبت الذي ينزله، ولا تستبدل التزامًا من `main` في بيئة الإنتاج.

هذا الدليل مخصص للتثبيتات الجديدة. لترقية تثبيت قائم، لا تُعد تشغيل برنامج التثبيت.
اتبع [النسخ الاحتياطي والاستعادة والترقية](/ar/self-hosting/backups-upgrades)، أو
[دليل الترقية إلى v0.2.0](/ar/self-hosting/upgrade-v0-2) إذا كنت تشغّل v0.1.2.

## المتطلبات المسبقة

جهّز ما يلي:

- مضيف Linux ببنية `amd64` (`x86_64`) عليه Docker Engine وDocker Compose v2
  (`docker compose`)؛
- الأدوات `curl` و`sed` وOpenSSL؛
- اسم مضيف للوحة التحكم واسم مضيف منفصل للتخزين يمكن الوصول إليه من المتصفح؛
- وكيلاً عكسيًا يدعم TLS؛
- بريدًا إلكترونيًا صادرًا عبر Postmark أو SMTP. يستخدم تسجيل الدخول رموزًا عبر البريد
  الإلكتروني، لذا لا يمكن للمالك الأول تسجيل الدخول من دونه ما لم يكن تسجيل الدخول
  عبر Google مُعدًّا؛
- سعة منفصلة كافية للنسخ الاحتياطية من Postgres وتخزين الكائنات.

تحقق من الأدوات المطلوبة والبنية:

```bash
uname -m
docker --version
docker compose version
curl --version
openssl version
```

يجب أن يطبع `uname -m` القيمة `x86_64`. لا تعمل الصورة المنشورة على بنى أخرى.

## شغّل برنامج التثبيت الموجّه

لأقصر مسار، شغّل برنامج التثبيت التفاعلي الرسمي من طرفية SSH:

```bash
curl -fsSL https://nibleaf.com/install.sh | sh
```

إذا كانت سياسة الأمان لديك تتطلب الفحص قبل التنفيذ، فنزّل البرنامج النصي نفسه
وراجعه أولًا:

```bash
curl -fsSLo nibleaf-install.sh https://nibleaf.com/install.sh
less nibleaf-install.sh
sh nibleaf-install.sh
```

يتحقق برنامج التثبيت من الأدوات المحلية، ويطلب الأصول العامة، وينشئ أسرارًا
جديدة، ويكتب ملف `.env` بصلاحيات الوضع 600، وينزّل ملف Compose الخاص بالإنتاج،
ويسحب الصورة المثبتة الإصدار، ثم يشغّل المنظومة. مجلد التثبيت الافتراضي هو
`$PWD/nibleaf`. يحتوي هذا المجلد على `docker-compose.yml` و`.env` فقط؛ نفّذ أوامر
Compose اللاحقة منه واحذف `-f docker-compose.prod.yml`.

## ثبّت يدويًا

استخدم هذا المسار عندما تكون إدارة الإعدادات مسؤولة عن ملف البيئة:

```bash
git clone https://github.com/lord007tn/nibleaf.git
cd nibleaf
cp .env.production.example .env
```

عيّن كل قيمة مطلوبة في `.env`. أنشئ أسرارًا مستقلة؛ ولا تُعد استخدام قيم
الأمثلة أو التطوير أو قيم بيئة أخرى مطلقًا:

```bash
openssl rand -hex 32
openssl rand -base64 24
```

ثم اسحب الإصدار المثبت وشغّله:

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

تطبّق خدمة `migrate` ذات التشغيل الواحد عمليات ترحيل Prisma قبل بدء خدمات
التطبيق.

## تحقق من أول نتيجة

شغّل:

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs migrate
docker compose -f docker-compose.prod.yml logs --tail=100 server worker app
```

ينبغي أن تكون جميع الخدمات طويلة التشغيل سليمة، وأن تنتهي `migrate` بنجاح.
افتح `$APP_URL/sign-up`، وأنشئ المالك الأول، وارفع صورة واحدة، وانشر مشروعًا من
صفحتين. تحقق من عنوان URL للصورة ومن البحث بعد تسجيل الخروج.

إذا كانت إحدى الخدمات غير سليمة، فلا تُعد إنشاء المنظومة مرارًا. اقرأ أول خطأ
لهذه الخدمة واستخدم [استكشاف الأخطاء وإصلاحها](/ar/self-hosting/troubleshooting).
قبل دعوة الكتّاب، أكمل [إعدادات الإنتاج](/ar/self-hosting/configuration)
و[قائمة التحقق للإنتاج](/ar/self-hosting/production) ونفّذ عملية مجرّبة
لـ[النسخ الاحتياطي والاستعادة](/ar/self-hosting/backups-upgrades).
