يعرض خادم Nibleaf مرجعًا تفاعليًا مدعومًا بـOpenAPI على `/docs` في منفذ واجهة
API رقم 4311. في مكدّس التطوير، افتح `http://localhost:4311/docs`. وفي بيئة
الإنتاج، تبقى واجهة API داخلية عادةً، ويمرّر التطبيق طلبات المتصفح عبر `/api`
كي تظل ملفات تعريف ارتباط الجلسة من الطرف الأول.

## استخدام مواصفات الإصدار المطابق

مواصفات الخادم قيد التشغيل هي المصدر المرجعي لمسارات التوجيه والطرائق والمخططات ورموز
الاستجابة. لا تنشئ تكاملًا انطلاقًا من لقطة شاشة أو مواصفات أنشأها وسم صورة
مختلف.

لواجهة API تعمل بالفعل على الجهاز المحلي، نزّل المواصفات المقروءة آلياً دون
إتاحة منفذها للإنترنت:

```bash
curl -fsS http://127.0.0.1:4311/openapi.json -o nibleaf-openapi.json
```

سجّل معرّف النسخة العاملة من `/health`. يثبّت المصدر الحالي `info.version` في
OpenAPI على `0.1.1`؛ فلا تستخدمه لتحديد الإصدار المنشور. يغطي وكيل التطبيق
`/api`، ولا يغطي جذري خادم API وهما `/docs` و`/openapi.json`. استخدم نفق مشغّل
لهذه المسارات الداخلية.

## حدود المصادقة

تستخدم مسارات لوحة التحكم جلسة المتصفح المصادَق عليها وتفويض المؤسسة والمشروع.
ويشكّل وكيل `/api` من المصدر نفسه في التطبيق جزءًا من هذا التصميم. لا تنشر
المنفذ 4311 على الإنترنت لمجرد تسهيل تكامل داخلي.

لا تعرض مسارات الموقع العام إلا المحتوى المنشور الموجّه للقرّاء والبحث
والبيانات الوصفية ومسارات العمل العامة صراحةً. ولا تمنح صلاحيات لوحة التحكم.
تظل بيانات اعتماد المشغّل وعامل المعالجة منفصلة عن وصول القرّاء ومساحة العمل.

تمثل نقطة MCP المصادَق عليها عبر HTTP عقد تكامل منفصلًا وصريحًا. وهي معطلة
افتراضيًا، وتقبل مفاتيح API شخصية أو اتصالات OAuth مرتبطة بالمشروع وتحمل `mcp:connect` ونطاقات
دقيقة، وتعيد التحقق من الدور الحالي لمالك المفتاح في كل طلب، ولا تحول مسارات
لوحة التحكم غير الموثقة إلى API كتابة عامة مدعومة. تغطي محولات القراءة محتوى
وملخصات محدودة للبحث والاستخدام والاستحقاقات والإضافات والسمات والتكاملات
والتشغيل. ولا تكتب إلا مسودات الصفحات ونشرًا يسبقه معاينة وتأكيد؛ أما إعادة
الفهرسة وتصدير الاستخدام والحذف وبيانات اعتماد المزوّد وسائر عمليات التغيير
فتبقى غير متاحة. راجع [ربط عملاء MCP بأمان](/ar/self-hosting/mcp).

## التكامل الآمن

- استخدم مستند OpenAPI الذي تقدمه البيئة المستهدفة.
- اختبر في مساحة عمل غير إنتاجية وبأقل قدر من الصلاحيات.
- تعامل مع ملفات تعريف ارتباط الجلسة وقيم bearer ورموز الدعوة والأسرار الداخلية
  بوصفها بيانات اعتماد؛ ولا تدرجها مطلقًا في أمثلة التوثيق.
- تعامل مع استجابات الأخطاء وحدود المعدل الموثّقة بدلًا من إعادة محاولة كل فشل
  إلى أجل غير مسمى.
- أعد التحقق من المواصفات ومسارات العمل المتأثرة قبل الترقية.
- بالنسبة إلى MCP، دوّر المفاتيح المرتبطة بالمشروع بدل إعادة استخدام جلسة
  متصفح أو مفتاح قديم بنطاق حرف بدل.

لا يزال Nibleaf قبل الإصدار 1.0، لذلك لا تمثّل المسارات الداخلية غير الموثّقة
عقد توافق. اقترح احتياجات التكامل المستقر عبر بلاغ عام من دون تضمين تفاصيل
البيئة الخاصة.

## مراجع API المنشورة للعملاء

واجهة API لمنصة Nibleaf ومرجع API الخاص بمشروع توثيق هما منتجان مختلفان. لنشر
مرجع مشروع، افتح **الإعدادات ← مرجع API**، واختر تسمية التنقل ومساره، ثم استخدم
أحد المصادر المدعومة:

- ارفع أو الصق مستند JSON أو YAML واحدًا بحجم أقصاه 5 MB؛
- اجلب عنوان URL عامًا عبر HTTP(S) من دون بيانات اعتماد مضمّنة؛ أو
- اقرأ ملفًا ذا مسار نسبي إلى المستودع من مستودع GitHub أو GitLab عام ومتصل.

يتحقق Nibleaf من OpenAPI 3.x قبل الحفظ، ويحل ملفات `$ref` الخارجية العامة
ويجمعها داخل المستند المخزن. تعمل المراجع النسبية مع مصادر URL والمستودع، ويمكن
للمستند المرفوع أو الملصق استخدام روابط HTTP(S) عامة ومطلقة. يقتصر الحجم المجمع
على 5 م.ب. و20 ملفًا خارجيًا. وتكون كل عملية جلب محدودة بالوقت والحجم، وترفض
وجهات الشبكات الخاصة وبيانات الاعتماد وعمليات إعادة التوجيه غير الآمنة وإعادة
ربط DNS.

انشر بعد حفظ المواصفات أو تحديثها. يُثبّت المستند المتحقق منه في عملية النشر
غير القابلة للتغيير، لذلك تحتفظ عملية نشر أقدم أو التراجع إلى الإصدار السابق
بمراجعة المواصفات الخاصة بها.

يستخدم المرجع المنشور Scalar. تنتقل طلبات التجربة مباشرة من متصفح القارئ إلى
واجهة API الموصوفة؛ لا يمرّر Nibleaf الطلبات عبر وكيل، ولا يحقن بيانات اعتماد،
ولا يحتفظ بالمصادقة، ولا يسجّل أسرار الطلبات. يجب أن تسمح واجهة API بمصدر
التوثيق المنشور ضمن سياسة CORS لديها. اختبر طلبًا واحدًا غير ضار ببيانات اعتماد
مؤقتة، وامسحها قبل مشاركة المتصفح أو تسجيل دليل مرئي.

## نقاط القارئ في المصدر الحالي

هذه مسارات Hono تحت `/api/public/sites`. يحدد `:id` الموقع، وتظل مصادقة القارئ
ونطاق النشر مطبّقين. لا يقبل البحث والإجابات والمحادثة مؤسسة أو منح صفحات
اختيارية من العميل. مسارات المحادثة من ميزات المصدر الحالي؛ تحقق من الصورة المنشورة.

| الطريقة واللاحقة | الاستجابة والحدود |
| --- | --- |
| `GET /:id` | هيكل الموقع المنشور؛ `lang` و`version` اختياريان. |
| `GET /:id/page` | محتوى الصفحة؛ افتراضي `path` هو الجذر، مع `lang` و`version` اختياريين. |
| `GET /:id/markdown` | نص `text/markdown`؛ لا يتيح هذا الشكل العام محتوى خاصاً أو غير قابل للفهرسة. |
| `GET /:id/search` | نتائج؛ `q` حتى 200 حرف، و`limit` اختياري من 1 إلى 50، و`lang` و`version` و`sessionId` و`consentState`. |
| `POST /:id/answer` | إجابة كاملة متحقق منها؛ `q` من 2 إلى 500 حرف بعد التشذيب، و`lang` و`version` اختياريان. |
| `POST /:id/chat` | أحداث خادم AG-UI؛ معرّف UUID في `conversationId` و`question` من 2 إلى 500 حرف، وسجل محدود وسياق صفحة اختياريان. |
| `POST /:id/chat/events` | تفاعلات خالية من المحتوى؛ من 1 إلى 20 حدثاً للطلب، و60 طلباً لكل IP في الدقيقة. |
| `PUT /:id/chat/feedback` | تقييم قابل للتعديل؛ معرّفا UUID للمحادثة والجولة ورمز الإجابة الموقّع، و`up` أو `down` أو `null`، وتعليق اختياري حتى 1000 حرف. الحد 30 طلباً لكل IP في الدقيقة. |
| `POST /:id/events` | أحداث تحليلات عامة متحقق منها. |
| `GET /:id/openapi.json` | مستند API الخاص بالعميل والمنشور في الموقع. |
| `GET /:id/llms.txt`, `GET /:id/llms-full.txt` | التوثيق المنشور المقروء آلياً. |
| `GET /:id/sitemap.xml`, `GET /:id/robots.txt` | ملفات الاكتشاف المنشورة. |
| `GET /:id/changelog`, `GET /:id/changelog/rss.xml` | سجل النشر وRSS. |

يقبل سجل المحادثة حتى 12 رسالة مستخدم أو مساعد، كل منها من 1 إلى 4000 حرف
بعد التشذيب، وقد تقلل إعدادات الخادم هذا الحد. افتراضي `consent` هو `unknown`،
ويتحقق الخادم من سماح الموقع بقيمة `not_required`. افتراضي الحد العام 300 طلب
لكل IP في الدقيقة؛ لمسارات خريطة الموقع وrobots وحل النطاق والبيانات الوصفية
الرخيصة ميزانية مستقلة أكبر بعشر مرات. لكل من الإجابة والمحادثة حد إضافي
افتراضي 10 طلبات في الدقيقة. الحصص اليومية وميزانيات الرموز مستقلة؛ راجع
[تشغيل البحث والذكاء الاصطناعي](/ar/self-hosting/search-ai).

تعيد معالجات JSON المعتادة `{data: ...}`. يستخدم تحقق المخطط HTTP `422`
بالغلاف `{error: {code, message, details}}` والرمز `validation:failed`.
تصل أخطاء المحادثة بعد بدء البث كأحداث؛ افحص الحدث النهائي أو الخطأ بدلاً من
اعتبار HTTP 200 دليلاً على الإجابة. يستخدم MCP أغلفة البروتوكول الخاصة به.

## نقاط الصحة

| المسار | المعنى |
| --- | --- |
| API `GET /health` على 4311 | حالة بدء الخدمة وإيقافها ومعرّف النسخة؛ HTTP 200 عند الجاهزية فقط، مع صحة التحليلات المستقلة. |
| العامل `GET /health` على 4312 | جاهزية الطوابير والبريد المطلوب ومعرّف النسخة وصحة التحليلات المنفصلة؛ الجاهزية المتدهورة تعيد HTTP 503. |
| التطبيق `GET /api/app/health` | فحص معرّف النسخة يعيد `ok: true`؛ ليس فحص جاهزية API الأساسية. |

أبقِ فحوص المشغّل داخلية. لا تثبت صحة المخطط استقبال التحليلات أو وصول البريد.

## أداة المصدر للتوثيق العام

تفحص CLI المواقع العامة وتجلبها؛ لا تقبل بيانات اعتماد ولا تنشئ مسودات ولا
تنشر أو ترحّل أو تنسخ الخادم احتياطياً. من مستودع مصدر مثبت الاعتماديات مع
Node.js 22.22.2 أو أحدث وpnpm 10.34.9:

```bash
node --import tsx packages/cli/src/cli.ts --help
node --import tsx packages/cli/src/cli.ts inspect https://docs.example.com --json
node --import tsx packages/cli/src/cli.ts fetch https://docs.example.com/getting-started
```

استبدل النطاق والمسار التوضيحيين بموقعك المنشور وصفحة عامة حقيقية. يفحص
`inspect` الجذر و`llms.txt` وخريطة الموقع وOpenAPI وتفاوض Markdown
و`Vary: Accept` وصفحة مفقودة. رمز الخروج 0 للنجاح، و1 لفشل فحص أو جلب، و2
لاستخدام أمر غير صالح. يطبع `fetch` استجابة Markdown. ينتج بناء الأداة
`packages/cli/dist/cli.mjs`؛ استخدم مسار المصدر أعلاه إذا لم تُبنَ.
وجود حزمة في المصدر لا يثبت إتاحتها من npm.

يتطلب `inspect` حالياً نجاح الفحوص الستة جميعاً، بما فيها مستند OpenAPI صالح.
لذلك يعيد 1 لموقع توثيق بلا مرجع API حتى لو عمل القارئ جيداً. تعامل مع الفحوص
كدليل منفصل لكل مسار، لا كحكم شامل على جاهزية الإنتاج.
