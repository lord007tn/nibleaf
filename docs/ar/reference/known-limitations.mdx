لا يزال Nibleaf قبل الإصدار 1.0. تعتمد الإمكانات على الإصدار الذي تنشره، وقد
يتضمن `main` ميزات غير موجودة في أحدث إصدار على GHCR. تحقق من مسار العمل
المطلوب باستخدام الوسم نفسه قبل الالتزام بترحيل إلى بيئة الإنتاج.

## التزامات الهوية والخدمة

خدمة Nibleaf Cloud نسخة تجريبية مجانية ولا تعد حاليًا بوقت تشغيل بمستوى
المؤسسات أو بأزمنة استجابة محددة للدعم العام. صدّر المحتوى الحرج واحتفظ بخيار
تشغيلي بديل.

تتوفر رموز البريد الإلكتروني لمرة واحدة من دون كلمة مرور، كما يتوفر Google
OAuth. ولا يتضمن نموذج الهوية الحالي تسجيل الدخول بكلمة مرور أو روابط إعادة
تعيينها. ولا يتوفر SAML أو عرض عام لتسجيل الدخول الموحد للمؤسسات. لا تستنتج
ادعاءً بالامتثال في الهوية من مجرد وجود OAuth أو عناصر التحكم في الموقع الخاص.

## مرجعية المحتوى وGit

يخزّن Nibleaf نصوص Markdown النشطة للصفحات والتنقل في Postgres. يُعد Markdown
تنسيق التسلسل المحمول، لكن المشروع المدعوم بقاعدة بيانات لا يصبح تلقائيًا مجلد
Git. يستهدف التأليف ثنائي الاتجاه حاليًا GitHub، ويستخدم فرعًا مخصّصًا وطلب سحب
بحالة مسودة وتسوية صريحة للتعارضات. ويظل بإمكان مستودعات GitHub وGitLab العامة
دعم الاستيراد أحادي الاتجاه ومسارات عمل OpenAPI المدعومة بالمستودع.

يقرأ مستورد Mintlify مستودع مصدر عامًا على GitHub، ولا يقرأ رابط محرّر مستضافًا
في Mintlify Cloud. تنشئ كل عملية 500 عقدة تنقل كحد أقصى، بما فيها المجموعات
والصفحات. تحتاج المصادر الأكبر إلى خطة صريحة للتقسيم والمطابقة؛ ولا يثبت نجاح
ملخص الاستيراد أن الموقع الأصلي يقع ضمن هذا الحد.

قبل استخدام مسار عمل مرتكز على Git، اختبر السحب والدفع وتسوية التعارضات وحماية
الفروع وسلوك المعاينة مع المزوّد نفسه وبنية المستودع التي ستستخدمها. عيّن مصدرًا
مرجعيًا واحدًا ووثّق الاستعادة عند تغيّر الجانبين.

## حدود مرجع API

ينشر خادم المنصة مرجع OpenAPI الخاص به. ويمكن لمشروع نشر مستند OpenAPI 3.x
واحدًا، من خلال الرفع أو اللصق، أو عنوان URL عام آمن، أو مستودع GitHub أو
GitLab عام ومتصل. تُجمع ملفات `$ref` الخارجية العامة ضمن حدود صارمة للعدد
والحجم والمهلة وإعادة التوجيه ووجهة الشبكة. تتطلب المراجع النسبية مصدر URL أو
مستودعًا، بينما يمكن للملفات المرفوعة استخدام روابط HTTP(S) عامة ومطلقة. ولا
يتوفر وكيل تجربة من جانب الخادم. اختبر مواصفات ممثلة، ومخططات كبيرة، وعينات
التعليمات البرمجية، والتنقل على الهاتف، واستخدام لوحة المفاتيح، وCORS،
والمصادقة، ومسار التجربة في المتصفح قبل اختيار Nibleaf لبوابة تركّز على API.

لا تنشر مطلقًا بيانات اعتماد حية داخل مثال OpenAPI. كما يعتمد طلب التجربة من
جانب القارئ على قبول واجهة API الموثّقة لمصدر التوثيق.

## التشغيل والاستعادة

تنقل الاستضافة الذاتية مسؤولية DNS وTLS وقواعد البيانات وطوابير المهام وتخزين
الكائنات والبريد والنسخ الاحتياطي والمراقبة والترقيات والاستجابة للحوادث إلى
المشغّل. مكدّس Compose نقطة بداية لعملية النشر، وليس التزامًا بخدمة مُدارة.

تحمي لقطات التطبيق القرّاء من المسودات المكتوبة جزئيًا. لكنها ليست بديلًا عن
نسخ احتياطية متزامنة لـPostgres وتخزين الكائنات.

تبدأ عمليات التصدير المحمولة من أحدث عملية نشر بالحالة `READY`، وتشمل Markdown
أو PDF أو HTML ثابتًا. ولا تحفظ المسودات أو هويات مساحة العمل أو التعليقات أو
التحليلات أو بيانات الاعتماد أو بقية قاعدة البيانات. ويتطلب تصدير PDF أيضًا
متصفحًا متوافقًا مع Chromium ضمن صورة عامل المعالجة (worker).

## سلوك البحث وتعدد اللغات

البحث نصّي كامل وتقريبي، وليس استرجاعًا دلاليًا. يحسن التقسيم الخاص باللغة
وتطبيع العربية من المطابقة، لكنهما لا يضمنان أن تؤدي كل صيغة صرفية أو كلمة
مرادفة إلى الصفحة المقصودة. أنشئ استعلامات القبول من المفردات الفعلية للقرّاء.

لكل لغة شجرة صفحات مستقلة. لا يترجم Nibleaf المحتوى المصدر تلقائيًا، ولا يضمن
التكافؤ بين اللغات. تعرض إعدادات اللغات نسبة تغطية الفرع الافتراضي باستخدام
مفاتيح الترجمة الصريحة والمسار المتطابق الاحتياطي نفسه المستخدم في `hreflang`
المنشور؛ وتظل جودة الترجمة وتكافؤ التحويل مسؤولية المشغّل.

## الإبلاغ عن فجوة مانعة

ابحث في متعقّب البلاغات العام قبل تقديم بلاغ. أرفق وسم الإصدار وملخّصه الرقمي،
ونوع عملية النشر، والنتيجة المتوقعة، والنتيجة الفعلية، وخطوات إعادة إنتاج
مصغّرة. أزل الأسرار ومحتوى العملاء وأسماء المضيفين الخاصة والرموز. أبلغ عن
الثغرات بصورة خاصة عبر المسار المحدد في ملف `SECURITY.md` بالمستودع.
