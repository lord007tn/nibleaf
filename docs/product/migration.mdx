An import copies your existing docs into Nibleaf and converts them. It is a
conversion, so some things will need checking. Keep your old site running until
you have checked the new one and know how to switch back.

## Before you start

- You need to be the site's Owner or an Admin.
- Record what you have now: the number of pages and images, the navigation
  structure, redirects, languages, and a few searches that must find a
  particular page.
- Keep a copy of the source, and decide who is responsible for the switch and for
  switching back if needed.
- Consider importing into a new, separate site first, so you can practice
  without touching your live docs.

## Choose your source

Open **Settings → Import** and choose a source:

| Source | What Nibleaf brings in | Check closely |
| --- | --- | --- |
| **Mintlify** | From a public GitHub repository: `docs.json` or `mint.json`, navigation, pages, languages, versions, images, and site branding. | Custom components, redirects, and settings that have no Nibleaf equivalent. |
| **GitBook** | From a public GitBook Git Sync repository on GitHub: `.gitbook.yaml`, `SUMMARY.md` sections, pages, GitBook blocks, images, and redirects. | Embeds, OpenAPI blocks, adaptive content, and blocks with no Nibleaf equivalent. |
| **Ghost** | From a Ghost JSON export: published posts and pages, tags, images, and metadata. | Language tags, custom cards and embeds, routes, and redirects. |

To bring in Markdown files from any other public Git repository, use
**Settings → Git** and open **Import a public repository instead**. That import
is one-way. To keep editing in both Git and Nibleaf, see
[Connect a GitHub repository](/git-authoring).

One import can bring in up to 500 navigation entries, counting groups and pages.
Split larger sources into smaller parts.

### Import from Mintlify

1. Enter the **GitHub repository** as `owner/repository`, and a
   **Branch (optional)**.
2. To replace everything in your current draft, tick
   **Replace the current draft with this repository**. Otherwise imported pages
   are added to what you already have.
3. Select **Import**.

Nibleaf can't read a private Mintlify workspace. If your docs aren't in a public
GitHub repository, copy them to a temporary public repository first, without any
secrets or private content.

### Import from GitBook

Enter the Git Sync **GitHub repository** and an optional **Branch (optional)**. If
the repository holds several GitBook spaces, also enter the
**Space folder (optional)**, for example `docs/guides`. Then select **Import**.
GitBook sections become sidebar headings and keep their GitBook addresses.

### Import from Ghost

1. Give every Ghost post and page exactly one language tag whose slug matches a
   language on your Nibleaf site, such as `en` or `ar`. The import stops if a
   tagged language doesn't exist on the site yet.
2. In Ghost Admin, open **Settings → Labs → Import/Export** and export your
   content as JSON.
3. In Nibleaf, choose the **Export file (.json)** (up to 15 MB) and enter the
   **Ghost site URL**, including `https://`. Nibleaf uses the address to copy your
   images.
4. Select **Import**.

Nibleaf imports published public posts and pages only. It skips drafts, scheduled
posts, and members-only or paid content, so private articles never become public
docs. Recreate your Ghost redirects yourself in
**Settings → Appearance → Redirects**.

## Read the import summary

The summary shows how many pages were imported, updated, and skipped, and how
many images were copied. Select **Show warnings** and deal with each one. Imports
add or update pages and never delete them, so running an import again is safe.

If an image couldn't be copied, the page still points to the old address. That
image will break when you shut down the old site, so download and upload it
again.

Imported pages are drafts. Readers see them only after you publish.

## Check that nothing was lost

1. Compare the page count and navigation with your notes.
2. Preview at least one page of each kind: tables, code, images, and components.
3. Check languages and versions, and open **Settings → Languages** to find
   missing translations.
4. Click through links, images, downloads, and redirects.
5. Run the searches you recorded, in every language.
6. Check page titles and descriptions.
7. Check a few pages on a phone and with a keyboard.
8. Publish, then repeat the checks in a private browser window.

## Switch over

Connect your domain only when everything above works. See
[Connect a custom domain](/product/custom-domains). Before you switch, make sure
you can point your domain back to the old site, and don't delete the old site
until the new one has run without problems for a while.

[Export a Markdown copy](/product/exports) before a large migration and after the
final switch. If you will keep using GitHub, set up
[two-way Git editing](/git-authoring) in a test repository first. Check the
[known limitations](/reference/known-limitations) too.
