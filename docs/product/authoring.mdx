To write documentation, open your site and select **Editor** in the sidebar, or
**Open editor** on the site overview. The editor has your page list on one side
and the page you are writing in the middle. Everything you type is a draft until
you publish.

## Write a page

1. Select a page in the **Pages** list, or select **New page**.
2. Type the page title, then write below it. Type `/` on an empty line to insert
   a heading, list, table, image, callout, or another block.
3. Watch the status next to the page name. It shows **Saving draft…** and then
   **Draft saved**. If it shows **Not saved**, select **Retry saving** before you leave.

The chip next to the status tells you whether readers can see this page yet:
**Unpublished changes** or **Published**.

To change how the editor looks, open **More options** (the `…` button above the
page):

- **Show formatting toolbar** adds a toolbar with bold, links, lists, and more.
- **Edit as Markdown (advanced)** shows the page as plain text with formatting
  codes. Use it for bulk edits or syntax the visual editor can't show. Select
  **Back to the visual editor** when you are done.

Both views edit the same page. If a page contains a component the visual editor
does not recognize, it keeps that block exactly as written and lets you edit
everything around it. To change that block, use **Edit as Markdown (advanced)**.
See [Markdown and MDX](/product/markdown-mdx) for what you can write.

## Organize pages

- **New group** creates a heading in the navigation that holds related pages.
- Drag a page to reorder it, or drop it onto a group to move it inside. With a
  keyboard, focus the page, press Space or Enter, move it with the arrow keys,
  and press Space or Enter again.
- Each page and group has a menu with **Rename**, **Add a page inside**, and
  **Delete page** or **Delete group**. Deleting can't be undone, and readers
  stop seeing the page after your next publish.

Keep the structure shallow and organized around reader tasks, such as "Getting
started", "Common tasks", and "Troubleshooting", rather than copying your
product's menus.

## Change page details

Select **Page settings** (the sliders icon above the page) to change:

- **Title** and **Web address**, the last part of the page's address. Changing
  the address of a published page breaks links people saved, so add a
  [redirect](/redirects) from the old address.
- **Description**, shown under the title and in search results.
- **Hidden**, which keeps the page out of the navigation.

**More options** in the same dialog holds the sidebar title, search-engine and
social sharing settings, page width, and the **Translation key** that links a
page to its translations. See [Arabic and right-to-left docs](/product/arabic-rtl).

## Review a change with your team

1. Select **Comment**, highlight the text you want to discuss, and write your
   comment. Comments appear in the **Comments** panel next to the page.
2. Select **Resolve** when the comment is handled.
3. Select **Preview** to read the draft as a reader would. It opens in a new tab;
   allow pop-ups for Nibleaf if nothing happens.
4. When you are ready, select **Publish** and use **Review changes** to see
   exactly what changed on each page before you publish.

## Get writing help from AI

If your site can draft with AI, through its own [Smart AI](/product/smart-ai)
connection or the provider your Nibleaf host set up, the panel next to the page
shows an **AI** tab with **AI assist**. It can **Continue writing**,
**Rephrase**, write an **Outline**, or **Summarize**, and it can write from your
own instruction. Review every suggestion before you choose **Insert** or
**Replace**. Nothing reaches readers until you publish.

## Manage documentation versions

Versions let readers switch between docs for different releases of your product,
such as `v1` and `v2`.

- To create one, open **More options** and select **New version**. The new
  version starts as a copy of the version you are viewing.
- When a site has more than one version, a **Version** switcher appears at the
  top of the editor.
- **Every publish includes every version**, so readers can see each one. Don't
  use a version as a private draft for a rewrite.

**Promote into main** brings the version's changes into main, then removes the
version. You can't undo this, so download your drafts first: open
**Settings → Exports → One-time export** and select
**Download the original Markdown ZIP**. A regular export contains only your
latest published version, not unpublished edits.

If someone changed pages on main after the version was created, Promote stops,
says why, and changes nothing. A step to review those pages and confirm is
coming soon. Until then, switch to main, create a new version there, and copy
this version's edits into it. When a version is promoted:

- **What you changed in the version** replaces main's, one field at a time. If
  you fixed a page's text and main renamed it, both changes are kept. If both
  changed the same thing, the version's change wins. If the page's folder is
  gone afterwards, the page also moves up to the nearest folder that's left,
  and the review says where it lands.
- **Pages you didn't touch** keep main's latest edits.
- **Pages added on main** stay. If a page's folder is gone, the page moves up to
  the nearest folder that's left. If a page would share an address with another
  page, it gets a numbered address, such as `refunds-2`.
- **Pages deleted on main** stay deleted, unless you changed them in the version
  or a page you kept is inside them.
- **Pages you deleted in the version** are removed from main.

If the moves on both sides would put two pages inside each other, Promote stops.
Move one of them in the version, then promote again.

Comments and reader access follow the page: on a page from the version they move
to main's page, and on a page that ends up removed they're removed with it.

Promote refuses versions created before this update, versions made from them,
and versions created before an import replaced main's pages. Recreate it from
main: switch to main, create a new version there, and move your changes into it.

## Recover from a bad draft

If the published site is still correct, don't publish. Fix the draft, wait for
**Draft saved**, and preview again. The publish dialog's **Review changes** shows
what differs from the published version, which helps you find the problem.

If a bad version is already live, see
[Publish your changes](/product/publishing#undo-a-publish).

A published version is not a backup of your drafts. To keep a copy of
unpublished work, use **Download the original Markdown ZIP**; see
[Export and archive](/product/exports).
