Add-ons are optional features you can turn on for your site, such as a
"Was this page helpful?" button or checks that run before you publish. Open
**Settings → Add-ons**. You need to be the site's Owner or an Admin.

Each add-on shows its status: **Active**, **Inactive**, **Needs configuration**,
or **Unavailable**. Unavailable means your plan does not include it. Add-ons
marked **Preview** are still being tested. Use the switch on each
add-on to switch it on or off. Changes apply to your published site straight
away, without a new publish.

Connections to outside services, such as Google Analytics or Slack, are not
add-ons. You'll find them in **Settings → Integrations**.

## Reader engagement

| Add-on | What readers see |
| --- | --- |
| **Feedback widget** | "Was this page helpful?" with **Yes** and **No**. Results appear in **Analytics → Feedback**. |
| **Edit suggestions** | A link that opens the page's source in a tool such as GitHub, so readers can suggest a change. |
| **Raise issues** | A link that opens a new issue form, for example on GitHub, with the page already filled in. |

The feedback widget records only Yes or No for the page. Readers can't type a
comment. Choose its **Placement** (**After page content** or **After previous and
next links**) and **Presentation** (**Compact row** or **Card**).

Edit and issue links need a web address template before they work. Use
`{path}` where the page's path should go. Issue links can also use `{url}` for
the page's full address. For example:

- Edit URL template: `https://github.com/acme/docs/edit/main/{path}.mdx`
- Issue URL template: `https://github.com/acme/docs/issues/new?body={url}`

Templates must start with `https://` or `http://` and can't contain a password.
Open a page inside a group in **Preview** and select the link to check that it
opens the right place.

## Privacy and consent

The **Consent banner** asks readers before optional analytics load. Readers can
accept or decline, and can change their choice later. Their choice is saved in
their browser.

You can choose **Card placement**, **Card density**, and **Action layout**. These
change only how the banner looks; they don't change what it allows.

If you turn the consent banner off, optional analytics stay blocked. They never
load without asking. Check the banner on a phone-sized window, in each of your
site's languages.

## Publishing checks

| Add-on | What it does |
| --- | --- |
| **CI checks** | Turns on the checks below. If it is off, none of them run. |
| **Broken link checks** | Stops a publish when a link points to a page that doesn't exist in the same language and version. |
| **Grammar linter** | Flags grammar and wording issues during publishing. This add-on is in preview. |
| **Preview deployments** | Lets your team preview unpublished changes before release. |

When a check stops a publish, the site overview shows the failed publish and a
list of issues. Fix broken links, then publish again. If only grammar
suggestions remain, you can select **Publish anyway**. Keep **CI checks** on
unless you need a temporary exception, and fix the copy afterwards.

## For developers and self-hosters

Add-ons can also be read and changed through the API with an API key that has
the `addons:read` or `addons:write` permission. AI assistants connected through
MCP can read add-ons but can't change them. See the [API reference](/reference/api)
and [Connect MCP clients securely](/self-hosting/mcp). Self-hosters upgrading
from an older release should follow the
[combined release migration guide](/self-hosting/combined-release-migration).
