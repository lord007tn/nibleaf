Connect an AI assistant to one of your websites and ask it, in your own words,
what readers can't find, which pages need work, or to draft and translate pages
for you. Everything it writes is a draft: nothing reaches readers until someone
reviews a publish and confirms it.

Assistants talk to Nibleaf through the Model Context Protocol (MCP), an open
standard that ChatGPT, Claude, Claude Code, Cursor and VS Code support. The full
list of what an assistant can do is in the
[AI assistant (MCP) reference](/reference/mcp).

## What you can do

- **Find gaps.** "What did readers search for this week and not find?" The
  assistant groups failed searches and checks which pages already cover them.
- **Fix pages.** "Which pages did readers mark as unhelpful? Propose edits." It
  reads the pages and drafts changes for you to review.
- **Write and translate.** "Draft a page on resetting a password, then translate
  it into Arabic." Both land as drafts, with a link to review each one.

## Before you start

- **Your role.** Editors, Admins and Owners can connect an assistant. Viewers
  can't yet.
- **Your app.** Install ChatGPT, Claude (claude.ai or Claude Desktop), Claude
  Code, Cursor, or VS Code with an MCP-capable chat extension.
- **The server.** Open your website's **Settings → AI assistants**. If it says
  **AI assistant connections aren't available yet**, this Nibleaf server has
  MCP turned off: nobody can connect an assistant to any website on it yet, and
  there is nothing to fix on your side. Keys and apps connected earlier are still
  listed so you can remove them. If you run your own server, see
  [Connect MCP clients securely](/self-hosting/mcp) to turn it on.

## Connect your assistant

In **Settings → AI assistants**, under **Connect an assistant**, choose your app
under **Your AI app**. The page shows two or three numbered steps for it, with
the address to paste and a **Copy** button on the step where you need it. The
address is your dashboard's address followed by `/api/mcp`; the examples below
use `https://docs.example.com/api/mcp`.

### ChatGPT

1. In ChatGPT, open **Settings › Apps & Connectors** and turn on developer mode.
2. Create a connector, choose OAuth, and paste the address.
3. When ChatGPT opens Nibleaf, sign in, choose the website and what ChatGPT may
   do, then select **Allow**.

### Claude (claude.ai or Claude Desktop)

1. Open **Settings › Connectors › Add custom connector**.
2. Paste the address, then select **Connect**.
3. When Claude opens Nibleaf, sign in, choose the website and what Claude may
   do, then select **Allow**.

### Claude Code

1. In a terminal, run:

```bash
claude mcp add --transport http nibleaf "https://docs.example.com/api/mcp"
```

2. Start Claude Code and open **/mcp › nibleaf › Authenticate**.
3. Sign in to Nibleaf, choose the website and what Claude Code may do, then
   select **Allow**.

### Cursor or VS Code

1. Select **Add to Cursor** or **Install in VS Code** on the page and confirm the
   install, or save the configuration from the page in your project. For Cursor,
   that is `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "nibleaf": {
      "url": "https://docs.example.com/api/mcp"
    }
  }
}
```

   For VS Code, it is `.vscode/mcp.json`:

```json
{
  "servers": {
    "nibleaf": {
      "type": "http",
      "url": "https://docs.example.com/api/mcp"
    }
  }
}
```

2. The first time the editor connects, it opens Nibleaf. Sign in, choose the
   website and what the editor may do, then select **Allow**.

### Choosing the website and what it may do

When you sign in from an app, Nibleaf asks you to **Choose a website**. If you
belong to more than one organization, websites are grouped under each
organization's name, with each website's address under its name. Then choose
**What the app can do** (see [Permission levels](#permission-levels)) and select
**Continue**. The next page, **Allow access?**, lists in plain words what the app
will and will not be able to do. If it says the app registered itself, its name
isn't verified: continue only if you started the connection from that app.

Each connection works on one website. To use another website, connect again and
choose it.

### Check that it worked

After you copy the address or install, the page watches for your app for ten
minutes:

- **Waiting for ChatGPT to connect…** Nothing has signed in yet.
- **Allowed: an app named ChatGPT can now use this website.** You approved it,
  and Nibleaf is waiting for its first request.
- **ChatGPT is connected and working.** It made a request that succeeded.
- **An app named … was allowed, not ChatGPT.** A different app signed in as you.
  If you didn't start it, disconnect it under **Connections**.
- **Not connected yet** or **… was allowed but hasn't made a request yet.** Check
  the steps in your app, then select **Watch again**.

You can also ask the assistant to call `get_capabilities`: it names the website
and lists exactly what this connection can and can't do, and why.

## Use a personal key instead

Use a key for scripts and for apps that can't sign in. ChatGPT and claude.ai
require HTTPS sign-in. Otherwise, use Claude Code, Cursor or VS Code with a
personal key. Select **Use a personal key**, choose a
permission level, name the key after where it will be used (for example "Laptop
– Claude Code") and choose when it expires. Then select **Create key**.

The secret is shown once. Copy it into your app or a password manager, never into
a chat, ticket or file you commit. The dialog then shows the setup for Claude
Code, Claude Desktop, Cursor or VS Code with the key filled in, and **Test
connection** checks it end to end. It closes only when you select **I saved my
key — close**.

For Claude Code, the command contains the key, so remove it from your shell
history afterwards:

```bash
claude mcp add --transport http nibleaf "https://docs.example.com/api/mcp" --header "Authorization: Bearer YOUR_NIBLEAF_KEY"
```

For Cursor, set `NIBLEAF_API_KEY` in the environment Cursor starts from; the
configuration reads it, so the file holds no secret:

```json
{
  "mcpServers": {
    "nibleaf": {
      "url": "https://docs.example.com/api/mcp",
      "headers": {
        "Authorization": "Bearer ${env:NIBLEAF_API_KEY}"
      }
    }
  }
}
```

VS Code asks for the key in a password prompt the first time and keeps it in its
secret storage. Claude Desktop reaches a key-protected server through the
`mcp-remote` bridge, which needs Node.js; the dialog shows the exact block and
where the settings file lives.

## Permission levels

Pick the smallest level that covers what you need. A connection can never do
more than your own role allows, and Nibleaf re-checks your role on every request.

| Level | It can | It can't |
| --- | --- | --- |
| **Read only** | Read the website's pages, languages, versions, analytics, search health, publish history, and saved Ask AI questions and answers. | See individual search terms, change any page, or publish. |
| **Support writer** | Everything in Read only, plus the words readers searched for; create, edit, move, translate, hide and show page drafts; publish after a fresh preview is confirmed. | Delete pages, change settings, members or billing, or publish without a confirmed preview. |
| **Full admin** (Admins and Owners) | Every tool Nibleaf offers over MCP, including usage, add-ons, themes, exports and integration status. | Anything Nibleaf doesn't offer over MCP at all: deleting, credentials, payments or running code. |

Give unattended automations **Read only**. A key's **Advanced** permissions let
you pick single scopes instead, for example Read only plus
`analytics:search_terms` for someone who reports on searches but never edits.

## Try asking

Ask in your own words; these are starting points. Each one leads to the tools
listed, and needs at least the permission shown.

| Ask | Tools it leads to | Needs |
| --- | --- | --- |
| What did readers search for in the last 7 days and not find? Group similar searches and tell me which pages are missing. | `get_failed_searches`, `search_pages` | Read only plus `analytics:search_terms` through a custom personal key, or Support writer |
| Write this week's docs health report. | `get_analytics_overview`, `get_top_pages`, `get_page_feedback`, `get_search_health`, `get_pending_changes` | Read only |
| Which questions couldn't Ask AI answer this month? Suggest an article for each. | `list_ai_content_gaps`, `get_ai_conversation` | Read only |
| Which pages did readers mark as unhelpful? Read them and propose edits, but don't save anything yet. | `get_page_feedback`, `get_page` | Read only |
| Draft a page called "Reset your password" in the style of our other pages. Don't publish it. | `search_pages`, `get_page`, `create_page_draft` | Support writer |
| Translate "Getting started" into Arabic as a draft. | `list_languages`, `get_page`, `translate_page` | Support writer |
| What would go live if I published now? | `preview_publish` | Support writer |
| Publish it. (after you've read the preview) | `publish_changes`, `get_deployment` | Support writer |
| Which AI assistants and crawlers send readers to our docs? | `get_referrers` | Read only |
| Hide the "Legacy API" page from navigation and search. | `search_pages`, `set_page_visibility` | Support writer |

Some assistants also list Nibleaf's ready-made prompts, such as
`weekly_docs_health_report` and `find_content_gaps`.

## Review and publish safely

- **Drafts first.** Every write changes drafts only. Readers keep seeing the
  published site.
- **A link to review.** After a write, the assistant gives you a link: the page
  in the editor, the publish dialog, or a publish's status. Opening a link never
  publishes anything; it only shows you where to look.
- **Preview, then confirm.** Publishing needs a fresh preview and an explicit
  confirmation that carries the preview's token. The token works for 10 minutes
  and only once: any change after the preview, including another publish, makes
  it stale, and the assistant has to preview again.
- **A publish includes everyone's drafts.** Publishing ships every unpublished
  change on the website, not only the assistant's. Read the preview, or open the
  publish dialog from its link, before you say yes.
- **Nibleaf checks the preview, not the person.** An assistant that runs without
  asking you could confirm on its own, so keep **Support writer** for assistants
  you work with, and **Read only** for anything unattended.
- **Page text is data, not instructions.** Pages, search terms and reader
  feedback can contain anything someone typed. If an assistant wants to do
  something because a page "says so", decline.

## What it can read about your readers

Every preset, including Read only, can read saved Ask AI questions and answers;
custom keys can read them only when granted `analytics:read`. Email addresses,
phone numbers and keys are removed, but names, addresses and other personal
details may remain. This is the same wording the **Allow access?** page shows. Individual search terms are a separate permission
and follow the rules in
[What analytics can and cannot tell you](/reference/mcp#what-analytics-can-and-cannot-tell-you).

## See and remove connections

**Connections** lists everything that can use the website on someone's behalf:
apps that signed in and personal keys, most recently used first. Each row shows
its permission level, when it was last used and what it last did. A key that
expires within a week says so. Expired and revoked keys move under **Inactive**.
Expired keys can be rotated or revoked. Revoked keys remain listed under Inactive
without further actions.

Admins and Owners see everyone's connections and can filter by person; others
see their own. **Disconnect** stops an app at once, **Revoke** stops a key at
once, and **Rotate** replaces your own key with a new secret. A rotated key keeps
its expiry date; an expired or older key without one gets 90 days. Connections
also stop when their owner leaves the website or is suspended.

## When something goes wrong

| The assistant says | Why | What to do |
| --- | --- | --- |
| It can't see search terms or failed searches | Its permission lacks search terms, or this server doesn't keep them. `get_capabilities` says which. | Reconnect with **Support writer** or a key with `analytics:search_terms`, or accept counts only. |
| It can't edit or publish | Its permission is **Read only**, or your role changed. | Reconnect with **Support writer**, or ask an Admin about your role. |
| The page changed after it read it | Someone else saved the page first. | Ask it to read the page again and redo its change. |
| The preview is stale or expired | Something changed after the preview, or 10 minutes passed. | Ask for a new preview, review it, then confirm. |
| Its key or connection is invalid | The key expired or was revoked, or the app was disconnected. | Create a new key or connect the app again. |

Every error code is listed in the
[AI assistant (MCP) reference](/reference/mcp#error-codes). When you ask for help,
share the request ID from the error, never the key or page content.
