Publishing turns your drafts into a new version of your site. Readers keep
seeing the current version until the new one is ready, so they never see a
half-built site. Owners, Admins, and Editors can publish.

## Check your pages first

Before you publish, read the pages you changed with **Preview** and check that:

- the first paragraph answers the reader's main question;
- steps are in order, and anything the reader needs comes before the step that
  uses it;
- links open the right page;
- images have a short text description and show no private information;
- titles and descriptions are correct in every language.

## Publish

1. In the editor, select **Publish**. The number on the button is how many
   changes are waiting.
2. The **Publish changes** dialog lists what changed since the last published
   version. Select **Review changes** to see the exact edits on each page.
3. Optionally, add a **Note for your team (optional)**, for example "Updated the
   refund policy".
4. Select **Publish now**.

The dialog shows **Publishing…** and then **Your changes are live**. Select
**View site** to open it. If nothing changed in your pages, you can still publish
to apply settings changes, such as redirects.

Publishing includes everyone's unpublished changes on the site and every
[documentation version](/product/authoring#manage-documentation-versions), not
only your own edits. Check the list before you publish.

## Check what readers see

Open your site in a private browser window, where you are signed out, and check:

1. The home page and a page you changed open normally.
2. Search finds a phrase from a page you changed.
3. A moved page's old address takes readers to the new page.
4. On a phone-sized window, the menu, language switcher, tables, and code blocks
   are easy to use.

"Your changes are live" means Nibleaf built the new version. It does not check
your custom domain or your readers' network. If the site does not open on your
own domain, see [Connect a custom domain](/product/custom-domains).

## If publishing is blocked or fails

- **Redirects must be fixed before publishing.** A redirect points to a page that
  doesn't exist or creates a loop. Fix it in the [redirect settings](/redirects)
  and try again.
- **Publishing did not finish.** Open **What went wrong** to read the reason,
  fix it, and select **Retry**. Your draft is safe, and readers still see the
  previous version.
- **Publish failed** on the site overview, with a list of broken links or grammar
  issues. These come from the publishing checks in
  [add-ons](/product/add-ons). Fix broken links before you publish again. If only
  grammar suggestions remain, you can select **Publish anyway**.

Don't publish again and again to get past an error. Read the reason first.

## Undo a publish

Right after a publish, the dialog offers **Restore previous version**. It
publishes the previous version again, so readers see it within moments.

Restoring does not change your drafts. They still contain the changes you wanted
to undo, so fix them before your next publish, or the same problem goes live
again.

A published version is not a backup. If you host Nibleaf yourself, also follow
the [backup and restore guide](/self-hosting/backups-upgrades).
