دُمجت ست حزم قدرات في شجرة المصدر العامة على فرع `main`: تشخيص البحث الهجين،
وقياس الاستخدام المحايد للمزوّد، وإضافات المشاريع، وسمات التوثيق المحمولة،
وتكاملات المشاريع، ومستوى تحكم MCP للقراءة فقط.

هذا إعلان عن مصدر مدمج، وليس إثبات نشر. لم يحدث نشر إنتاجي ولا يعني الدمج وجود
صورة استضافة ذاتية جديدة. لا يزال المثبت الموقّع يشير إلى v0.1.2؛ لذلك ينبغي
للمشغّل انتظار صورة v0.2 منشورة بصورة منفصلة أو بناء المصدر المراجع قبل تطبيق
مسار الترحيل الجديد.

## بحث هجين مع مسار تراجع واضح

يجمع مسار البحث الجديد بين BM25 والمتجهات الكثيفة داخل Qdrant مع فلتر إلزامي
للمستأجر. يشتق الخادم المشروع والنشر والإصدار واللغة ووضع الوصول ومنح صفحات
القارئ؛ ولا يستطيع المتصفح إرسال نطاق استرجاع يختاره. يعمل العقد نفسه للمحتوى
العربي والإنجليزي والمختلط مع إبقاء مسارات التطبيع والترتيب الواعية باللغة.

ابدأ بـ `SEARCH_RUNTIME=shadow`. يبني هذا الوضع المسار الهجين ويقيّمه بينما
يستمر القارئ في تلقي النتائج التقليدية. بعد التحقق من الأعداد المقيدة واختبارات
منع التسرب وجودة الترتيب والمهلة، يمكن الانتقال إلى `hybrid`. يبقى
`SEARCH_RUNTIME=legacy` هو التراجع الفوري لنتائج البحث.

الإجابات الموثّقة اختيار منفصل. تحتاج إلى تفعيل بيئة الإجابة وتثبيت النموذج
وتفعيل إعداد المشروع صراحة. تعمل النتائج من دون نموذج إجابة. يتحقق Nibleaf من
الاستجابة البنيوية والاستشهادات كاملة قبل إعادتها، ويرفض الادعاءات غير المدعومة
بدلاً من بث نص نموذج غير متحقق منه.

## الاستخدام يصف الاستهلاك ولا يدّعي أنه فوترة

يسجل عقد الاستخدام أحداثاً محايدة للمزوّد ومجاميع تمت تسويتها. يحتفظ ClickHouse
بالحقائق عالية الحجم والتجميعات، بينما يحتفظ PostgreSQL بالخطط والاستحقاقات
وحواجز الحذف ونقاط فحص التصدير. تبقى حالة المزوّد المفقودة غير معروفة ولا تتحول
إلى صفر.

سلوك حدود الاستخدام استشاري في هذا المصدر. لا توجد عملية دفع ولا ادعاء بفرض
حصة ذرية. هذا حد مقصود: يستطيع مزوّد مستقبلي استهلاك المجاميع النهائية من دون
امتلاك هوية المستأجر أو الصلاحيات أو بيانات القارئ الخام.

## الإضافات تجعل السلوك الاختياري صريحاً

تنقل إضافات المشروع السلوك الاختياري للموقع والنشر إلى سجل دائم ومدقق. يغطي
الدليل الحالي الملاحظات واقتراح التعديل وروابط البلاغات وعرض الموافقة وفحوص CI
والروابط المعطلة والتدقيق اللغوي ونشرات المعاينة. التدقيق اللغوي موسوم كمعاينة؛
وجوده في الدليل لا يعني أنه متاح في كل نسخة أو خطة.

تجمع الإتاحة بين الخطة والاستحقاق الحاليين وإعداد المشروع الدائم. تستخدم
التغييرات أرقام مراجعات، ولا تقبل قوالب الروابط سوى العناصر النائبة الموثقة عبر
HTTP(S)، ويفشل الإسقاط العام بصورة مغلقة عندما تكون الإتاحة غير معروفة. ويصل
إعداد الموافقة إلى حد الموقع المنشور نفسه المستخدم للتحليلات بدلاً من إنشاء
مفتاح خصوصية ثانٍ.

## ملكية واضحة لبيانات اعتماد التكاملات

يفصل محرك التكاملات بين الاتصالات التي يديرها المشروع والمزوّدين الذين يديرهم
مشغّل النسخة. تُشفّر بيانات خطافات الويب الخاصة بالمشروع وتصبح للكتابة فقط بعد
الحفظ. تبقى بيانات اعتماد النسخة لدى المشغّل ولا تظهر في إعدادات المشروع.

يعرض الدليل حالة الإعداد وعدم الإتاحة والصحة وعدم الصحة وعدم التحقق، ولا يحول
غياب المزوّد إلى نجاح. تحتاج عمليات دورة الحياة المدمرة إلى جلسة لوحة موثقة
وتأكيد صريح. لا يعرض سطح MCP النهائي هذه التغييرات.

## السمات المحمولة كبيانات أو مستودعات حقيقية

Harbor وManuscript وSignal قوالب بنيوية لا عينات ألوان. تغير موضع التنقل وإطار
المحتوى وتركيب فهرس الصفحة، مع عرض مصدر Markdown وMDX نفسه. تبقى حالة سمة
المسودة منفصلة عن السمة الثابتة داخل النشر.

يستطيع الفريق تبادل JSON محدود ومتحقق منه من دون CSS أو JavaScript تنفيذي. كما
يمكنه إنشاء مستودع Git عادي قابل للتشغيل يضم مكوّنات وتخطيطات وأنماطاً وأصولاً
ومحوّلات وحالات اختبار قابلة للتحرير. تملك مسارات المنصة والمحتوى المشترك وملفات
العميل حدود ملكية صريحة كي يوفق التزامن التغييرات بدلاً من الكتابة فوقها.

## MCP مقيد بالمشروع وللقراءة فقط

يوثق مسار MCP مفاتيح API ذات صلاحيات ومقيدة بمشروع واحد. يستطيع قراءة بيانات
المشروع والمحتوى وتشخيص البحث والاستخدام والاستحقاقات وحالة الإضافات وصحة
التكاملات والعمليات وبيانات السمات. معاينة استيراد السمة تستخدم `apply=false`؛
ولا يوفر البروتوكول تغيير المحتوى أو التكاملات أو الإعدادات.

يمكن أن تنتهي المفاتيح أو تُدوّر، وتُطبّع الصلاحيات العامة القديمة من دون منح
سلطة MCP، وتسجل أحداث التدقيق بيانات عملية محدودة لا محتوى أو أسراراً. تبقى
صلاحية القارئ الخاص ونطاق المشروع مشتقة في الخادم.

## ترتيب ترحيل واحد وتراجع عكسي

ترتيب PostgreSQL المدمج مقصود:

1. إعداد البحث وتشخيصه؛
2. خطط الاستخدام والاستحقاقات وحالة الاستقبال؛
3. إضافات المشروع؛
4. تكاملات المشروع؛ ثم
5. مفاتيح MCP وسجل التدقيق.

تملك هجرة التكاملات العمود الاختياري `ApiKey.expiresAt`. تعتمد MCP على هذه
الملكية وتحافظ على العمود عند التراجع عنها. أوقف مكوّنات التطبيق قبل عكس
المخطط، واعكس MCP قبل التكاملات. يبقى ClickHouse وQdrant نظامين تشغيليين
اختياريين لكل منهما فحوص نسخ احتياطي وانتقال وتراجع منفصلة.

## ما الذي يجب التحقق منه قبل إتاحة الإصدار؟

شغّل اختبارات الترحيل والوصول في نسخ مؤقتة من PostgreSQL وClickHouse وQdrant.
ثم شغّل تكافؤ التوثيق وسلامة أصول الاستضافة وفحص الشيفرة غير المستخدمة والأنواع
والتنسيق والاختبارات وبناء الإنتاج وحد حزمة جافاسكربت العامة. يحتاج الإصدار
الحقيقي أيضاً إلى بصمة صورة دقيقة وإثبات عرض إنجليزي LTR وعربي RTL على سطح
المكتب والهاتف.

يثبت المصدر العقود، أما الصورة أو النشر أو نتيجة المزوّد فتحتاج إلى دليل مستقل.
