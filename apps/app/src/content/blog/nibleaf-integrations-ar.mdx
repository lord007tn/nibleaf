اختر الاتصال بحسب مهمته: مزامنة ملفات المصدر، أو استيراد موقع قائم، أو قياس زيارات الصفحات المنشورة، أو تشغيل البنية التحتية. تختلف الصلاحيات وأسباب التعطل بين هذه المهام. وجود اسم مزوّد في الفهرس لا يعني أن كل حساب يملك اتصالًا نشطًا به.

يدعم Nibleaf سير تأليف عبر GitHub واستيراد مستودعات Git العامة. ولتحليلات الموقع والبنية التحتية إعدادات منفصلة. يوضح [إعلان إصدار المصدر](/blog/nibleaf-august-2026-source-release-ar) فهرس إدارة التكاملات الأحدث؛ ولا يعني ذلك أن كل مساحة Cloud أو صورة الاستضافة الذاتية المثبتة على v0.1.2 تتضمن هذه القدرات.

## طابق الاتصال مع المهمة

| مهمتك | الاتصال | الحد الذي يجب التحقق منه |
| --- | --- | --- |
| مراجعة تغييرات Markdown في المستودع | GitHub | يعتمد التأليف ثنائي الاتجاه على المستودع والفروع ومسار المحتوى المحددة. تحقّق من الصلاحيات قبل التحرير. |
| نقل توثيق عام قائم | GitLab أو Git عام | استيراد فقط، وليس تحريرًا ثنائي الاتجاه مع GitLab. راجع التنقل والمكونات غير المدعومة. |
| قياس زيارات الموقع المنشور | Google Analytics 4 أو Plausible | إعداد المشروع ثم النشر وموافقة القارئ. لا يستورد هذا المسار تقارير المزوّد السابقة. |
| تقييم اتصالات webhooks للمشروع | Slack وDiscord وZapier | دورة إدارة ضمن إصدار المصدر. حفظ الاتصال أو اختباره لا يثبت إرسال إشعارات النشر تلقائيًا أو وجود تطبيق في متجر Zapier. |
| توفير البحث أو التخزين أو البريد | خدمات يديرها المشغّل | إعداد على مستوى النسخة، وليس ربط حساب المستخدم النهائي. تكاليف المزوّد وتوافره منفصلان. |

## مزامنة GitHub أم استيراد لمرة واحدة؟

استخدم GitHub عندما يبقى المستودع جزءًا من المراجعة المستمرة. اتفق أولًا على فرع المصدر ومجلد المحتوى والشخص المسؤول عن حل التعارضات. جرّب صفحة صغيرة تحتوي عنوانًا وصورة وكتلة شيفرة ومكوّن MDX مدعومًا. قارن فرق الملفات مع الصفحة المعروضة قبل اعتماد المسار للموقع كله.

عند الانتقال من منصة أخرى، ابدأ بتجربة استيراد. ينقل استيراد GitLab العام وGit العام المحتوى إلى Nibleaf، لكنه لا يَعِد بكتابة تعديلات المتصفح اللاحقة إلى المستودع. احتفظ بالمصدر حتى تراجع التنقل والأصول والروابط والتصدير. يشرح [دليل تحويل الموقع بعد الترحيل](/blog/documentation-migration-seo-cutover-lab-ar) ملكية الروابط وخطة إعادة التوجيه.

لا يناسب Nibleaf متطلب التحرير ثنائي الاتجاه مع GitLab أو Bitbucket، أو التأليف المتزامن المباشر، أو تنفيذ مكونات MDX برمجية بلا قيود. راجع هذه المتطلبات قبل النقل في صفحتي [المقارنة مع Mintlify بالإنجليزية](/compare/nibleaf-vs-mintlify) و[المقارنة مع GitBook بالإنجليزية](/compare/nibleaf-vs-gitbook).

## التحليلات تتطلب الإعداد والموافقة

يستخدم GA4 معرّف قياس، ويستخدم Plausible اسم نطاق. اضبط المزوّد المختار للمشروع ثم انشر التغيير. افصل اختبار الزيارة الجديدة عن الزيارة بعد الموافقة: يجب أن يبقى التتبع الاختياري غير نشط قبل الموافقة الصريحة. افتح تفضيلات الخصوصية عمدًا لاختبار التفعيل. حفظ المعرّف وحده لا يثبت وصول حدث إلى المزوّد.

تختلف تحليلات القرّاء المدمجة وبنية ClickHouse التي يديرها المشغّل عن ربط GA4 أو Plausible الخاص بالمشروع. وقد يحتاج المزوّد الخارجي إلى حساب ورسوم وسياسة احتفاظ مستقلة. لا يتضمن هذا المسار ترحيلًا تلقائيًا للبيانات السابقة.

## تحقّق من توافر webhooks وخدمات النسخة

يميّز فهرس المصدر بين بيانات اعتماد webhooks الخاصة بالمشروع والخدمات التي يملكها المشغّل. قد يرسل اختبار Slack وZapier رسالة مرئية ويتطلب تأكيدًا في لوحة التحكم، بينما يكون فحص Discord سلبيًا. لا تثبت حالة التحقق وحدها اكتمال مسار الاشتراك في الأحداث. تحقّق من الحدث المطلوب وسلوك التسليم قبل الاعتماد على الأتمتة.

يشمل التخزين Amazon S3 والخدمات المتوافقة مثل Cloudflare R2 وBackblaze B2، ويمكن للبريد استخدام Postmark أو SMTP. إعداد OpenRouter وQdrant الاختياري مسؤولية المشغّل؛ ووجودهما لا يعني تفعيل الإجابات المستندة إلى المصادر أو شمولها ضمن حصة بيتا مجانية. راجع [نظرة الاستضافة الذاتية بالإنجليزية](/self-hosting) لفهم المسؤولية التشغيلية وتوافق الإصدار.
