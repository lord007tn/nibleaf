After Midad is live, operate it like any other stateful application: monitor the
app, API, worker, database, queue, and object storage together.

## Health checks

| Check | URL or command |
| --- | --- |
| Dashboard | Open `https://app.example.com` and sign in. |
| API | `GET /health` on the server service. |
| Worker | `GET /health` on the worker ops service. |
| Jobs | `GET /jobs` on the worker ops service. |
| Public docs | Open a published site and search for a known page title. |

## Logs

```bash
docker compose logs -f app server worker
```

Check `server` logs for API/auth/storage issues and `worker` logs for publish,
search, email, or analytics job failures.

## Backups

Back up Postgres and object storage together.

- Postgres stores users, workspaces, projects, pages, comments, analytics, and
  immutable deployment snapshots.
- Object storage stores uploaded assets.
- Dragonfly stores queue state; it should be durable enough for normal restarts,
  but Postgres and object storage are the critical recovery targets.

## Upgrades

1. Read the release notes.
2. Back up Postgres and object storage.
3. Pull the new source revision or image.
4. Run migrations.
5. Rebuild/restart app, server, worker, and www.
6. Publish a small docs change to verify the worker and search index.

```bash
git pull
docker compose up -d --build
docker compose run --rm migrate
```

## Troubleshoot publishing

If a publish does not become `READY`:

1. Check worker logs.
2. Open the worker jobs page.
3. Verify Dragonfly is reachable from the server and worker.
4. Verify the worker and server use the same `POSTGRES_URL`.
5. Verify storage credentials and bucket access.

The live site serves the latest `READY` deployment, so readers should continue
to see the previous published version while you investigate a failed publish.

## Rotate secrets

Rotate secrets on a schedule and after any suspected exposure.

- Rotate `BETTER_AUTH_SECRET` during a maintenance window because existing
  sessions can be invalidated.
- Rotate Postgres and storage credentials with matching changes in `.env`.
- Recreate compromised API keys from the dashboard.

## Capacity

Scale the worker before the app if publishing or search indexing becomes slow.
Scale Postgres and object storage based on normal database/storage metrics:
CPU, memory, disk, query latency, and bucket throughput.
