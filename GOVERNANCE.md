# Governance

Nibleaf is currently a maintainer-led open-source project. Maintainers set the
release direction and have final responsibility for security, architecture, and
repository administration.

## How decisions are made

- Bugs, feature proposals, and design questions should begin in a GitHub issue
  or discussion so the reasoning is visible to the community.
- Small, reversible changes can proceed through a pull request after maintainer
  review.
- Substantial or irreversible changes should have an agreed issue before code is
  written. Maintainers weigh user impact, maintenance cost, compatibility,
  security, accessibility, and English/Arabic parity.
- If consensus is not possible, maintainers document the decision and its
  tradeoffs in the relevant issue or pull request.

## Contributions and releases

Anyone may report problems, join discussions, review changes, or open a pull
request under [CONTRIBUTING.md](CONTRIBUTING.md). Merge access is granted by the
maintainers to contributors who demonstrate sustained, constructive work and
sound judgment. Releases are tagged from `main`; supported versions and private
reporting channels are described in [SECURITY.md](SECURITY.md).

Project spaces follow the [Code of Conduct](CODE_OF_CONDUCT.md). This governance
model may evolve as the contributor community grows; changes to it will be made
through a public pull request.
