# Nibleaf SEO and production-readiness audit

Date: 2026-08-15  
Scope: `nibleaf.com`, the local Nibleaf repository, Google Search Console property `sc-domain:nibleaf.com`, and the Nibleaf service in the Coolify `Raed` production project.

## Executive summary

The deployed SEO patch fixes verified indexability, Arabic search, international metadata, content accuracy, internal linking, soft-404, sitemap/canonical, CSP, and article-bundle defects. It adds one English comparison article, one original Arabic implementation guide, and a contact and corrections hub.

The follow-up production-readiness work removed the four external blockers. The GitHub repository and pinned GHCR release are anonymously accessible. Search Console accepted the sitemap and priority crawl requests. Coolify now sends daily object-storage and PostgreSQL volume archives to the connected Cloudflare R2 destination, and both logical database restore and object-archive extraction tests passed. Cloudflare wildcard DNS and Worker routes now serve Nibleaf project subdomains while preserving reserved service hosts; three real customer custom domains remain active with TLS and correct canonicals.

The accompanying application patch restores the public installer endpoints, updates crawlable product claims to match the now-public release, and changes unresolved wildcard/custom hosts from a homepage 200 to a noindex HTTP 404. Production validation passed after rollout.

## Local changes

### Indexability and international SEO

- Published missing-project and missing-page loaders now throw the router's real not-found response after a confirmed API 404.
- API response errors retain their HTTP status, so a backend 500 is not converted into a crawler-visible 404.
- Published hreflang excludes noindex pages and languages that disallow indexing.
- Pages with a custom external canonical no longer emit an internal alternate cluster or appear as an internal sitemap URL.
- English and Arabic companion blog articles emit reciprocal `en`, `ar`, and `x-default` alternates.
- Blog SSR sets the correct document language and direction from loader data.

### Arabic and RTL

- Added conservative Arabic search normalization for diacritics, tatweel, common alef variants, and alef maqsura.
- Stemming remains disabled and ta marbuta is not folded to ha.
- Normalized text is indexed once; original fields remain in a sidecar map to avoid duplicating the full index.
- Search snippets preserve useful centering when a normalized Arabic match occurs beyond the initial text window.
- Inline code is LTR-isolated in reader, editor, and blog prose; fenced code stays LTR.
- Arabic headings reset letter spacing.
- Blog cards set their own `lang` and `dir`, including mixed-language related cards.
- Added `arabic-technical-documentation-rtl-checklist.mdx`, written and humanized in Arabic with primary-source Unicode and Google guidance.
- Rewrote the existing English Arabic/RTL article to match tested behavior.

### Content and internal links

- Added `gitbook-vs-mintlify.mdx`, a source-backed workflow, pricing, API, multilingual, and ownership comparison.
- Added contextual links to the comparison from both relevant alternatives pages and both Nibleaf comparison pages.
- Reframed the introduction article away from overlapping Mintlify-alternative intent.
- Corrected the plain-Markdown article so it distinguishes Markdown stored in the database from a live Git directory.
- Reworked the Docker Compose article into a production architecture and readiness guide, then updated it after anonymous source and container access were restored.
- Updated GitBook alternatives and comparison content for current hosted pricing and the limited open-source reader renderer.
- Replaced unverified roadmap and self-hosting claims across marketing, FAQ schema, `llms.txt`, `llms-full.txt`, manifests, terms, and privacy copy. After access was restored, those surfaces were updated again with the verified public repository, pinned GHCR release, and installer facts.
- Restored `/install.sh` and `/docker-compose.yml` on the marketing apex and added a manual clean-runner installer smoke workflow.

### Structured data, metadata, and assets

- Article JSON-LD now uses the article language and localized image.
- Arabic blog metadata uses `ar_AR`; English uses `en_US`.
- Regenerated English and Arabic 1200 x 630 social raster cards from corrected SVG sources and visually inspected both.
- Blog metadata moved to a lightweight manifest, preventing article prose from entering the homepage bundle.
- A test deep-compares every MDX frontmatter block with the manifest and validates reciprocal translation targets.
- Added a dedicated contact page for product support, privacy requests, security disclosures, abuse reports, and editorial corrections, with `ContactPage` structured data and footer, sitemap, and `llms.txt` links.
- Article pages now expose semantic publication and modification dates, a visible organization byline linked with `rel=author`, and `BlogPosting` microdata alongside JSON-LD.

### Performance

- Article body text is no longer present in the main client chunk and is isolated to the blog article route chunk.
- Dashboard-only localization, direction, confirmation, tooltip, and toast providers now live under the app, authentication, and invitation routes instead of the public root. The production build reduced the shared root client chunk from about 848 KB raw / 259 KB gzip to 689 KB raw / 206 KB gzip, a roughly 20% gzip reduction. The remaining shared bundle still warrants attribution and route-level splitting rather than an untested last-minute rewrite.

## Post-deployment production-readiness follow-up

- Coolify reports three persistent Compose volumes: PostgreSQL, Dragonfly, and MaxIO object storage. PostgreSQL and MaxIO now have successful daily R2-backed schedules and restore evidence; Dragonfly remains intentionally disposable cache/queue state.
- Coolify is configured to keep two application images, but its Rollback page reports no previous image. The source-built Compose currently uses one mutable local image tag, so a verified rollback artifact is not available.
- Added a per-response nonce-based Content Security Policy for HTML. TanStack streaming, hydration, route scripts, the theme bootstrap, and consent-loaded analytics receive the nonce; script attributes remain disabled, and the policy retains only the external origins required by Cloudflare analytics, Google Tag Manager, Plausible, Google Fonts, and operator-configured storage. HTTP storage remains available to HTTP-only private deployments without forcing insecure upgrades. HTML now uses `private, no-store` because replaying a cached document would also replay its nonce; versioned assets and public API responses keep their independent cache policies.
- Post-deploy SquirrelScan crawled all 22 sitemap URLs with 0 failures: overall 89/B, Security 97, Performance 85, Accessibility 98, Content 99, and Core SEO/Crawlability/Internationalization/Schema/Links/Mobile/Images/Social/Legal all 100. It reported 2,242 passing checks and 97 warnings, down from 121 warnings before the CSP and bundle passes.
- The separate admin application now enforces its own nonce policy with `frame-ancestors 'none'`, remains `noindex` and `no-store`, and passes its full TypeScript check after narrowing the two typed list callbacks that previously inferred `any`.
